# AI 任务选择决策指南

很多 AI 使用失败，不是因为 prompt 写得不够漂亮，而是从一开始就选错了任务形态。简单问题被做成复杂 agent，复杂任务又被塞进一次对话，都会让结果不稳定。

这份指南回答一个问题：

```text
我现在这个任务，应该用普通对话、结构化 prompt、工作流、skill、RAG、工具调用，还是 agent？
```

建议配合 [常见误区与纠偏指南](common-pitfalls.md)、[Prompt 调试指南](prompt-debugging-guide.md)、[AI 安全案例更新指南](safety-case-updates.md)、[AI 安全事故复盘案例集](safety-incident-retrospectives.md)、[中外 AI 模型特色概览](model-landscape-china-global.md)、[AI 模型选型实战案例集](model-selection-cases.md)、[AI 工作流配方库](workflow-recipes.md)、[课堂练习工作纸](classroom-worksheets.md)、[团队 AI 落地手册](team-adoption-playbook.md) 和 [AI 能力评估量表](assessment-rubric.md) 使用。

## 先问 5 个问题

在选择方法前，先回答：

```text
1. 这个任务是否只需要一次回答？
2. 这个任务是否需要多步处理和中间检查？
3. 这个任务是否会反复出现，值得沉淀？
4. 这个任务是否依赖外部资料、文件、数据库或最新信息？
5. 这个任务是否需要 AI 采取行动，例如读写文件、调用工具、发送请求或修改系统？
```

对应关系：

| 如果答案是 | 优先考虑 |
| --- | --- |
| 只需要一次回答 | 普通对话或结构化 prompt |
| 需要多步处理 | 工作流 |
| 会反复出现 | 模板或 skill |
| 依赖外部资料 | RAG 或工具调用 |
| 需要采取行动 | agent |
| 涉及高风险决策 | 人工主导，AI 只做辅助 |

## 一张决策树

```text
任务是否高风险？
是 -> 人工主导，AI 只做资料整理、草稿或检查清单
否 -> 是否需要外部事实或私有资料？
      是 -> RAG、工具调用或人工核验
      否 -> 是否需要行动或多轮执行？
            是 -> agent 工作说明
            否 -> 是否需要多步推理或生成？
                  是 -> 工作流
                  否 -> 结构化 prompt 或普通对话
```

高风险包括：

- 医疗、法律、金融、招聘、教育评价等专业判断。
- 删除、发布、支付、审批、发信、改权限等外部动作。
- 处理隐私、客户数据、密钥、合同和未公开业务资料。
- 会影响他人权益或组织责任的输出。

## 任务形态 1：普通对话

适合：

- 快速解释一个概念。
- 找一个例子。
- 改一句话。
- 头脑风暴。
- 让 AI 帮你澄清问题。

不适合：

- 长文档分析。
- 事实必须准确的结论。
- 多步骤项目。
- 需要保存和复用的流程。
- 需要调用工具或改变外部状态的任务。

可复制 prompt：

```text
请用初学者能理解的话解释【概念】。
要求：
1. 先用一句话解释。
2. 再给一个真实例子。
3. 最后说明它不是什么。
```

判断是否足够：

- 如果回答错了，影响很小。
- 不需要引用来源。
- 不需要进入正式交付。
- 你可以马上判断是否有用。

## 任务形态 2：结构化 Prompt

适合：

- 写邮件、周报、摘要、清单。
- 改写短内容。
- 整理一段资料。
- 生成单个明确交付物。

不适合：

- 中途需要多次检查的大任务。
- 输出依赖大量外部资料。
- 需要持续复用和维护的流程。
- 需要 AI 自主行动的任务。

结构：

```text
目标：

背景：

约束：

验收标准：

输出格式：
```

可复制 prompt：

```text
请完成【任务】。

目标：
【希望达成什么】

背景：
【必要上下文】

约束：
- 【必须做】
- 【不能做】

验收标准：
- 【怎样算合格】
- 【怎样算不能用】

输出格式：
【表格/清单/Markdown/邮件/大纲】

如果信息不足，请先问我最多 3 个关键问题。
```

判断是否足够：

- 输出只有一个明确交付物。
- 任务不需要长时间执行。
- 你能一次性提供足够上下文。
- 验收标准很清楚。

## 任务形态 3：工作流

适合：

- 写长文。
- 做竞品分析。
- 读论文或报告。
- 设计课程。
- 分析用户反馈。
- 修复 bug 前的定位和计划。

不适合：

- 只需要一句解释的小问题。
- 已经高度固定、可以直接模板化的重复任务。
- 需要 AI 调用工具并持续推进的任务。

工作流模板：

```text
第 1 步：澄清目标
输入：
输出：
检查点：

第 2 步：整理资料
输入：
输出：
检查点：

第 3 步：生成初稿或分析
输入：
输出：
检查点：

第 4 步：检查和修改
输入：
输出：
检查点：

第 5 步：汇总交付
输入：
输出：
检查点：
```

可复制 prompt：

```text
请不要直接完成任务。先把下面任务拆成 5 步工作流。

任务：
【填写任务】

每一步请写：
1. 输入。
2. 动作。
3. 输出。
4. 检查点。
5. 是否需要人工复核。

拆完后先停下，等我确认。
```

判断是否足够：

- 任务需要分阶段完成。
- 中间结果可以验收。
- 人需要在关键点做判断。
- 任务暂时不需要 AI 自主调用工具。

## 任务形态 4：模板或配方

适合：

- 每周重复的周报、纪要、复盘。
- 固定格式的资料整理。
- 常见写作和分析任务。
- 已经验证过几次的工作流。

不适合：

- 还没跑通过的新任务。
- 每次输入差异很大、难以稳定描述的任务。
- 需要大量判断和权限控制的任务。

从工作流升级为模板：

```text
已验证工作流 -> 固定输入 -> 固定输出 -> 边界 -> 验收标准 -> 示例
```

可复制 prompt：

```text
请把下面这次成功的 AI 协作过程整理成可复用模板。

材料：
【粘贴 prompt、输出摘要、人工修改和失败点】

请输出：
1. 适用场景。
2. 输入要求。
3. 可替换变量。
4. 执行步骤。
5. 输出格式。
6. 边界。
7. 验收标准。
```

判断是否足够：

- 这个任务至少重复出现 3 次。
- 每次输入和输出结构相似。
- 有明确的失败案例。
- 不需要复杂工具权限。

## 任务形态 5：Skill

适合：

- 团队或个人长期复用的专业能力。
- 需要固定流程、示例、边界和验收标准的任务。
- 希望 agent 或助手在合适场景自动调用的能力。

不适合：

- 一次性任务。
- 还没验证过的 prompt。
- 只是收藏了一段提示词，但没有边界和样例。

Skill 最小结构：

```text
名称：
用途：
触发场景：
输入要求：
执行步骤：
输出格式：
边界：
验收标准：
示例：
维护方式：
```

可复制 prompt：

```text
请把以下重复任务整理成一个 skill/card。

任务：
【填写任务】

请输出：
名称、用途、触发场景、输入要求、执行步骤、输出格式、边界、验收标准、示例、维护方式。

要求：
1. 只沉淀可重复使用的部分。
2. 写清什么不能做。
3. 对信息不足的情况写处理方式。
4. 给出一个最小测试样例。
```

判断是否足够：

- 它比模板多了边界、示例和维护规则。
- 多个人使用时也能保持稳定。
- 能被测试和更新。
- 能减少重复解释。

## 任务形态 6：RAG 或知识库问答

适合：

- 回答基于内部文档的问题。
- 基于课程资料、产品文档、政策手册或项目记录生成回答。
- 需要引用来源的资料问答。
- 资料会更新，不能只靠模型记忆。

不适合：

- 资料质量很差或没有权限整理。
- 没有来源、日期和版本的材料。
- 想用 RAG 替代人工判断。
- 希望把所有文件直接丢进去就自动变聪明。

RAG 最小流程：

```text
资料整理 -> 切分和标注 -> 检索 -> 注入上下文 -> 生成回答 -> 标注引用 -> 核验
```

可复制 prompt：

```text
请基于我提供的资料回答问题。

要求：
1. 只依据资料回答。
2. 每个结论标注依据。
3. 资料没有说明的地方写“资料未说明”。
4. 区分事实、推测和建议。
5. 列出需要人工核验的信息。

资料：
【粘贴资料】

问题：
【填写问题】
```

判断是否足够：

- 资料边界清楚。
- 回答需要引用依据。
- 资料可能更新。
- 有人负责维护知识库。

## 任务形态 7：工具调用

适合：

- 需要计算、查询、检索、运行代码或访问文件。
- 需要连接外部系统，但不需要 AI 长时间自主推进。
- 需要让 AI 使用某个明确工具完成一步操作。

不适合：

- 工具权限不清。
- 操作不可回滚。
- 涉及支付、发布、删除、审批等高风险动作。
- 人无法验证工具输出。

工具调用说明：

```text
目标：
可使用工具：
工具输入：
允许访问范围：
禁止事项：
输出要求：
人工复核点：
```

可复制 prompt：

```text
请使用【工具名称】完成【任务】。

允许访问：
【范围】

禁止：
- 【禁止动作 1】
- 【禁止动作 2】

执行前请先说明：
1. 你将调用什么工具。
2. 输入是什么。
3. 预期输出是什么。
4. 哪些结果需要我复核。
```

判断是否足够：

- 工具能力明确。
- 权限范围明确。
- 只需要一次或少量工具调用。
- 人能检查工具结果。

## 任务形态 8：Agent

适合：

- 目标明确，但需要 AI 自己计划多步行动。
- 需要读取资料、调用工具、观察结果、修正计划。
- 任务可以被日志记录、检查和回滚。
- 风险可控，有人工确认点。

不适合：

- 目标模糊。
- 权限边界不清。
- 高风险动作不能中途确认。
- 出错后无法追踪和回滚。
- 普通工作流已经足够。

Agent 工作说明：

```text
目标：
可使用工具：
允许读取：
允许写入：
禁止事项：
验收标准：
必须人工确认的动作：
执行日志要求：
失败时如何停止：
```

可复制 prompt：

```text
请先不要执行任务。请帮我写一份 agent 工作说明。

任务：
【填写任务】

必须包含：
目标、可使用工具、允许读取、允许写入、禁止事项、验收标准、必须人工确认的动作、执行日志要求、失败时如何停止。

写完后请判断：这个任务是否真的需要 agent，还是普通工作流就够。
```

判断是否足够：

- 有明确的停止条件。
- 有日志和审计。
- 高风险动作需要人工确认。
- 允许读写范围可控。

## 任务形态 9：多 Agent 协作

适合：

- 大任务可以拆成互不重叠的模块。
- 多个角色可以并行工作。
- 每个 agent 有独立责任边界。
- 有人负责整合和审查。

不适合：

- 任务本身还没拆清楚。
- 多个 agent 会修改同一文件或同一结论。
- 没有统一验收标准。
- 没有人做最终整合。

常见分工：

| 任务 | 分工方式 |
| --- | --- |
| 写作 | 资料整理、初稿、事实核验、编辑审查 |
| 编程 | 前端、后端、测试、代码审查 |
| 课程 | 大纲、练习、案例、安全检查 |
| 研究 | 资料收集、观点整理、反例分析、报告生成 |

可复制 prompt：

```text
请把这个任务拆成适合多 agent 协作的子任务。

任务：
【填写任务】

请输出：
1. 子任务列表。
2. 每个子任务的输入。
3. 每个子任务的交付物。
4. 每个子任务的禁止事项。
5. 哪些文件或内容不能多人同时修改。
6. 最终整合和验收方式。
```

判断是否足够：

- 子任务之间依赖少。
- 每个 agent 的写入范围清楚。
- 有最终负责人。
- 有冲突处理规则。

## 任务形态 10：人来做，AI 只辅助

适合：

- 法律、医疗、金融和人事判断。
- 涉及伦理、责任和组织承诺的决策。
- 高风险发布和审批。
- 需要深度人际理解的沟通。
- 数据不足但影响重大的选择。

AI 可以做：

- 整理资料。
- 列出问题。
- 生成草稿。
- 提供反例。
- 做检查清单。
- 标注不确定信息。

AI 不应做：

- 替人做最终责任判断。
- 自动执行高风险动作。
- 编造缺失依据。
- 绕过专业审查。

可复制 prompt：

```text
这个任务由我做最终判断。请只做辅助分析。

任务：
【填写任务】

请输出：
1. 我需要考虑的问题。
2. 已知事实和不确定信息。
3. 可能风险。
4. 可选方案。
5. 每个方案需要进一步核验的内容。

不要给最终决定。
```

## 快速选择表

| 任务特征 | 推荐形态 | 下一步 |
| --- | --- | --- |
| 小问题、低风险 | 普通对话 | 直接问，必要时追问 |
| 单个明确交付物 | 结构化 prompt | 写五要素 |
| 多步骤、需检查 | 工作流 | 拆 3-6 步 |
| 重复出现 | 模板或配方 | 固化输入输出 |
| 长期复用 | skill | 加边界、示例和维护 |
| 依赖资料 | RAG | 整理来源和测试问题 |
| 需要工具 | 工具调用 | 限定权限和输出 |
| 需要自主推进 | agent | 写工作说明 |
| 可并行拆分 | 多 agent | 划清责任和写入范围 |
| 高风险决策 | 人工主导 | AI 只做辅助 |

## 三个常见选择错误

把小任务做成 agent：

```text
如果一个结构化 prompt 就能完成，不要为了自动化而引入 agent。
```

把复杂任务塞进一次对话：

```text
如果任务需要调研、判断、生成、检查和发布，就先拆工作流。
```

把重复任务永远临时写：

```text
如果同一任务已经做过 3 次，就该整理成模板、配方或 skill。
```

如果一项任务同时满足多个条件，按风险优先：

```text
高风险 -> 人工主导
需要行动 -> agent 或工具调用
依赖资料 -> RAG 或核验
多步骤 -> 工作流
重复出现 -> 模板或 skill
单次低风险 -> 结构化 prompt
```

## 最后提醒

AI 方法不是越复杂越好。正确顺序通常是：

```text
普通对话 -> 结构化 prompt -> 工作流 -> 模板 -> skill -> RAG/工具 -> agent
```

每升一级，都要多一层边界、验证和维护。能用简单方式稳定完成的任务，就不要急着复杂化；已经复杂到一次对话不稳定的任务，就不要硬塞给一个 prompt。
