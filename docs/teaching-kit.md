# 教学版本材料包

这份材料面向教师、培训者、读书会主持人和团队学习负责人。它把本书整理成可以直接开课的 4 周教学版本，适合配合 [读书会与教学方案](facilitation-guide.md)、[教学资料库连续案例](cases/teaching-rag-skill-agent-memory.md)、[连续案例练习与复盘评分表](cases/continuous-case-exercises.md)、[连续案例课堂试跑版](cases/continuous-case-classroom-run.md)、[连续案例课堂投影短版](cases/continuous-case-slide-brief.md)、[连续案例团队试点版](cases/continuous-case-team-pilot.md)、[连续案例样例库](cases/continuous-case-samples.md)、[AI 安全与模型选型工作坊](workshop-safety-model-selection.md)、[课堂练习工作纸](classroom-worksheets.md)、[教学示范作业集](teaching-examples.md)、[Prompt 调试指南](prompt-debugging-guide.md)、[章节复盘题与小测](chapter-review-questions.md) 和 [AI 能力评估量表](assessment-rubric.md) 使用。

建议课时：

- 标准版：4 周，每周 90 分钟。
- 强化版：4 周，每周 120 分钟，增加更多现场互评。
- 企业内训版：2 个半天，把第 1-2 周合并，第 3-4 周合并。

## 教学目标

课程结束后，学习者应该能做到：

1. 写出包含目标、背景、约束、验收标准和输出格式的 prompt。
2. 把一个复杂任务拆成可验证的 AI 工作流。
3. 建立一个可复用的 skill/card。
4. 写出一个低风险 agent 工作说明。
5. 识别必须人工复核的事实、数据、权限和行动风险。

## 课前准备

讲师准备：

- 通读 [第 0 章](chapters/00-learning-map.md)、[第 1 章](chapters/01-dialogue-basics.md)、[第 4 章](chapters/04-prompt-workflows.md)、[第 8 章](chapters/08-agents.md) 和 [第 13 章](chapters/13-safety-governance.md)。
- 选择一个课堂统一案例，例如会议纪要、论文阅读、用户反馈分析、代码审查或课程设计。
- 准备 2 个失败 prompt 和 2 个改进 prompt。
- 选取 [教学示范作业集](teaching-examples.md) 中的 1-2 个样例作为课堂对照。
- 课前发放 [课堂练习工作纸](classroom-worksheets.md)，让学员带着真实任务填写。
- 确认可用 AI 工具、账号、网络和数据边界。

学员准备：

- 带一个真实任务，最好是最近一周需要完成的任务。
- 带一段可公开使用的资料，不要包含隐私、密钥、客户数据或未公开商业资料。
- 课前浏览 [课堂练习工作纸](classroom-worksheets.md)，先填写自己的原始 prompt。
- 完成一次课前自评，使用 [AI 能力评估量表](assessment-rubric.md)。

## 4 周课件大纲

| 周次 | 主题 | 核心章节 | 课堂产出 |
| --- | --- | --- | --- |
| 第 1 周 | 会和 AI 对话 | 第 0、1、3 章 | 一个五要素 prompt |
| 第 2 周 | 把 prompt 变成工作流 | 第 4、5 章 | 一个 5 步 AI 工作流 |
| 第 3 周 | 知识库、RAG 和 skill | 第 6、7 章 | 一个 skill/card 初稿 |
| 第 4 周 | Agent、记忆和治理 | 第 8、9、13 章 | 一个 agent 工作说明和安全规范 |

每周建议结构：

```text
10 分钟：回顾作业和真实失败点
20 分钟：讲解核心概念
25 分钟：现场练习
20 分钟：同伴互评
10 分钟：讲师点评
5 分钟：布置下周任务
```

如果是 120 分钟课，把同伴互评延长到 30 分钟，并增加 20 分钟现场修改。

## 第 1 周：会和 AI 对话

学习目标：

- 理解 AI 不是魔法答案机，而是需要上下文的协作者。
- 能区分弱 prompt 和可执行 prompt。
- 能让 AI 在信息不足时先提问。

课件页建议：

1. 课程目标和最终作品。
2. AI 学习的四层能力。
3. 弱 prompt 的常见问题。
4. 好 prompt 五要素。
5. 示例和反例。
6. 现场练习说明。

讲师提示词：

```text
请把以下章节内容改写成 6 页课件大纲：
【粘贴第 1 章和第 3 章相关片段】

要求：
1. 面向零基础学习者。
2. 每页只讲一个观点。
3. 每页包含一个真实例子。
4. 不介绍具体工具价格、模型排行榜或过时事实。
5. 最后生成一个 15 分钟现场练习。
```

课堂练习：

```text
请把你最近一个真实任务改写成五要素 prompt。

目标：

背景：

约束：

验收标准：

输出格式：

如果信息不足，请让 AI 先问最多 3 个关键问题。
```

同伴互评问题：

- 目标是否能被一句话判断完成或未完成。
- 背景是否足够让一个陌生人理解任务。
- 约束是否写出了不能做的事。
- 验收标准是否能用于检查输出。
- 输出格式是否能直接进入下一步。

常见卡点：

| 卡点 | 讲师处理方式 |
| --- | --- |
| 学员只写“帮我优化” | 追问“优化给谁看，用来做什么，怎样算好” |
| 学员背景写得太长 | 帮他标出真正影响输出的 3 条信息 |
| 学员没有验收标准 | 让他写“我会因为什么拒收这个结果” |
| 学员材料涉密 | 换成公开材料或虚构结构相同的数据 |

课后任务：

```text
用课堂上的五要素 prompt 完成一次真实任务。
保存原始 prompt、AI 输出、人工修改和最终版本。
```

## 第 2 周：把 Prompt 变成工作流

学习目标：

- 理解复杂任务不能一次性交给 AI。
- 能把任务拆成 3-6 个步骤。
- 能为每一步设置输入、输出和检查点。

课件页建议：

1. 上周作业复盘。
2. 为什么复杂任务需要工作流。
3. 工作流六步法。
4. 检查点和验收标准。
5. 小型评测集。
6. 现场练习说明。

讲师提示词：

```text
请根据以下任务设计一个教学案例：
【任务描述】

输出：
1. 一个失败的一步式 prompt。
2. 一个拆成 5 步的工作流。
3. 每一步的输入、动作、输出和检查点。
4. 3 个供学员讨论的失败风险。

要求案例适合课堂展示，材料不能包含真实隐私。
```

课堂练习：

```text
请选择一个复杂任务，把它拆成 5 步 AI 工作流。

任务名称：

第 1 步：
输入：
动作：
输出：
检查点：

第 2 步：
输入：
动作：
输出：
检查点：

第 3 步：
输入：
动作：
输出：
检查点：

第 4 步：
输入：
动作：
输出：
检查点：

第 5 步：
输入：
动作：
输出：
检查点：
```

小型评测集练习：

```text
请为你的工作流写 5 条测试样例。

每条样例包含：
1. 输入材料。
2. 预期输出特征。
3. 必须避免的问题。
4. 合格或不合格的判断标准。
```

同伴互评问题：

- 每一步是否只做一类动作。
- 上一步输出是否能成为下一步输入。
- 哪些步骤必须人工复核。
- 有没有过早让 AI 做最终判断。
- 评测样例是否覆盖容易失败的情况。

课后任务：

```text
运行一次自己的 5 步工作流。
记录每一步实际输出、人工修改和失败原因。
下周带来一个最值得沉淀的步骤。
```

## 第 3 周：知识库、RAG 和 Skill

学习目标：

- 理解资料、知识库和 RAG 的关系。
- 能判断哪些资料适合进入知识库。
- 能把重复任务写成 skill/card。

课件页建议：

1. 上周工作流失败点复盘。
2. 知识库为什么不是文件堆。
3. RAG 最小流程。
4. skill 与 prompt 的区别。
5. skill/card 结构。
6. 现场练习说明。

讲师提示词：

```text
请把以下重复任务整理成一个 skill/card 初稿：
【任务说明】

输出字段：
名称、用途、触发场景、输入要求、执行步骤、输出格式、边界、验收标准、示例。

要求：
1. 只沉淀可重复使用的部分。
2. 对缺少资料的情况写清楚处理方式。
3. 明确哪些内容不能由 AI 编造。
4. 给出一个最小测试样例。
```

课堂练习：

```text
请从上周工作流中选择一个会重复使用的步骤，把它写成 skill/card。

```

```text
更新频率：

是否进入知识库：

更新频率：

是否进入知识库：
原因：
权限：
更新频率：

是否进入知识库：
原因：
权限：
更新频率：

是否进入知识库：
原因：
权限：
更新频率：
```

同伴互评问题：

- 这个 skill 是否真的会重复使用。
- 输入要求是否足够明确。
- 输出格式是否稳定。
- 边界是否写出了禁止事项。
- 验收标准是否能用于测试。

课后任务：

```text
用真实材料测试一次自己的 skill/card。
记录：
1. 哪些输入不够清楚。
2. 哪些步骤需要拆分。
3. 哪些边界需要补充。
4. 是否值得保存为长期模板。
```

## 第 4 周：Agent、记忆和治理

学习目标：

- 理解 agent 与普通聊天的区别。
- 能为低风险 agent 写工作说明。
- 能定义记忆保存规则和人工确认点。
- 能写一份个人或团队 AI 使用底线。

课件页建议：

1. skill 作业复盘。
2. Agent 的基本循环。
3. 工具、权限和日志。
4. 记忆系统的价值与风险。
5. 安全治理底线。
6. 结业项目说明。

讲师提示词：

```text
请为以下低风险任务写一份 agent 工作说明：
【任务说明】

必须包含：
目标、可使用工具、允许读取、允许写入、禁止事项、验收标准、需要人工确认的动作。

要求：
1. 不允许自动发送、删除、支付、发布或改变权限。
2. 对不确定信息必须标注。
3. 输出最后要有执行日志摘要。
```

课堂练习：

```text
请为一个低风险任务写 agent 工作说明。

目标：

可使用工具：

允许读取：

允许写入：

禁止事项：

验收标准：

需要人工确认的动作：

执行日志要求：
```

记忆规则练习：

```text
请写出 5 条值得长期保存的偏好或背景：
1.
2.
3.
4.
5.

请写出 5 条禁止保存或禁止上传的信息：
1.
2.
3.
4.
5.
```

同伴互评问题：

- 任务是否适合 agent，而不是一次普通对话。
- 工具权限是否过大。
- 禁止事项是否覆盖高风险动作。
- 人工确认点是否明确。
- 记忆规则是否保护隐私和商业信息。

课后任务：

```text
整理结业项目材料：
1. 一个高质量 prompt。
2. 一个 5 步工作流。
3. 一个 skill/card。
4. 一个 agent 工作说明。
5. 一份 AI 使用安全规范。
```

## 结业项目模板

项目目标：

把一个真实任务整理成可复用、可验证、有边界的 AI 工作系统小包。

提交材料：

```text
项目名称：
使用场景：
目标用户：

材料 1：高质量 prompt
材料 2：5 步 AI 工作流
材料 3：skill/card
材料 4：agent 工作说明
材料 5：安全规范
材料 6：一次真实测试记录
```

测试记录模板：

```text
测试日期：
输入材料：
使用的 prompt 或 skill：
AI 输出摘要：
人工修改：
失败点：
下次修改：
是否可以复用：
```

展示结构：

```text
2 分钟：说明任务和使用者。
3 分钟：展示 prompt 与工作流。
3 分钟：展示 skill/card 与 agent 边界。
2 分钟：展示测试结果和失败点。
2 分钟：回答同伴问题。
```

评分表：

| 维度 | 分值 | 判断标准 |
| --- | --- | --- |
| 问题定义 | 15 | 目标、读者、背景和约束清楚 |
| Prompt 质量 | 15 | 五要素完整，能让 AI 稳定开始 |
| 工作流设计 | 20 | 步骤清楚，有输入、输出和检查点 |
| Skill 沉淀 | 15 | 可复用，有边界和验收标准 |
| Agent 边界 | 15 | 工具、权限、禁止事项和人工确认点明确 |
| 验证记录 | 10 | 有真实测试、失败点和修改记录 |
| 安全治理 | 10 | 处理了数据、事实、权限和复核风险 |

结业项目点评提示词：

```text
请按评分表点评以下结业项目。

项目材料：
【粘贴项目】

请输出：
1. 总分和各维度得分。
2. 最值得保留的设计。
```

## 课堂运营清单

课前：

- 确认学员能访问所需 AI 工具。
- 准备不涉密的统一练习材料。
- 发放本节课阅读章节和复盘题。
- 说明禁止上传的数据类型。
- 预留无法联网时的离线案例。

课中：

- 每 20 分钟安排一次学员输出，不连续讲太久。
- 每个概念都配一个失败例子。
- 优先点评真实任务，不只点评模板格式。
- 遇到事实类输出，现场示范核验。
- 遇到高风险动作，现场示范人工确认点。

课后：

- 收集 3 类反馈：最有用内容、最困惑内容、下一次想练的任务。
- 保存优秀作业时先去除隐私和业务敏感信息。
- 把反复出现的问题补进下一次课的开场复盘。
- 用 [AI 能力评估量表](assessment-rubric.md) 做阶段对比。
- 回收 [课堂练习工作纸](classroom-worksheets.md) 时先确认内容已经匿名化。
- 把可复用的匿名化作业沉淀到 [教学示范作业集](teaching-examples.md) 的结构中。

## 常见教学问题

学员过度关注工具：

把讨论拉回任务、输入、输出、验收标准和安全边界。工具可以替换，工作方法要能迁移。

学员担心 AI 会取代自己：

让学员比较原始输出和人工修改后的输出，看到判断、取舍、验证和责任仍然在人。

学员 prompt 写得很长但效果不好：

要求先删掉不影响输出的信息，再补上验收标准和输出格式。

学员想直接做 agent：

先让他写清楚允许动作、禁止动作、工具权限和人工确认点。写不清楚边界，就先回到普通工作流。

管理者想快速推广：

先选低风险、高频、容易验收的任务试点，例如会议纪要、资料整理、公开文案草稿和内部知识库问答。不要从自动发布、自动审批或敏感数据处理开始。
