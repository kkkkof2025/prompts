# 读书会与教学方案

这份方案适合教师、培训者、团队负责人或自学小组使用。它把本书拆成 4 周读书会，每周 90 分钟。

如果需要更完整的授课材料，包括周课件大纲、讲师提示词、课堂练习、作业和结业项目模板，请使用 [教学版本材料包](teaching-kit.md)。如果需要一节进阶专题课，请使用 [AI 安全与模型选型工作坊](workshop-safety-model-selection.md)。如果需要可发给学员填写的表单，请使用 [课堂练习工作纸](classroom-worksheets.md)。如果需要课堂展示样例，请使用 [教学示范作业集](teaching-examples.md)。

## 使用方式

每周结构：

```text
10 分钟：回顾上周实践
25 分钟：共读核心章节
25 分钟：现场练习
20 分钟：小组互评
10 分钟：确定下周任务
```

人数建议：

- 个人自学：按练习完成即可。
- 小组读书会：3-8 人最合适。
- 团队培训：可以分组，每组选择一个真实业务场景。

## 第 1 周：会和 AI 对话

阅读：

- [第 0 章：学习路线图](chapters/00-learning-map.md)
- [第 1 章：从最基本的对话开始](chapters/01-dialogue-basics.md)
- [第 3 章：Prompt 入门](chapters/03-prompt-basics.md)

现场练习：

```text
每人选择一个真实任务，把它改写成五要素 prompt：
目标、背景、约束、标准、输出格式。
```

讨论问题：

- 你的原始 prompt 最大问题是什么。
- 哪个背景信息最影响 AI 输出。
- 输出格式如何减少返工。

课后任务：

用改写后的 prompt 完成一次真实任务，并保存结果。

## 第 2 周：把 Prompt 变成工作流

阅读：

- [第 4 章：结构化 Prompt 与工作流](chapters/04-prompt-workflows.md)
- [第 5 章：模型选择、验证与评估](chapters/05-evaluation.md)
- [Prompt 模式实践模板](../examples/prompt-patterns.md)

现场练习：

```text
把一个大任务拆成 5 步工作流。
每一步写清楚输入、动作、输出和检查点。
```

讨论问题：

- 哪一步最容易让 AI 误解。
- 哪些结果必须人工确认。
- 如何判断输出是否合格。

课后任务：

建立一个 5 条样例的小型评测集。

## 第 3 周：知识库、Skill 和复用

阅读：

- [第 6 章：工具调用、RAG 与知识库](chapters/06-tools-rag.md)
- [第 7 章：Skills，把经验固化成能力](chapters/07-skills.md)
- [AI Skill/Card 可复用模板](../examples/skill-card-template.md)

现场练习：

```text
每人设计一个最小 skill。
要求包含触发场景、输入、输出、边界和验收标准。
```

讨论问题：

- 这个 skill 是否真的会重复使用。
- 哪些输入不足会导致失败。
- 怎样避免 AI 编造。

课后任务：

用真实材料测试一次自己的 skill，并记录失败点。

## 第 4 周：Agent、记忆和治理

阅读：

- [第 8 章：Agent，从聊天到行动](chapters/08-agents.md)
- [第 9 章：记忆系统与个性化助手](chapters/09-memory.md)
- [第 13 章：安全、伦理与治理](chapters/13-safety-governance.md)
- [Agent 工作流安全检查清单](../examples/agent-workflow-checklist.md)

现场练习：

```text
写一份 agent 工作说明。
必须包含目标、工具、禁止事项、验收标准和人工确认点。
```

讨论问题：

- 这个 agent 最危险的动作是什么。
- 哪些记忆值得保存，哪些不能保存。
- 团队使用 AI 需要什么规范。

课后任务：

写一份个人或团队 AI 使用规范。

## 结业作品

每位参与者提交一个 AI 工作系统小包：

```text
1. 一个高质量 prompt。
2. 一个 5 步工作流。
3. 一个 skill/card。
4. 一个 agent 工作说明。
5. 一份安全规范。
```

更细的提交模板、展示结构和评分表见 [教学版本材料包](teaching-kit.md)。

可参考 [教学示范作业集](teaching-examples.md) 中的结业项目小包，帮助参与者理解提交质量。

## 评分建议

| 维度 | 说明 |
| --- | --- |
| 清晰度 | 目标、背景、约束是否明确 |
| 可执行性 | 是否能直接用于真实任务 |
| 可验证性 | 是否有验收标准 |
| 可复用性 | 是否能沉淀为模板或 skill |
| 安全性 | 是否有边界和人工确认点 |

## 培训者注意事项

- 不要让读者只听概念，必须现场做练习。
- 不要把工具名字当作教学重点。
- 对高风险场景要强调人工复核。
- 鼓励读者带自己的真实材料，而不是只用虚构案例。
- 如果读者背景差异大，按 [分角色学习路径](learning-paths.md) 分组。
