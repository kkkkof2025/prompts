# AI 模型成本计算与选型实战

> 选模型不只是看排行榜。成本、延迟、合规、部署方式都是决策的关键维度。这一节帮你建立自己的模型选型决策框架。

## 一、为什么成本很重要

很多人在 AI 上花的第一笔大钱不是因为模型贵，而是因为**没算过账**。

一个典型场景：

```text
我用最强的模型处理所有任务 → 月底账单超出预算3倍 →
开始降级模型 → 发现90%的任务用便宜模型就够了
```

### 1.1 不同模型的价格差

模型价格变化很快，本书不把某个厂商的实时价格写成固定结论。更稳妥的做法是维护一张“价格核验卡”，每次上线或复盘时填入官网最新价格。

| 模型类型 | 常见定位 | 输入价格 | 输出价格 | 适合任务 |
|---------|---------|---------|---------|---------|
| 顶级推理模型 | 质量优先、复杂推理 | 官网实时价 | 官网实时价 | 高价值分析、复杂代码、法律/合同初审 |
| 性价比模型 | 日常主力 | 官网实时价 | 官网实时价 | 写作、总结、客服、知识库问答 |
| 轻量模型 | 批量、低延迟、低成本 | 官网实时价 | 官网实时价 | 分类、抽取、格式转换、短摘要 |
| 开源本地模型 | 数据隔离、可控部署 | 硬件折旧 + 电费 + 运维 | 硬件折旧 + 电费 + 运维 | 内部知识、敏感数据、离线场景 |
| 免费或套餐模型 | 试用、个人学习 | 套餐规则 | 套餐规则 | 学习、低频试验、非关键任务 |

价格核验卡建议记录：

- 核验日期。
- 模型名称和版本。
- 输入、输出、缓存、批处理等不同计费项。
- 上下文长度、多模态能力、速率限制。
- 是否有企业合规、数据保留和地域限制。

> 本页中的金额示例只用于演示计算方法，不构成价格承诺。真实选型必须回到厂商官网或合同报价核验。

### 1.2 成本差异有多大？

一个真实对比：

| 场景 | 月均 token 用量 | 用 GPT-4o | 用 DeepSeek-V3 | 差价 |
|------|----------------|-----------|---------------|------|
| 个人日常使用 | 50万 tokens/月 | ¥28-52 | ¥2-5 | 节省90% |
| 小团队使用 (5人) | 250万 tokens/月 | ¥140-260 | ¥10-25 | 节省90% |
| 客服 Bot (1000次/天) | 1500万 tokens/月 | ¥840-1560 | ¥60-150 | 节省90% |
| 企业级应用 (1万次/天) | 1.5亿 tokens/月 | ¥8400-15600 | ¥600-1500 | 节省90% |

**结论**：如果任务不需要最强推理能力，分层路由通常能显著降低成本；但具体节省比例必须用你的真实 token、缓存命中率和模型价格计算，不能直接套用别人的账单。

## 二、成本计算工具

### 2.1 快速估算公式

```text
月成本 = 日均请求数 × 平均 token 数 × 30 × 每 token 价格
```

**示例**：你每天用 AI 20 次，每次平均输入 1500 tokens、输出 500 tokens。

```text
模型 A：
= 20 × 30 × (1500 × 输入单价 + 500 × 输出单价) / 1000000

模型 B：
= 20 × 30 × (1500 × 输入单价 + 500 × 输出单价) / 1000000
```

### 2.2 自制成本计算表

在 Excel / Google Sheets 中建一个简单表格：

| A | B | C | D |
|---|-----|---|---|
| **参数** | **你的值** | | |
| 日均请求数 | 50 | | |
| 平均输入 tokens | 1500 | | |
| 平均输出 tokens | 800 | | |
| 月天数 | 30 | | |
| **模型** | **输入价格** | **输出价格** | **月成本** |
| 模型 A | 输入官网价/百万 token | 输出官网价/百万 token | `=日均请求数*月天数*(平均输入token*输入价+平均输出token*输出价)/1000000` |

或者直接在 AI 对话中让 AI 帮你算：

```text
请帮我计算 AI 月度成本：
- 我每天调用 100 次 API
- 每次输入约 2000 tokens，输出约 500 tokens
- 模型 A 输入价为 X/百万 tokens，输出价为 Y/百万 tokens
- 模型 B 输入价为 M/百万 tokens，输出价为 N/百万 tokens
- 给出月度总成本和年度成本对比
```

## 三、模型选型决策框架

### 3.1 按任务选模型

```text
简单任务 → 便宜模型
├── 翻译短句
├── 简单分类
├── 格式改写
├── 代码补全
└── 生成摘要

中等任务 → 性价比模型
├── 长文写作
├── 数据分析
├── 代码生成
├── 客服回答（基于知识库）
└── 会议纪要整理

复杂任务 → 强推理模型
├── 多步骤分析
├── 复杂代码调试
├── 合同/法律文本分析
├── 数学推理
└── 多约束排程
```

### 3.2 模型选型检查清单

选择模型时，按以下顺序检查：

```text
□ 1. 任务复杂度
   简单（便宜模型） / 中等（性价比） / 复杂（强推理）

□ 2. 中文能力需求
   中文为主 → DeepSeek、Qwen、Kimi、豆包
   中英双语 → GPT、Claude、Gemini

□ 3. 数据隐私要求
   高敏感 → 本地部署（Qwen、Llama）
   一般 → API调用（选国内合规模型）
   公开内容 → 任何模型

□ 4. 长上下文需求
   短（<8K） → 任何模型
   中（8-32K） → DeepSeek、GPT-4o、Claude
   长（>32K） → Gemini、Claude 200K、Qwen 128K

□ 5. 多模态需求
   纯文本 → 所有模型
   图片理解 → GPT-4o、Claude、Gemini、Qwen-VL
   图片生成 → DALL-E、Midjourney、可灵
   音频/视频 → Gemini、Whisper+

□ 6. 预算约束
   无预算限制 → 选效果最好的
   有限预算 → 90%便宜模型 + 10%强推理模型
   零预算 → DeepSeek/Kimi/豆包免费版

□ 7. 部署要求
   API调用 → 最简单，按量付费
   私有化部署 → 需硬件，固定成本
   混合部署 → 敏感数据私有 + 一般任务API
```

### 3.3 选型示例

#### 例1：个人学习助手

```text
需求：日常问答、笔记整理、学习计划
任务复杂度：中等
中文需求：强
隐私要求：学习笔记，中等敏感
预算：<100元/月

推荐：DeepSeek-V3（API）+ 豆包（免费备用）
理由：中文好、便宜、API方便
```

#### 例2：企业客服 Bot

```text
需求：回答产品问题（基于知识库）、处理退货咨询
任务复杂度：中等
中文需求：强
隐私要求：涉及客户数据，高
预算：<5000元/月

推荐：Qwen-72B 本地部署 + DeepSeek API 备用
理由：客户数据不能上传第三方API，本地部署保安全
```

#### 例3：代码生成工具

```text
需求：代码补全、bug排查、测试生成
任务复杂度：复杂
中文需求：中等
隐私要求：涉及源代码，高
预算：团队预算

推荐：Claude Sonnet / GPT-4o API + 自建评测
理由：代码能力最强，需要好的推理能力
```

## 四、成本优化策略

### 4.1 分层路由策略

不是所有请求都要发给最强模型。实现一个"路由器"：

```text
用户请求 → 复杂度判断
├── 简单（90%的请求）→ 便宜模型
├── 中等（8%的请求） → 性价比模型
└── 复杂（2%的请求） → 强推理模型
```

这个策略通常可以省 70-80% 的费用，同时保持关键任务的质量。

### 4.2 Prompt 成本优化

长 prompt = 高成本。每次发请求都在为上下文付费。

**省钱技巧**：

1. **缩短 system prompt**：把不常用的规则放在知识库里
2. **精简历史对话**：只保留最近 3-5 轮
3. **用短输出格式**："用3个要点回答" 比 "写一段200字" 便宜
4. **缓存常用 prompt**：部分平台支持 prompt caching（如 Claude）
5. **减少 markdown 格式要求**：让 AI 输出纯文本比带格式便宜

### 4.3 缓存策略

如果多个用户问相同问题，不需要每次都调模型：

```text
用户提问 → 查缓存 → 命中缓存 → 直接返回（零成本）
                   → 未命中 → 调模型 → 存入缓存
```

简单实现：

```python
# 最简单的缓存（用Python字典）
cache = {}

def ask_ai(question):
    if question in cache:
        return cache[question]  # 免费
    answer = call_model(question)
    cache[question] = answer
    return answer
```

### 4.4 硬件成本（本地部署）

如果你想本地运行开源模型：

| 模型大小 | 推荐 GPU | GPU 价格（约） | 电费/月（约） |
|---------|---------|-------------|------------|
| 7B-8B | RTX 3060 12GB / RTX 4060 | ¥1500-2500 | ¥30-60 |
| 13B-14B | RTX 3090 24GB / RTX 4090 | ¥4000-8000 | ¥60-120 |
| 32B-34B | RTX 4090 24GB (量化) / M2 Ultra | ¥6000-12000 | ¥100-200 |
| 70B-72B | 2×RTX 3090 / A6000 / Mac Studio | ¥8000-20000+ | ¥150-400 |

> ⚠️ 如果你的用量不大（每月 < 1万次调用），API 通常比买硬件便宜。

## 五、实战：建立你的模型选型评测

### 5.1 快速评测流程

```text
1. 准备 10 条你的真实任务样例
2. 对每个模型用同一套 prompt 测试
3. 按以下维度打分（1-5）：

| 维度 | 模型A | 模型B | 模型C |
|------|-------|-------|-------|
| 准确性 | | | |
| 格式遵守 | | | |
| 中文质量 | | | |
| 响应速度 | | | |
| 综合评分 | | | |

4. 计算性价比：综合评分 / 每千次成本
```

### 5.2 长期选型策略

不要一次性选好就再也不变。模型在快速迭代：

- **每月**：关注新模型发布和价格变动
- **每季度**：重新跑一次评测，看排名变化
- **每半年**：评估是否值得切换主模型
