# 第 3 章：Prompt 入门

Prompt 是你给 AI 的任务说明。它不只是“提问技巧”，更像是给一个聪明但不了解你环境的合作者写工作单。

## 本章导读

- 预计阅读时间：15-22 分钟。
- 学习目标：写出结构化 prompt；使用示例、反例和分阶段输出；让 AI 对自己的结果做基本自检。
- 练习入口：[章节练习与验收映射表](../chapter-validation-map.md) 和 [Prompt 调试指南](../prompt-debugging-guide.md)。
- 相关材料：[Prompt 模式实践模板](../../examples/prompt-patterns.md) 和 [教学示范作业集](../teaching-examples.md)。

## Prompt 的基本结构

一个通用结构：

```text
你要完成的任务：

背景信息：

输入材料：

约束条件：

输出格式：

验收标准：
```

你不需要每次都写满，但越重要的任务越应该结构化。

## 清楚描述任务

含糊：

```text
优化这段话。
```

清楚：

```text
请把下面这段产品介绍改写得更适合官网首页。
目标读者是第一次听说我们产品的中小企业老板。
要求：语气专业、少用形容词、突出问题和结果。
```

“优化”这个词太宽。你需要说明优化方向：更短、更清楚、更有说服力、更适合初学者、更适合专家、更正式、更口语化，还是更容易转化。

## 给示例

当你想要固定风格或格式时，示例非常有用。

```text
请按下面风格生成 5 条标题：

示例：
- 不是工具太少，而是流程没有被设计
- 好 prompt 不是咒语，而是任务说明书

要求：
- 每条不超过 18 个字
- 不使用感叹号
- 避免“震撼”“必看”“神器”等词
```

示例比抽象描述更稳定，因为模型可以模仿具体模式。

如果你发现自己反复要求同一种语气、视觉风格、写作节奏或角色人格，就不要只把它写在单次 prompt 里。可以把它沉淀成 `STYLE.md`、`WRITER.md` 或 `DESIGN.md` 这类长期约束文件。这个方向在本书中称为 [Style Engineering 与 AI Native 创作](../style-engineering-ai-native.md)：prompt 负责一次生成，风格工程负责长期一致。

## 给反例

反例能告诉 AI 不要走哪条路。

```text
请写一段课程介绍。

不要写成这样：
“这是一门颠覆认知、引爆效率的 AI 神课。”

我希望的风格：
朴素、具体、可信，强调学习路径和实践结果。
```

很多时候，反例比要求更有用，因为它排除了常见坏答案。

## 分阶段输出

复杂任务不要一次要求最终答案。可以先计划，再执行。

```text
请分两步完成：
第一步：先列出你准备如何分析这个问题，不要给最终答案。
第二步：等我确认后，再按计划输出完整方案。
```

或者：

```text
请先给 3 个备选结构。
每个结构说明适合什么读者、优点和风险。
我选定结构后，你再写正文。
```

## 让 AI 自我检查

自查不是万能，但能发现明显问题。

```text
请检查你的回答是否满足以下标准：
1. 是否回答了我的核心问题。
2. 是否有未经核验的事实。
3. 是否遗漏关键风险。
4. 是否可以直接执行。

只列出需要修改的地方。
```

## 常见 prompt 模式

任务型：

```text
请完成 X，背景是 Y，输出为 Z。
```

顾问型：

```text
请站在 X 角色角度，评估 Y 方案，指出风险和改进建议。
```

教练型：

```text
不要直接给答案。请通过提问引导我自己完成。
```

审稿型：

```text
请按准确性、结构、表达、可执行性四个维度审查下面内容。
```

对比型：

```text
请比较 A、B、C 三个方案，给出适用场景、成本、风险和推荐选择。
```

## 同一结构，不同角色

好 prompt 的结构是通用的，但具体写法因角色而异。下面用同一个格式对比四个典型场景：

| 角色 | 任务 | 背景 | 约束 | 输出 |
|------|------|------|------|------|
| 产品经理 | 写竞品分析 | 市场调研阶段，需要初步对比 | 只对比已公开信息，标注信息来源日期 | Markdown 对比表格 + 3条行动建议 |
| 开发者 | 代码重构 | 旧 PHP 代码，迁移到 Python | 保持原有 API 行为不变，通过现有测试 | 重构计划 + 关键代码片段 + 风险点 |
| 运营 | 写活动方案 | 618 促销，预算 5 万，竞品也在做 | 不能涉及虚假宣传，ROI 预估要有依据 | 三点式活动框架 + 执行时间表 |
| 管理者 | 团队 AI 落地 | 15 人团队，已有飞书和 Notion | 月度预算不超 2000 元，不能影响现有项目 | 三步落地计划 + 每步验收标准 |

**关键点**：结构一样（任务→背景→约束→输出），但每个角色填的内容完全不同。**好的 prompt = 固定的结构 + 你的专业判断。**

## 练习

把下面这个弱 prompt 改写成强 prompt：

```text
帮我做一个 AI 学习计划。
```

要求改写后包含：

- 学习者背景。
- 时间约束。
- 目标场景。
- 输出格式。
- 验收标准。

你可以参考 [prompt 模式示例](../../examples/prompt-patterns.md)。
