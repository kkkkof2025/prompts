# 第 4 章：结构化 Prompt 与工作流

当任务变复杂，单个 prompt 往往不够。你需要的是工作流：让 AI 按步骤完成任务，每一步都有输入、输出和检查。

## 为什么要工作流

单个 prompt 适合简单任务，比如改写一句话、解释一个概念、生成一份清单。

工作流适合复杂任务，比如：

- 写一篇长文。
- 做竞品分析。
- 阅读论文并提炼观点。
- 生成代码并补测试。
- 规划课程。
- 分析用户反馈。

复杂任务的问题在于：如果 AI 第一步理解错了，后面的内容会全部偏掉。工作流可以把错误尽早暴露出来。

## 一个通用工作流

```text
1. 澄清目标：判断信息是否足够。
2. 拆解任务：列出步骤和产物。
3. 执行第一步：只处理一个小任务。
4. 检查输出：按标准发现问题。
5. 迭代修正：根据反馈重做。
6. 汇总交付：输出最终版本和后续建议。
```

## 示例：写一篇深度文章

第一轮：

```text
我想写一篇面向初学者的文章，主题是“为什么 prompt 不是咒语”。
请先不要写正文。
请先帮我确定：
1. 目标读者可能有什么误解。
2. 文章应该回答哪 5 个问题。
3. 推荐的文章结构。
```

第二轮：

```text
我选择第 2 个结构。
请先写详细提纲，每个小节列出核心观点、例子和可能的反对意见。
```

第三轮：

```text
请根据提纲写正文。
要求：
- 用通俗中文。
- 每节有一个具体例子。
- 不使用夸张营销词。
- 结尾给一个可执行练习。
```

第四轮：

```text
请审查这篇文章：
1. 哪些地方对初学者太抽象。
2. 哪些例子不够具体。
3. 是否有重复段落。
4. 给出修改建议，不要直接重写。
```

## 示例：让 AI 协助编程

```text
你将帮我修改一个已有代码库。
请按以下流程工作：
1. 先阅读项目结构和相关文件。
2. 用简短语言说明你理解的需求和受影响文件。
3. 在修改前给出计划。
4. 修改代码。
5. 运行相关测试。
6. 总结变更和验证结果。

约束：
- 不要重构无关代码。
- 不要删除我已有改动。
- 如果测试无法运行，请说明原因。
```

这个流程比“帮我修 bug”稳定得多，因为它强制 AI 先理解环境。

## 工作流中的检查点

检查点是你决定是否继续的地方。常见检查点：

- 需求理解是否正确。
- 资料来源是否可靠。
- 输出结构是否合适。
- 代码是否通过测试。
- 结果是否符合验收标准。
- 是否出现安全、隐私或成本风险。

## 把工作流写成模板

当一个流程反复出现，就应该模板化。

```text
# 模板：资料分析

目标：
请分析我提供的资料，并输出可执行结论。

步骤：
1. 先总结资料内容。
2. 列出最重要的事实。
3. 区分事实、推测和建议。
4. 给出行动清单。
5. 标注仍需核验的信息。

输出格式：
- 摘要
- 关键事实
- 可能解释
- 建议行动
- 待核验问题
```

模板不是为了限制创造力，而是减少重复沟通。

## 练习

选择一个你每周都会做的任务，例如写周报、整理会议纪要、学习新知识、分析数据或写代码。把它改造成一个 5 步 AI 工作流，并为每一步写清楚输入和输出。
