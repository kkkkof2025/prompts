# 第 4 章:结构化 Prompt 与工作流

当任务变复杂,单个 prompt 往往不够。你需要的是工作流:让 AI 按步骤完成任务,每一步都有输入、输出和检查。

## 本章导读

- 预计阅读时间:15-22 分钟。
- 学习目标:判断什么时候需要工作流;把复杂任务拆成多个检查点;把重复任务沉淀成可复用模板。
- 练习入口:[章节练习与验收映射表](../chapter-validation-map.md) 和 [AI 工作流配方库](../workflow-recipes.md)。
- 相关材料:[常用检查清单](../appendix-checklists.md) 和 [真实应用案例](../case-studies.md)。

## 为什么要工作流

单个 prompt 适合简单任务,比如改写一句话、解释一个概念、生成一份清单。

工作流适合复杂任务,比如:

- 写一篇长文。
- 做竞品分析。
- 阅读论文并提炼观点。
- 生成代码并补测试。
- 规划课程。
- 分析用户反馈。

复杂任务的问题在于:如果 AI 第一步理解错了,后面的内容会全部偏掉。工作流可以把错误尽早暴露出来。

## 一个通用工作流

```text
1. 澄清目标:判断信息是否足够。
2. 拆解任务:列出步骤和产物。
3. 执行第一步:只处理一个小任务。
4. 检查输出:按标准发现问题。
5. 迭代修正:根据反馈重做。
6. 汇总交付:输出最终版本和后续建议。
```

## 示例:写一篇深度文章

第一轮:

```text
我想写一篇面向初学者的文章,主题是"为什么 prompt 不是咒语"。
请先不要写正文。
请先帮我确定:
1. 目标读者可能有什么误解。
2. 文章应该回答哪 5 个问题。
3. 推荐的文章结构。
```

第二轮:

```text
我选择第 2 个结构。
请先写详细提纲,每个小节列出核心观点、例子和可能的反对意见。
```

第三轮:

```text
请根据提纲写正文。
要求:
- 用通俗中文。
- 每节有一个具体例子。
- 不使用夸张营销词。
- 结尾给一个可执行练习。
```

第四轮:

```text
请审查这篇文章:
1. 哪些地方对初学者太抽象。
2. 哪些例子不够具体。
3. 是否有重复段落。
4. 给出修改建议,不要直接重写。
```

## 示例:让 AI 协助编程

```text
你将帮我修改一个已有代码库。
请按以下流程工作:
1. 先阅读项目结构和相关文件。
2. 用简短语言说明你理解的需求和受影响文件。
3. 在修改前给出计划。
4. 修改代码。
5. 运行相关测试。
6. 总结变更和验证结果。

约束:
- 不要重构无关代码。
- 不要删除我已有改动。
- 如果测试无法运行,请说明原因。
```

这个流程比"帮我修 bug"稳定得多,因为它强制 AI 先理解环境。

## 工作流中的检查点

检查点是你决定是否继续的地方。常见检查点:

- 需求理解是否正确。
- 资料来源是否可靠。
- 输出结构是否合适。
- 代码是否通过测试。
- 结果是否符合验收标准。
- 是否出现安全、隐私或成本风险。

## 把工作流写成模板

当一个流程反复出现,就应该模板化。

```text
# 模板:资料分析

目标:
请分析我提供的资料,并输出可执行结论。

步骤:
1. 先总结资料内容。
2. 列出最重要的事实。
3. 区分事实、推测和建议。
4. 给出行动清单。
5. 标注仍需核验的信息。

输出格式:
- 摘要
- 关键事实
- 可能解释
- 建议行动
- 待核验问题
```

模板不是为了限制创造力，而是减少重复沟通。

### 实战：从混乱到流程——周报的蜕变

下面的例子展示了一个真实任务从"每次都要重新写 prompt"到"一次写完，用一年"的演变过程。

**阶段 1：每次临时写（原始状态，很多人的日常）**

每周五下午，打开 AI：

```text
帮我写周报。这周做了A、B、C。
```

问题：结果质量不稳定，格式每次不同，有时漏重要事项。

**阶段 2：固定 prompt（比原始好，但还有问题）**

```text
你是我的周报助手。请根据我提供的本周事项，生成结构化的周报：
- 本周完成事项
- 进行中的事项
- 遇到的阻塞
- 下周计划
- 需要支持的事项
```

问题：每次还要描述格式、风格、团队背景。

**阶段 3：完整工作流（一次配置，反复使用）**

```text
# 周报工作流

角色：你是我的个人助理，了解我的工作背景。

背景（固定）：
- 我是一名后端工程师，维护用户系统和支付模块
- 团队 8 人，主管是张总
- 每周五提交周报到飞书文档

输入（每周提供）：
请列出本周的关键事项（用列表或自由描述即可）

流程：
1. 理解我提供的事项，如有不清楚请先提问
2. 按五段结构整理：完成/进行中/阻塞/下周计划/需要支持
3. 每事项不超过 3 条，用动词开头
4. 阻塞事项必须写明影响和需要的资源

输出格式：
- 用 Markdown 表格，周报标题为「{本周日期范围} 工作周报」
- 每条信息后标注「已完成/进行中/需关注」状态

自查（固定）：
- 是否所有我提到的事项都被覆盖？
- 是否有未经确认的推测？
- 格式是否正确？
```

**效果对比**：

| 维度 | 阶段1（每次临时） | 阶段3（工作流） |
|------|-----------------|----------------|
| 写 prompt 时间 | 30秒（质量不稳定） | 0秒（粘贴模板） |
| AI 输出质量 | 忽好忽坏 | 稳定一致 |
| 格式一致性 | 每次不同 | 完全一致 |
| 遗漏事项 | 经常 | 几乎没有（有检查点） |
| 新人上手 | 不知道怎么写 | 直接粘贴模板 |

> **核心洞察**：工作流的本质不是"写得更好"，而是"不用再写"。

### 不同角色的工作流对比

同样的五步结构，不同岗位的工作流差异很大：

| 角色 | 常见工作流 | 检查点重点 | 输出物 |
|------|-----------|-----------|--------|
| 产品经理 | PRD评审→竞品分析→用户故事拆解→原型文案→评审材料 | 需求是否一致、竞品信息是否过时 | PRD草稿、对比表 |
| 开发者 | 理解需求→方案设计→代码实现→测试→代码审查 | 是否破坏已有功能、安全风险 | 代码+测试+变更说明 |
| 运营 | 活动策划→文案→多平台适配→数据追踪→复盘 | 数据可衡量、合规 | 活动方案+物料+复盘 |
| 教师 | 教学目标→内容组织→练习设计→讲解脚本→效果评估 | 难度适合、概念准确 | 教案+练习+评分标准 |
| 管理者 | 目标拆解→资源分配→进度追踪→风险识别→汇报 | 数据准确、优先级合理 | 计划+风险列表+汇报 |

> **关键原则**：工作流的检查点不是"让 AI 全部自己做"，而是"在 AI 容易出错的地方停下来让你判断"。

当模板开始包含语气、审美、角色人格、品牌规则和输出禁区时，它就不只是工作流模板，而开始接近 [Style Engineering](../style-engineering-ai-native.md)。这类模板适合长期项目，但要配合样例、反例和评分标准，否则很容易停留在"高级、专业、有质感"这类不可执行形容词上。

## 练习

选择一个你每周都会做的任务,例如写周报、整理会议纪要、学习新知识、分析数据或写代码。把它改造成一个 5 步 AI 工作流,并为每一步写清楚输入和输出。
