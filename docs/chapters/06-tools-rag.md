# 第 6 章：工具调用、RAG 与知识库

当 AI 只能聊天时，它主要依靠已有知识和你提供的上下文。当 AI 能调用工具时，它可以搜索、计算、读文件、写代码、查数据库、操作浏览器。能力更强，风险也更大。

## 工具调用是什么

工具调用是让模型在需要时请求外部函数或系统。例如：

- 搜索网页。
- 查询数据库。
- 读取文件。
- 运行代码。
- 发送邮件。
- 创建日程。
- 调用企业内部 API。

模型负责判断“该用哪个工具、传什么参数、如何解释结果”。系统负责真正执行工具。

## 工具调用的边界

给 AI 工具时，要同时给边界。

```text
你可以读取 docs/ 目录下的 Markdown 文件。
你不能读取 .env、keys、credentials、客户隐私数据。
在写入文件前，先说明准备修改哪些文件。
删除文件必须先获得确认。
```

工具越接近真实世界，越需要权限控制和审计。

## RAG 是什么

RAG 是 Retrieval-Augmented Generation，通常译为检索增强生成。它的思路是：先从知识库中检索相关资料，再把资料作为上下文交给模型生成回答。

RAG 适合解决两个问题：

- 模型不知道你的私有资料。
- 模型内置知识可能过时。

一个典型 RAG 流程：

```text
用户问题 -> 查询改写 -> 检索文档 -> 排序筛选 -> 注入上下文 -> 生成回答 -> 引用来源
```

## RAG 不是万能的

RAG 常见失败点：

- 文档切分太碎，丢失上下文。
- 检索词不好，找不到正确资料。
- 找到了资料，但模型没有正确使用。
- 知识库里本身有过时或冲突信息。
- 回答没有标明引用位置。

所以 RAG 项目不只是“把文件丢进去”。你需要设计文档结构、元数据、更新流程和评估集。

## 建立个人知识库

个人知识库可以很简单：

```text
knowledge/
├── profile.md       # 个人背景、偏好、长期目标
├── projects.md      # 当前项目
├── writing-style.md # 写作风格样例
├── glossary.md      # 常用术语
└── sources/         # 原始资料
```

你可以在对话中告诉 AI：

```text
请优先依据我提供的 knowledge/ 内容回答。
如果知识库没有答案，请明确说明，不要猜测。
```

## 知识库维护原则

- 原始资料和总结分开。
- 每条重要信息保留来源和日期。
- 定期删除过时内容。
- 对冲突信息做标记。
- 私密资料单独存放，限制访问。

## 工具调用安全清单

在让 AI 使用工具前，问自己：

- 它是否真的需要这个工具。
- 工具能访问哪些数据。
- 工具能修改什么。
- 是否有删除、发送、付款、发布等高风险动作。
- 是否有日志记录。
- 是否能回滚。

## 练习

创建一个小型知识库，放入 3 篇你自己的资料。然后让 AI 回答一个问题，并要求：

```text
请只依据我提供的资料回答。
每个结论后标注来自哪份资料。
如果资料不足，请说明缺口。
```
