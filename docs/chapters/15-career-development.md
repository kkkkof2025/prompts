# 第 15 章：AI 职业发展全景

学习 AI 不只是掌握技术，更关乎你的职业未来。本章帮你回答三个核心问题：

1. **学会了之后能做什么？** —— AI时代的职位地图
2. **我现在该补什么？** —— 技能要求与学习路径
3. **怎么找到机会？** —— 作品集、面试、转型策略

## 本章导读

- 预计阅读时间：18-25 分钟。
- 学习目标：明确 AI 相关职位的技能要求；制定个人作品集计划；准备 AI 相关面试；规划短期职业转型步骤。
- 练习入口：[章节练习与验收映射表](../chapter-validation-map.md)。
- 相关材料：[分角色学习路径](../learning-paths.md)、[真实应用案例](../case-studies.md) 和 [AI 能力评估量表](../assessment-rubric.md)。

## 一、AI 时代的职位地图

AI 不只是创造了新职位，也在改造几乎所有已有职位。以下职位分类按"离 AI 技术核心多远"来分，方便你定位自己。

### 1.1 AI 核心技术类

这些职位直接与 AI 系统、模型、工具链打交道。

#### 🧑‍💻 AI 应用工程师（AI Application Engineer）

**做什么**：用现有 AI 能力和工具构建产品功能。不训练模型，而是把模型、prompt、RAG、agent、工具调用组合成可运行的业务系统。

**典型日常**：

- 设计 prompt 和工作流，把业务需求转成 AI 可执行的任务
- 搭建 RAG 系统，连接私有知识库和 AI 模型
- 开发 agent 系统，让 AI 能调用工具、执行多步骤任务
- 搭建评估体系，确保 AI 输出质量和安全合规
- 与产品、业务团队协作，把 AI 能力嵌入现有产品

**必备技能**：

- 熟悉至少一种主流 AI 平台（OpenAI API / Claude API / DeepSeek API 等）
- 能写出结构化、可复用的 prompt 和 skill
- 理解 RAG 架构和向量数据库基础
- 基本编程能力（Python / JavaScript / TypeScript）
- 懂 API 调用和集成

**加分技能**：

- 有 agent 框架使用经验（LangChain / CrewAI / OpenClaw 等）
- 了解 OpenTelemetry 和 AI 可观测性
- 懂 MCP / A2A 协议
- 有生产环境部署经验

**适合人群**：有编程基础、想深入 AI 应用的开发者；本书第 1-10 章就是要帮你达到这个水平。

---

#### 🧪 AI 产品经理（AI Product Manager）

**做什么**：定义 AI 功能的产品策略，判断什么场景适合用 AI、什么不适合。

**典型日常**：

- 识别 AI 可以创造价值的业务场景
- 设计 AI 功能的产品方案和验收标准
- 与工程团队协作，把模糊需求转成可执行的 prompt 设计
- 建立 AI 产品的评估体系（不只是"好不好看"，而是准确率、覆盖面、成本等）
- 管理用户对 AI 的期望，处理失败案例和边界情况

**必备技能**：

- 产品基本功（需求分析、用户研究、竞品分析）
- 理解 AI 能力边界——知道模型能做什么、不能做什么
- 能手写出 prompt 原型
- 理解 RAG、agent、微调的基本概念
- 成本思维——知道 API 调用的成本结构

**加分技能**：

- 能用 AI 工具搭建产品原型（cursor / v0 / bolt 等）
- 有 A/B 测试和用户行为数据分析经验
- 理解 AI 安全与合规要求

**适合人群**：想做产品的产品经理、想转型 AI 赛道的业务人员。

---

#### 🛡️ AI 安全工程师（AI Security Engineer）

**做什么**：保护 AI 系统不被攻击，确保 AI 输出安全合规。

**典型日常**：

- 进行 prompt injection 和 jailbreak 测试
- 设计 agent 权限模型和审计日志方案
- 建立 AI 内容安全审核流程
- 评估模型和数据隐私风险
- 制定组织的 AI 使用安全规范

**必备技能**：

- 深入理解 LLM 的工作原理和常见攻击手段
- 安全工程基础（认证、授权、审计）
- 懂 prompt engineering 和 agent 架构
- 了解数据隐私法规（生成式 AI 管理办法、GDPR 等）

**加分技能**：

- 有红队测试（Red Teaming）经验
- 了解模型训练的安全风险
- 有安全合规认证

**适合人群**：安全背景想切入 AI 安全、本书读完后想专攻安全方向的人。

---

#### ✍️ AI 技术写作者 / AI 培训师（AI Technical Writer & Trainer）

**做什么**：把复杂的 AI 概念讲清楚，帮助团队和组织提升 AI 能力。

**典型日常**：

- 写 AI 使用指南、最佳实践文档（就像本书）
- 设计 AI 培训课程和工作坊
- 制作 prompt 模板库和案例集
- 帮非技术人员理解 AI 能做什么、不能做什么
- 收集用户反馈，改进教学材料

**必备技能**：

- 深入理解 prompt engineering 和 AI 工作流
- 优秀的写作和表达能力
- 能设计结构化学习路径
- 有同理心——能从初学者的角度思考

**加分技能**：

- 教学/培训经验
- 视频制作或内容创作能力
- 社区运营经验

**适合人群**：擅长表达和写作、希望帮别人用好 AI 的人。

### 1.2 AI + 行业融合类

这些职位把 AI 能力嵌入特定行业。你不需要成为 AI 专家，但要比同行更会用 AI。

| 职位方向 | 核心场景 | 关键 AI 技能 |
|---------|---------|------------|
| **AI + 运营** | 用 AI 做内容生成、用户分析、自动化营销 | prompt 设计、工作流自动化、数据分析 |
| **AI + 客服** | 搭建 AI 客服 bot、智能知识库 | RAG、agent 设计、对话评估 |
| **AI + HR** | 简历筛选、培训材料生成、员工问答 | prompt 设计、RAG、安全合规 |
| **AI + 金融** | 研报分析、风险识别、合规审查 | 数据分析、私有部署、安全治理 |
| **AI + 教育** | 个性化辅导、作业批改、教案生成 | prompt 设计、RAG、评估体系 |
| **AI + 医疗** | 病历总结、医学文献检索、辅助诊断建议 | 高安全要求、私有部署、合规 |
| **AI + 法律** | 合同审查、案例检索、法规解读 | 事实核查、来源追踪、安全合规 |
| **AI + 设计** | AI 辅助设计、图片/视频生成、品牌风格 | 多模态模型、Style Engineering |
| **AI + 销售** | 客户洞察、话术优化、商机分析 | prompt 设计、数据分析、CRM 集成 |

### 1.3 周边生态类

这些职位不一定天天调 prompt，但对 AI 生态至关重要。

| 职位 | 核心工作 |
|------|---------|
| **AI 数据标注 / 数据治理** | 准备高质量训练数据、标注、数据质量管理 |

| **AI 解决方案架构师** | 帮客户设计 AI 落地架构（更偏售前/咨询） |

## 四、作品集构建指南

无论你应聘什么 AI 相关岗位，**作品集比简历更重要**。AI 不像传统开发能看 GitHub 贡献数，面试官更想看到你实际用 AI 做成了什么事。

### 4.1 作品集核心项目（选 3-5 个）

#### 🥇 必选项目：个人 AI 助手

用 OpenClaw 或类似平台搭建一个真正在用的个人 AI 助手。

**至少要包含**：

- 一个你的个人知识库（profile + projects + writing style）
- 至少 3 个可复用 skill（如：周报生成、会议纪要、代码审查）
- 一份 agent 工作说明，定义权限和边界
- 一份使用日记，记录 30 天的实际效果和改进

**展示方式**：

- GitHub README：说明架构、skill 列表、使用效果截图
- 录一个 3 分钟演示视频
- 写一篇技术博客，记录搭建过程和踩坑经验

#### 🥈 特色项目：行业 AI 方案

选一个你熟悉的行业，设计一个 AI 落地方案。

**推荐方向**：

- 客服知识库 RAG 系统（Zendesk / 飞书知识库 + AI）
- 工作周报自动生成器（从邮件 / 文档提取要点）
- 学习辅导 agent（帮学生拆解题目、逐步引导）
- 代码审查 skill（自动检查代码规范和潜在 bug）
- 内容创作工作流（选题 → 大纲 → 初稿 → 润色 → 配图）

**展示方式**：

- 提供可复制的 prompt / skill 模板
- 展示前后效果对比
- 说明设计思路和边界考虑

#### 🥉 可选项目：AI 工具评测

写一篇深度评测，比较不同模型或工具在特定任务上的表现。

**要求**：

- 有明确的评测标准
- 有定量数据（不只是"感觉"）
- 有实际使用案例

### 4.2 作品集展示规范

#### GitHub 仓库

```text
your-name-ai-portfolio/
├── README.md              # 个人简介 + 项目索引
├── personal-assistant/    # 项目1：个人AI助手
│   ├── README.md
│   ├── skills/
│   ├── knowledge/
│   └── demo.mp4
├── industry-solution/     # 项目2：行业方案
│   ├── README.md
│   ├── prompts/
│   └── evaluation.md
├── model-evaluation/      # 项目3：模型评测
│   └── README.md
└── blog-posts/            # 你的技术文章
    └── README.md
```

**关键原则**：

- README 要能让面试官 5 分钟内看懂你做了什么
- 一定要有实际效果展示（截图、视频、数据对比）
- 写清楚你的设计思路和遇到的困难——这比完美结果更重要

#### 技术博客

推荐平台：

- **中文**：知乎（AI 话题流量大）、掘金（开发者多）、微信公众号（私域沉淀）
- **英文**：Medium、Dev.to、个人博客

**前 5 篇文章建议**：

1. "我用 30 天学了 Prompt Engineering，这是 10 条最有用的经验"
2. "从零搭建 RAG 知识库的完整记录（含踩坑）"
3. "我用 AI 省下了每天 2 小时——这是我设计的 3 个工作流"
4. "AI Agent 不是黑魔法——这篇文章讲清楚原理和风险"
5. "比较 5 个模型在中文任务上的表现（附评测数据）"

## 五、面试准备

### 5.1 常见面试题型

#### 基础题

> 1. prompt、skill、agent 的区别是什么？
> 2. RAG 的核心流程是什么？常见失败点有哪些？
> 3. 你会怎样评估一个 AI 生成的回答质量？
> 4. Agent 做高风险操作时应该有哪些安全措施？

#### 设计题

> 1. 如果让你设计一个客服 AI 机器人，你会怎么设计？（从 prompt → RAG → agent → 评估 → 安全）
> 2. 一个用户说"AI 老是回答不对"，你会从哪些角度排查问题？
> 3. 老板想用 AI 替代 3 个客服，你会怎么评估可行性和风险？

#### 案例题

> 1. 给你一个模糊需求："用 AI 提升运营效率"，你会怎么拆解、设计、落地？
> 2. 你发现 AI 助手偶尔会泄露其他用户的信息，你会怎么处理？
> 3. 一个 prompt 的评估分从 85/100 降到了 70/100，你会怎么排查？

### 5.2 面试准备清单

- [ ] 能用 2 分钟讲清楚自己做的 3 个 AI 项目
- [ ] 能用 1 句话解释 prompt / RAG / agent / skill 的区别
- [ ] 能现场写出一个结构化 prompt
- [ ] 能说出至少 3 个 AI 常见风险和应对措施
- [ ] 能分析自己作品集中一个项目的设计决策
- [ ] 准备 3 个你想问面试官的问题（关于他们的 AI 实践）

### 5.3 面试要问公司的问题

面试不仅是公司考察你，也是你考察公司。以下问题帮你判断这个团队是否真的在做 AI 落地，还是在"蹭 AI 热度"：

> 1. 你们目前 AI 功能在生产环境中的使用频率和效果如何？
> 2. AI 功能的评估体系是怎样的？有没有评测集？
> 3. 团队对 AI 输出的安全性有哪些措施？
> 4. 新人入职后会在多长时间内接触到生产环境的 AI 项目？
> 5. 团队最近一次因为 AI 输出质量出问题是什么情况？怎么处理的？

**红色预警信号**（如果听到这些要小心）：

- "我们使用了最先进的 AI 技术" 但说不出具体是什么
- "AI 会替代所有人工" 但没有具体方案
- 团队没有评测体系，只看"感觉好不好"
- 没有 AI 安全规范

## 六、职业转型路径

### 6.1 从零基础到 AI 应用工程师（3 个月计划）

| 月份 | 目标 | 关键行动 | 交付物 |
|------|------|---------|--------|
| 第 1 月 | 基础对话 + Prompt | 完成本书第 0-4 章，在真实场景中每天用 AI 完成至少 1 个任务 | 10 个可复用 prompt + 3 个工作流模板 |
| 第 2 月 | RAG + Skills | 完成本书第 5-7 章，搭建个人知识库，写 3 个 skill | 个人知识库 + 3 个 skill + 1 个评测集 |
| 第 3 月 | Agent + 项目 | 完成本书第 8-14 章，搭建个人 AI 助手并写一篇技术博客 | 作品集项目 + 博客文章 |

**转型关键**：第 2 个月末开始投简历，不要等"完全学完"。面试本身也是学习。

### 6.2 从产品/运营转 AI 产品经理（2 个月计划）

| 月份 | 目标 | 关键行动 |
|------|------|---------|
| 第 1 月 | 建立 AI 认知 | 完成本书第 0-5 章，用 AI 完成 3 个真实工作任务 |
| 第 2 月 | 做 AI 方案 | 设计 1 个 AI 产品方案，用 prompt 和 RAG 搭建原型 |

**你的优势**：你已懂产品/用户/业务，缺的只是 AI 能力边界认知。不要把自己当"从零学编程的人"。

### 6.3 从非技术岗转 AI 培训师/技术写作者（1 个月计划）

| 周 | 目标 | 关键行动 |
|----|------|---------|
| 第 1 周 | 掌握 prompt | 本书第 0-3 章，每天写一篇 AI 使用日记 |
| 第 2 周 | 建立案例库 | 本书第 4-7 章，收集 20 个 AI 使用案例 |
| 第 3 周 | 开始输出 | 写 2 篇 AI 教程文章，录制 1 个教程视频 |
| 第 4 周 | 构建教学材料 | 设计 1 个 AI 入门工作坊大纲 + 课件 |

**你的优势**：表达能力和共情力是你的核心竞争力，AI 技术只是工具。

### 6.4 Freelancer 起步指南

如果在职或不确定要不要全职转型，可以先做 Freelancer 试水。

**起步步骤**：

1. **第 1-4 周**：用本书方法搭建个人 AI 助手，积累 10 个可复用 prompt/skill
2. **第 5-6 周**：在社交平台分享你的 AI 使用经验，建立初步影响力
3. **第 7-8 周**：在 Upwork / 猪八戒接 2-3 个小单（500-2000 元级别）
4. **第 9-12 周**：积累评价，提高报价，标准化交付流程

**接单建议**：

- 从 prompt 优化、AI 工作流定制、小型 RAG 搭建开始
- 不要接"替代开发"类的大项目（需求不清、价格低、交付难）
- 每个项目都要求客户写评价
- 建立可重复使用的模板，降低交付成本

## 七、持续成长：如何在 AI 时代保持竞争力

### 7.1 建立学习系统

```text
每周：
├── 用 AI 完成 3 个真实任务（不要只为学习而学）
├── 读 1 篇 AI 行业动态文章
├── 把本周最好用的 prompt 保存到知识库
└── 写 1 条学习笔记（公开发布效果更好）

每月：
├── 复盘：哪些 skill 需要更新，哪些流程可以优化
├── 看 1 个开源 AI 项目（理解别人的设计思路）
└── 做 1 个小评测（新模型 / 新工具 / 新 prompt pattern）

每季度：
├── 检查前沿资料是否过时（参考本书第 12 章）
├── 更新简历和作品集
└── 参加 1 次 AI 社区活动（线上或线下）
```

### 7.2 长期发展建议

1. **不要追每个新工具**：工具的底层原理是相通的。把 prompt、RAG、agent、评估这四个基础吃透，新工具上手很快。

2. **建立"T 型能力"**：横向了解 AI 生态全貌（本书就是帮这个），纵向在 1-2 个方向深耕（比如专注于 AI + 教育，或专注于 agent 安全）。

3. **积累失败经验**：面试时最有价值的不是你成功了多少次，而是你能说清楚"为什么那次失败了，学到了什么"。

4. **保持输出**：写文章、做分享、帮别人解决问题。AI 领域变化太快，教别人是最好的学习方式。

5. **守住底线**：AI 越强大，越需要伦理和责任感。不要让"能力很强"变成"什么都可以做"。
