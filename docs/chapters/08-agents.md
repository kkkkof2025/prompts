# 第 8 章：Agent，从聊天到行动

聊天机器人主要回答问题。Agent 不只是回答，它会围绕目标进行计划、调用工具、观察结果、调整策略，并在一定边界内持续执行。

## Agent 的基本循环

一个简化的 agent 循环：

```text
目标 -> 计划 -> 行动 -> 观察 -> 反思 -> 下一步行动 -> 完成
```

例如，让 AI agent 修复代码缺陷：

1. 阅读错误信息。
2. 搜索相关代码。
3. 推断原因。
4. 修改文件。
5. 运行测试。
6. 根据测试结果继续修复。
7. 总结变更。

## Agent 需要哪些组件

- 模型：负责理解、规划和生成。
- 工具：执行搜索、文件、代码、API、浏览器等操作。
- 记忆：保存任务状态、用户偏好和历史经验。
- Skills：调用成熟流程。
- 权限：限制能读什么、写什么、发什么。
- 评估：判断是否完成。
- 日志：记录做过什么，便于审计和回滚。

## 什么时候该用 Agent

适合 agent 的任务：

- 目标明确，但步骤需要探索。
- 需要多次使用工具。
- 需要根据中间结果调整计划。
- 有可验证的完成标准。
- 错误可以被检测和修复。

不适合 agent 的任务：

- 后果很严重但无法回滚。
- 目标本身不清楚。
- 没有验收标准。
- 涉及高风险法律、医疗、金融决策。
- 需要访问敏感数据但没有权限控制。

## 给 Agent 的任务说明

```text
目标：
请修复项目中登录页提交后无响应的问题。

边界：
- 只修改登录相关文件。
- 不要改数据库结构。
- 不要删除已有测试。
- 修改前先说明计划。

验收：
- 登录成功后跳转到 dashboard。
- 错误密码显示错误提示。
- 相关测试通过。

过程要求：
- 先阅读相关文件。
- 每次修改后运行最小相关测试。
- 最后总结修改文件和验证结果。
```

## Agent 的风险

Agent 的风险来自“行动能力”。

常见风险：

- 读取不该读取的文件。
- 修改过多无关代码。
- 调用外部 API 产生费用。
- 把草稿内容发布到外部。
- 删除数据。
- 在错误假设下长时间执行。
- 生成难以审计的复杂变更。

## Agent 安全边界

最小权限原则：只给完成任务必需的权限。

分阶段授权：先读，再计划，再写，再执行高风险动作。

可观察：保留日志、diff、命令输出和结果摘要。

可回滚：重要操作前要能恢复。

人工确认：发送邮件、支付、删除、发布、改变权限等动作必须确认。

## 多 Agent 协作

多 agent 协作适合任务可以拆成相互独立的部分。例如：

- 一个 agent 查资料，一个 agent 写代码，一个 agent 做审查。
- 一个 agent 写前端，一个 agent 写后端。
- 一个 agent 从初学者视角读稿，一个 agent 从安全视角审查。

关键是写清楚各自的文件范围和责任边界。否则多个 agent 会互相覆盖。

## 练习

选择一个真实任务，写一份 agent 工作说明。必须包含：

- 目标。
- 可使用工具。
- 禁止事项。
- 验收标准。
- 需要人工确认的动作。
