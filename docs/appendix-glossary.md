# 附录 B：AI 术语表

这份术语表面向初学者。它不追求学术定义最完整，而追求你读书、看文档、使用工具时能快速理解。

如果你想知道某个术语应该回到哪一章、哪个案例或哪个练习，请看 [术语回链索引](glossary-links.md)。

## A

### Agent

能围绕目标进行计划、调用工具、观察结果并继续行动的 AI 系统。聊天机器人主要回答，agent 可以执行。

简单理解：

```text
聊天机器人：你问，它答。
Agent：你给目标，它计划、行动、检查、继续。
```

### A2A

Agent2Agent 的缩写，指 agent 与 agent 之间互操作和协作的协议方向。它关注不同 agent 如何发现彼此能力、交换任务状态和传递结果。

### Alignment

通常译为“对齐”。意思是让 AI 的行为更符合人类意图、价值、安全边界和使用规则。

## B

### Blackboard Architecture

黑板架构。多个模块或 agent 不直接互相私聊，而是围绕一个共享黑板读取任务状态、证据、假设和中间结果，再把自己的发现写回去。它适合复杂、多角色、需要复盘的协作任务。

## C

### Chain of Thought

常译为“思维链”。指模型在解决复杂问题时进行中间推理的方式。普通用户不需要强迫模型暴露完整推理过程，更实用的做法是要求它给出结论、依据、检查点和不确定性。

### Context Window

上下文窗口。模型一次能看到的输入范围，包括当前对话、文件片段、工具结果和系统说明。窗口大不代表一定理解得好，长资料仍需要结构化。

### Context Engineering

上下文工程。指为模型下一步行动选择、排序、压缩、隔离和追踪上下文的工程实践。它不只是写 prompt，而是管理模型应该看到什么、不能看到什么、哪些资料需要引用、哪些记忆可以调用。

### CQRS

Command Query Responsibility Segregation，命令查询职责分离。它把改变状态的 command 和读取状态的 query 分开，适合读写需求差异明显、查询视图复杂的系统。

## E

### Embedding

把文本、图片等内容转换成向量表示的方法。常用于搜索、推荐、相似度比较和 RAG。

### Evaluation

评估。判断 AI 输出是否满足任务要求。可以是人工评分、自动测试、事实核验、格式检查或小型评测集。

### Event Sourcing

事件溯源。把状态变化记录成按时间顺序追加的事件，而不是只保存当前状态。它适合需要审计、回放、复盘和恢复的多 agent 协作任务。

## F

### Fine-tuning

微调。在已有模型基础上用特定数据继续训练，让模型更适合某类任务、风格或格式。微调不是解决所有问题的第一选择，很多问题用 prompt、RAG 或 skill 就够。

### Function Calling

函数调用或工具调用。模型根据任务决定调用外部函数，例如搜索、查数据库、运行代码或创建日程。

## G

### Guardrail

护栏。限制 AI 行为的规则、检查、过滤器或人工确认机制。比如不允许删除文件、不允许输出隐私、不允许直接给医疗诊断。

## H

### Hallucination

幻觉。AI 生成看似合理但不真实的信息。降低幻觉的关键是提供来源、要求标注不确定性、使用工具核验和建立评估。

### Handoff

交接。一个 agent 把任务转交给另一个更适合的 agent 或流程。例如“资料搜索 agent”把结果交给“写作 agent”。

### Hermes

开放模型生态中常被讨论的一类模型路线和训练作品。本书把 Hermes 放在开放模型与 agent 能力演进里理解，不把某个具体版本写成永久不变的结论。

### HiMeS

个性化记忆系统相关研究方向。本书用它帮助读者理解“长期记忆、用户画像、任务历史和隐私边界”如何影响 AI 助手设计。

## L

### LLM

Large Language Model，大语言模型。擅长处理文本、代码和结构化语言任务，也可以作为多模态系统的一部分。

### Long Context

长上下文。指模型可以处理很长输入。适合读长文档、代码库、会议记录，但仍需要目录、引用和分块策略。

## M

### MCP

Model Context Protocol，模型上下文协议。它提供一种让 AI 应用连接外部工具和数据源的标准化方式。

### Memory

记忆。让 AI 保存跨会话信息，例如用户偏好、项目背景、长期目标和历史经验。好的记忆需要写入、检索、更新和删除机制。

### Materialized View

物化视图。数据库预先计算并保存的查询结果，适合高频统计、审批看板和报表。它和普通 view 的区别在于，物化视图会存结果，普通 view 只存查询定义。

### Multimodal

多模态。模型能处理文本之外的信息，例如图片、音频、视频、文件、屏幕和表格。

## O

### Open Model

开放模型。通常指权重、代码、训练方法或使用方式在不同程度上开放的模型路线。不同项目开放范围不同，阅读许可证和模型卡比只看“开源”两个字更重要。

### OpenClaw

个人 AI 助手和多通道 agent 工作台方向的案例。本书用它讨论个人工作台、工具连接、权限边界和前沿工具复核，不要求读者必须安装某个固定版本。

## P

### Prompt

提示词。你给 AI 的任务说明。好的 prompt 通常包含目标、背景、约束、输出格式和验收标准。

### Prompt Engineering

提示词工程。设计、测试、评估和维护 prompt 的方法。它不只是写一句神奇指令，而是把任务说明写清楚。

### Prompt Injection

提示注入。指用户输入、网页、文档、邮件、图片或外部工具结果中夹带指令，试图让 AI 忽略原有规则、泄露信息或执行越权动作。

### Projection

投影。把事件流、写入模型或黑板状态转换成读模型的过程。它常和 CQRS、事件溯源一起出现，用来让系统快速查询当前状态、看板和统计。

### Transactional Outbox

事务外箱。把待发布事件和业务数据写进同一个事务，再由独立 worker 可靠发布到消息系统或事件流的模式。它主要用来避免双写不一致。

## R

### RAG

Retrieval-Augmented Generation，检索增强生成。先从知识库检索相关资料，再让模型基于资料回答。适合私有知识和过时风险高的事实问题。

### Reasoning Model

推理模型。通常在复杂规划、数学、代码和多步骤问题上更稳，但可能更慢、更贵。

### Read Model

读模型。为查询优化的状态视图，例如当前任务表、审批队列、agent 工作量和风险清单。读模型可以从事件流重建，不应该当成唯一事实源。

### Idempotent Consumer

幂等消费者。重复收到同一条消息时，执行结果保持一致的消费端设计。它通常依赖已处理消息表、唯一消息编号或状态检查。

### Inbox

消费端去重表。有些实现会把已处理消息表叫 Inbox。它的作用是记录已经消费过的消息编号，避免重复消息再次改变读模型或业务状态。

### Saga

Saga。把跨多个服务、多个 agent 或多个本地事务的长流程拆成可审计的步骤，并为每一步准备补偿动作的模式。它不保证全局原子性，但能把失败后的恢复路径写清楚。

### Process Manager

流程协调器。负责跟踪 Saga 进度、决定下一步命令、触发补偿动作的组件。它本身通常保存流程状态，但不是事实源。

### Compensation

补偿动作。Saga 失败后执行的逆向或修正操作，用来把系统拉回可接受状态。补偿不等于完美回滚。

### Durable Execution

持久化执行。让长时间运行的流程在进程崩溃、重启、等待人工或外部回调后，能根据历史继续执行的运行时能力。它常见于 workflow engine、durable workflow 和 serverless orchestration。

### Durable Timer

可持久化定时器。定时等待状态会被保存下来，系统重启后仍能在约定时间继续流程。

## S

### Skill

可复用能力包。通常包含说明、流程、模板、脚本、资源和边界。Skill 把经验从一次性 prompt 固化为可维护资产。

### Style Engineering

风格工程。本书用它指一组正在形成的实践：把语气、审美、输出结构、品牌规则、角色人格和行为边界写成可复用约束，让 AI 在长期项目中保持稳定风格。它不是已经统一标准化的行业术语，阅读时要区分已有产品能力和本书推演。

### System Prompt

系统提示。比用户普通消息更高优先级的规则，用于定义模型角色、行为边界、工具使用规则和安全要求。

## T

### Token

模型处理文本的基本单位。中文、英文、符号和代码都会被拆成 token。上下文长度和计费常与 token 有关。

### Tool Use

工具使用。AI 调用搜索、文件、代码、数据库、浏览器或 API 完成任务。工具能力越强，权限和审计越重要。

## V

### Vector Database

向量数据库。用于存储和检索 embedding，常用于 RAG 和语义搜索。

## 学术定义与日常用法的区别

AI 术语经常有两种用法：论文中的严格定义，和产品文档、社区讨论中的日常用法。初学时先掌握日常用法，遇到工程实现或研究论文时再回到严格定义。

## 遇到新术语时怎么问 AI

```text
请解释【术语】。
要求：
1. 先用一句话解释。
2. 再给一个生活类比。
3. 再说明它在 AI 系统中解决什么问题。
4. 最后列出它容易被误解的地方。
```
