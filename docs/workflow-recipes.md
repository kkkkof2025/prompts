# AI 工作流配方库

这份配方库把常见任务整理成可复制的工作流。每个配方都包含适用场景、输入、步骤、prompt 模板和验收标准。

如果你还不确定一个任务是否应该做成工作流、skill、RAG 或 agent，先读 [AI 任务选择决策指南](task-decision-guide.md)。

## 使用方式

不要照搬后直接用于所有任务。先替换背景、资料、约束和验收标准，再让 AI 执行。

一个好配方应该能回答：

```text
我要做什么？
AI 需要什么材料？
AI 应该按什么步骤做？
怎样判断结果合格？
哪些地方必须人工确认？
```

## 配方 1：文章精读

适用场景：

阅读论文、报告、长文章或政策文件时，先建立理解，再提炼行动。

输入：

- 原文或摘要。
- 目标读者。
- 阅读目的。

Prompt：

```text
请帮我精读下面资料。

阅读目的：
【例如：判断这篇文章对我的 AI 学习书有什么启发】

要求：
1. 先用 5 句话总结全文。
2. 列出最重要的 5 个观点。
3. 区分事实、作者观点和你的推测。
4. 提取 3 条可行动建议。
5. 标注资料中没有说明或需要核验的信息。

资料：
【粘贴资料】
```

验收标准：

- 不把推测写成事实。
- 行动建议能直接执行。
- 清楚标注需要核验的信息。

## 配方 2：会议纪要

适用场景：

从会议转写、聊天记录或零散笔记中整理可执行纪要。

Prompt：

```text
请整理下面会议记录。

要求：
1. 只依据记录，不补充未出现的信息。
2. 输出会议摘要、关键决定、待办事项、争议和待确认问题。
3. 待办事项字段：事项、负责人、截止时间、依赖。
4. 缺失字段写“待确认”。

会议记录：
【粘贴记录】
```

验收标准：

- 每个待办都能被复制到任务管理工具。
- 争议没有被误写成决定。
- 未确认负责人和日期没有被编造。

## 配方 3：周报生成

适用场景：

把一周零散工作整理成适合发给上级或团队的周报。

Prompt：

```text
请把下面工作记录整理成周报。

目标读者：
【直属上级/项目组/跨部门同事】

要求：
1. 把工作分为已完成、进行中、风险、下周计划。
2. 每条已完成事项写清结果或影响。
3. 风险要写清需要谁支持。
4. 不夸大成果，不编造数据。

工作记录：
【粘贴记录】
```

验收标准：

- 上级能快速判断进展和风险。
- 没有空泛描述。
- 下周计划具体可执行。

## 配方 4：竞品分析

适用场景：

比较多个产品，为功能决策、定位或路线图提供依据。

Prompt：

```text
请基于我提供的资料做竞品分析。

决策问题：
【例如：我们是否应该做团队知识库问答功能】

竞品：
- A：【资料】
- B：【资料】
- C：【资料】

比较维度：
- 目标用户
- 核心功能
- 使用流程
- 权限和安全
- 定价或商业模式
- 对我们的启发

要求：
1. 只依据资料回答。
2. 每条事实标注来源。
3. 区分事实、推测和建议。
4. 列出待核验信息。
```

验收标准：

- 输出服务于明确决策。
- 不把营销文案当事实。
- 能指出资料缺口。

## 配方 5：用户反馈分类

适用场景：

把大量用户反馈归类，用于产品迭代、客服改进和运营分析。

Prompt：

```text
请把用户反馈分类。

分类标签：
- 故障反馈
- 功能需求
- 价格异议
- 服务体验
- 正面评价
- 续费或购买意向
- 其他

要求：
1. 允许多标签。
2. 每条反馈给出分类理由。
3. 不确定时标注“不确定”。
4. 输出 Markdown 表格。

反馈：
【粘贴反馈列表】
```

验收标准：

- 多标签处理合理。
- 分类理由简短明确。
- 不确定样例没有被强行分类。

## 配方 6：学习计划

适用场景：

为个人、团队或课程设计由浅入深的学习计划。

Prompt：

```text
请制定学习计划。

学习者背景：
【基础、职业、已有经验】

目标：
【希望达到的可观察结果】

约束：
- 每周可投入：【时间】
- 工具或预算：【限制】
- 不希望学习：【排除内容】

输出：
用表格列出每周主题、学习内容、练习、小作品、验收标准。

要求：
计划必须由浅入深，每周都有可提交成果。
```

验收标准：

- 符合时间限制。
- 有真实练习。
- 不堆砌工具名。

## 配方 7：论文或报告摘要

适用场景：

快速理解论文、行业报告和技术白皮书。

Prompt：

```text
请总结下面论文或报告。

我的背景：
【例如：产品经理，不是研究员】

输出结构：
1. 一句话结论
2. 研究或报告解决的问题
3. 核心方法
4. 关键发现
5. 对我的启发
6. 局限和待核验信息

资料：
【粘贴摘要、正文或链接摘录】
```

验收标准：

- 适合目标读者。
- 不遗漏局限。
- 能提炼实践启发。

## 配方 8：代码阅读

适用场景：

理解陌生模块、定位 bug 或准备重构。

Prompt：

```text
请帮我阅读下面代码。

目标：
【理解模块职责/定位 bug/准备修改】

要求：
1. 先总结文件职责。
2. 画出主要数据流或调用关系。
3. 列出关键函数和状态。
4. 指出可能风险或不清楚的地方。
5. 不要直接改代码，先给理解结果。

代码：
【粘贴代码或文件摘要】
```

验收标准：

- 能帮助人理解结构。
- 不急着修改。
- 明确标注不确定点。

## 配方 9：Bug 修复协作

适用场景：

让 AI 协助工程修复，但控制修改范围和风险。

Prompt：

```text
请协助修复 bug。

现象：
【描述现象】

复现步骤：
【列出步骤】

错误信息：
【日志或截图文字】

范围：
- 允许读取：【文件或目录】
- 允许修改：【文件或目录】

禁止：
- 不改无关模块。
- 不删除测试。
- 不回滚已有改动。

流程：
1. 先阅读相关代码。
2. 说明可能原因。
3. 给出修改计划。
4. 等确认后再修改。
5. 修改后运行最小相关测试。
```

验收标准：

- 修改范围明确。
- 测试或验证明确。
- 最终能说明原因和变更。

## 配方 10：内容改写

适用场景：

把一段内容改成适合不同读者、渠道或风格的版本。

Prompt：

```text
请改写下面内容。

目标读者：
【例如：零基础读者/老板/工程师/学生】

目标场景：
【官网/邮件/课程介绍/社交媒体/内部文档】

要求：
- 保留核心事实。
- 语气：【专业/亲切/简洁/教学式】
- 不使用夸张营销词。
- 如果原文信息不足，不要补编事实。

原文：
【粘贴内容】

输出：
1. 改写版本
2. 改写原则
3. 未改动的核心信息
```

验收标准：

- 读者匹配。
- 没有改变事实。
- 风格符合渠道。

## 配方 11：决策矩阵

适用场景：

在多个工具、模型、课程、技术方案之间选择。

Prompt：

```text
请帮我做决策矩阵。

选项：
- A：【说明】
- B：【说明】
- C：【说明】

我的目标：
【说明】

决策标准：
- 【标准 1】，权重：【高/中/低】
- 【标准 2】，权重：【高/中/低】
- 【标准 3】，权重：【高/中/低】

输出：
1. 对比表
2. 每个选项的优势和风险
3. 推荐选择
4. 推荐成立的前提
5. 什么时候应该改变选择
```

验收标准：

- 标准和目标一致。
- 推荐有前提。
- 能解释何时切换。

## 配方 12：发布前审查

适用场景：

发布文章、文档、课程、项目说明前做质量检查。

Prompt：

```text
请对下面内容做发布前审查。

目标读者：
【说明】

发布场景：
【GitHub/公众号/课程/公司内部】

检查维度：
1. 准确性
2. 结构清晰度
3. 初学者可读性
4. 可执行性
5. 风险和边界
6. 链接或引用

要求：
先列问题，不要直接重写。
每个问题给出严重程度和修改建议。

内容：
【粘贴内容】
```

验收标准：

- 问题按严重程度排序。
- 建议具体可改。
- 不把风格偏好当事实错误。

## 配方沉淀方法

当某个配方连续 3 次有效，就可以把它升级为 skill：

```text
配方 -> 固定输入 -> 固定输出 -> 边界 -> 验收标准 -> 示例 -> Skill
```
