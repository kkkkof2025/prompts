# 产品案例

## 案例 1：围绕决策问题做竞品分析

场景：

产品经理需要比较 3 个竞品，判断下一版本是否加入“团队知识库问答”功能。

失败 prompt：

```text
帮我分析一下这几个竞品哪个好。
```

为什么失败：

“哪个好”没有决策标准。竞品分析应该服务于具体产品选择，而不是输出泛泛排名。

改进 prompt：

```text
请基于我提供的资料做竞品分析。

决策问题：
我们是否应该在下一版本加入“团队知识库问答”功能。

比较对象：
- 竞品 A
- 竞品 B
- 竞品 C

比较维度：
- 目标用户
- 核心功能
- 知识库接入方式
- 权限与安全
- 定价或商业模式
- 对我们的启发

要求：
1. 只依据资料回答。
2. 每条事实标注来自哪个资料。
3. 把事实、推测和建议分开。
4. 列出还需要人工核验的信息。

资料：
【粘贴官网、文档、评测或访谈摘要】
```

验收标准：

- 团队能据此讨论是否做、先做什么、不做什么。
- 没有把营销文案当作事实。
- 安全、权限和成本没有被忽略。

复盘：

把最后决策记录回产品文档：哪些依据来自事实，哪些只是团队判断，哪些需要上线后验证。

## 案例 2：把用户反馈整理成需求评审材料

场景：

产品经理收集了客服记录、访谈摘要和工单，希望整理成一次需求评审材料。

失败 prompt：

```text
根据这些反馈帮我写需求文档。
```

为什么失败：

AI 可能直接把用户抱怨写成功能方案，跳过问题归类、影响范围和优先级判断。

改进 prompt：

```text
请把下面的用户反馈整理成需求评审材料。

要求：
1. 先按问题类型聚类，不要直接写方案。
2. 每一类问题列出代表性原话或来源编号。
3. 区分用户目标、当前阻碍、影响范围、可能方案。
4. 给出优先级建议，但必须说明依据。
5. 列出需要数据或研发确认的点。

输出结构：
- 问题聚类表
- 用户影响
- 可能方案
- 优先级建议
- 风险和待确认问题

资料：
【粘贴客服记录、访谈摘要、工单】
```

验收标准：

- 需求来自真实反馈，而不是 AI 自己扩写。
- 问题和方案分开。
- 优先级依据明确，可在评审会上被挑战。

复盘：

评审后把被否决的方案和原因补充到材料中，形成“为什么不做”的记录，避免下次重复讨论。
