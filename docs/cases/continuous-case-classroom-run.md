# 连续案例课堂试跑版

本页面向教师、培训者、读书会主持人和企业内训负责人。它把 [连续案例练习与复盘评分表](continuous-case-exercises.md) 改成一节可以直接试跑的课堂活动，适合第 3-4 周课程、读书会专题课或团队内训中的案例工作坊。

这不是讲概念的课，而是让学员把一个长案例拆成可执行的 AI 工作系统：普通 prompt、RAG、skill、agent、memory 和治理边界。

## 适用场景

| 场景 | 建议时长 | 适合人数 | 产出 |
| --- | --- | --- | --- |
| 读书会专题 | 90 分钟 | 6-18 人 | 每组一份连续案例复盘卡 |
| 标准培训课 | 120 分钟 | 12-30 人 | 每组一份工作流设计稿和评分表 |
| 企业内训 | 半天 | 10-40 人 | 1-3 个可进入试点的候选场景 |
| 教师备课演练 | 60 分钟 | 2-8 人 | 讲师版课堂脚本和点评标准 |

## 课前准备

讲师准备：

1. 选择 1-3 条连续案例：
   - [客户反馈知识库到可治理行动助手](rag-skill-agent-memory.md)
   - [教学资料库到受控助教助手](teaching-rag-skill-agent-memory.md)
   - [代码库问答到受控修复助手](codebase-rag-skill-agent-memory.md)
2. 准备一页案例摘要，每条只保留场景、失败 prompt、升级路径和风险边界。
3. 打印或复制 [连续案例练习与复盘评分表](continuous-case-exercises.md) 中对应案例的评分表。
4. 准备 3 张空白模板：RAG 资料结构、skill/card、agent 工作说明。
5. 明确课堂禁区：不得上传真实客户数据、学员隐私、密钥、生产配置和未公开业务资料。

学员准备：

1. 课前阅读至少一条连续案例。
2. 标出案例中“AI 不能自动做”的动作。
3. 带一个真实但已脱敏的任务，或者使用讲师提供的统一任务。
4. 写下自己最想迁移的一条流程经验。

## 90 分钟课堂流程

| 时间 | 环节 | 讲师动作 | 学员产出 |
| --- | --- | --- | --- |
| 0-10 分钟 | 开场和边界 | 说明今天不追求完整系统，只练升级判断和边界 | 选择案例 |
| 10-20 分钟 | 快速复盘案例 | 用一条案例展示 prompt -> RAG -> skill -> agent -> memory | 标出升级理由 |
| 20-35 分钟 | 小组拆解 | 每组填写“普通 prompt 为什么不够” | 失败 prompt 和失败原因 |
| 35-50 分钟 | RAG 设计 | 提醒资料、权限、引用、更新频率和评估集 | RAG 资料表和 3 条评估样例 |
| 50-65 分钟 | Skill 设计 | 要求只沉淀可重复的流程 | skill/card 初稿 |
| 65-78 分钟 | Agent 和 memory | 追问允许工具、禁止动作、确认点、禁止保存 | agent 边界和 memory 清单 |
| 78-88 分钟 | 组间互评 | 每组用评分表评另一组 | 评分和 2 条修改建议 |
| 88-90 分钟 | 收尾 | 要求课后只改最关键的 2 个问题 | 下一步修改项 |

## 120 分钟强化流程

120 分钟版本可以把“展示”和“互评”做得更充分：

| 时间 | 环节 | 增强点 |
| --- | --- | --- |
| 0-15 分钟 | 案例导入 | 展示三条连续案例的横向比较 |
| 15-30 分钟 | 失败 prompt 复盘 | 每组先写一个失败版本，再说明为什么失败 |
| 30-50 分钟 | RAG 资料设计 | 增加资料权限分级和更新频率 |
| 50-70 分钟 | Skill/card 编写 | 增加触发场景、输入要求、失败复盘 |
| 70-90 分钟 | Agent 工作说明 | 增加工具权限表、禁止动作、人工确认点 |
| 90-105 分钟 | Memory 治理 | 增加可保存、禁止保存、复查和删除规则 |
| 105-118 分钟 | 展示与互评 | 每组 3 分钟展示，其他组只问证据和边界 |
| 118-120 分钟 | 课后任务 | 布置真实任务迁移和复盘记录 |

## 分组方式

按角色分组：

- 产品/运营/客服组：优先做客户反馈案例。
- 教师/培训者组：优先做教学资料库案例。
- 工程/技术负责人组：优先做代码库案例。
- 管理者/安全负责人组：横向比较三条案例的治理边界。

按能力分组：

- 基础组：只完成改进 prompt 和 RAG 资料结构。
- 进阶组：完成 RAG、skill 和评估样例。
- 技术组：完成 RAG、skill、agent、memory 和日志要求。

## 讲师追问清单

当小组输出太空泛时，讲师可以只追问这些问题：

- 这个结论引用哪条资料？
- 这一步为什么需要 RAG，而不是继续粘贴材料？
- 这个 skill 下次还能不能复用？
- Agent 写入的是草稿，还是正式结果？
- 哪个动作如果自动执行会造成真实损失？
- 哪些信息绝对不能进入 memory？
- 如果模型答错，谁能发现，靠什么证据发现？
- 这套流程第一周只能试哪一个最小版本？

## 三个课堂示范样例

以下样例是可公开教学用的虚构示范，不包含真实客户、学员或代码信息。

### 样例一：客户反馈

弱版本：

```text
请总结这周客户反馈，告诉我产品要做什么。
```

课堂可接受版本：

```text
请只根据编号 F-001 到 F-030 的匿名化反馈，生成内部反馈周报。
每个结论必须引用反馈编号。
输出区分 bug、功能请求、使用误解和需人工确认。
不得输出客户名称、联系人、合同金额或对外承诺。
最后列出资料不足和需要产品负责人确认的事项。
```

讲师点评：

- 已经限定资料来源。
- 已经要求引用证据。
- 已经写清隐私边界。
- 还需要补 RAG 字段表和评估样例。

### 样例二：教学反馈

弱版本：

```text
请点评这个学员作业，看看他能力怎么样。
```

课堂可接受版本：

```text
请根据第 3 周课程目标和匿名化作业 A-07，生成反馈草稿。
反馈只能评价作业文本，不评价学员人格、智力、态度或长期能力。
每条建议必须给出可直接修改的文本方向。
不得给正式分数，最后列出需要讲师确认的内容。
```

讲师点评：

- 已经把“评价人”改成“评价文本”。
- 已经保留讲师确认。
- 还需要补课程资料编号和评分量规。

### 样例三：代码修复

弱版本：

```text
登录接口有问题，帮我修一下。
```

课堂可接受版本：

```text
请先协助定位“错误密码返回 500，而不是 401”的问题。
允许读取 src/auth/、src/api/login*、tests/auth/ 和 docs/api-auth.md。
禁止读取 .env、secrets/、credentials/、production-config/ 和真实用户数据。
先输出调查计划和最小相关文件列表，不直接改文件。
验收标准：错误密码返回 401，错误码为 INVALID_CREDENTIALS，相关测试通过。
```

讲师点评：

- 已经写清现象、范围、禁止读取和验收标准。
- 已经要求先计划后修改。
- 还需要补测试命令和 diff 暂停条件。

## 评分方式

课堂评分不建议只看“写得完整”。更应看它是否能进入下一步：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 目标 | 看不出任务 | 有任务但不可验收 | 目标和验收标准清楚 |
| 证据 | 没有来源 | 有来源但不稳定 | 结论能回到编号、路径或资料 |
| RAG | 只是堆资料 | 有字段但无权限 | 字段、权限、引用和更新完整 |
| Skill | 只是 prompt | 有流程但边界弱 | 可复用，有边界和失败复盘 |
| Agent | 权限不清 | 有工具但确认点弱 | 工具、禁止动作、确认点完整 |
| Memory | 什么都保存 | 有禁止项但不完整 | 可保存、禁止保存和复查清楚 |
| 迁移 | 只复述案例 | 能迁移一部分 | 能形成自己的最小试点 |

总分 14 分。课堂上建议只要求 10 分以上，不追求一次满分。

## 课后作业

基础版：

```text
选择一条连续案例，把它迁移成自己的真实任务。
只提交：
1. 改进 prompt。
2. RAG 资料结构。
3. 3 条禁止事项。
```

标准版：

```text
选择一条连续案例，把它迁移成自己的真实任务。
提交：
1. 改进 prompt。
2. RAG 资料结构和 5 条评估样例。
3. Skill/card。
4. Agent 工作说明。
5. Memory 保存与禁止保存清单。
```

进阶版：

```text
用自己的任务试跑一次标准版材料。
记录：
1. AI 输出哪里不稳定。
2. 哪个检查点发现了问题。
3. 哪条规则应该写回 skill 或 memory。
4. 是否适合进入团队试点。
```
