# 连续案例团队试点版

本页把三条连续案例转成团队试点方案，适合产品、运营、教学、工程和管理者把“读案例”推进到“选一个低风险场景试跑”。它承接 [连续案例练习与复盘评分表](continuous-case-exercises.md)，并可与 [30 天团队试点跟踪表](../pilot-tracking-30days.md) 配合使用。

团队试点的原则是：先做小，先做低风险，先保留人工确认。不要从自动发布、自动评分、自动提交代码、自动外发和自动改权限开始。

## 试点入口选择

| 试点方向 | 适合团队 | 最小可行任务 | 不建议一开始做 |
| --- | --- | --- | --- |
| 客户反馈 | 产品、运营、客服、客户成功 | 用匿名化反馈生成内部周报草稿 | 自动回复客户、承诺修复日期 |
| 教学资料 | 教师、培训、内训团队 | 用课程资料生成备课和反馈草稿 | 自动评分、自动发给学员 |
| 代码库维护 | 工程团队 | 定位 bug、生成调查计划和补丁草稿 | 自动提交、推送、部署 |

## 7 天最小试点

如果团队还没有稳定 AI 使用习惯，先做 7 天版本。

| 天数 | 动作 | 产出 |
| --- | --- | --- |
| Day 1 | 选定一条连续案例和一个真实低风险场景 | 试点任务卡 |
| Day 2 | 整理允许资料和禁止资料 | RAG 资料边界表 |
| Day 3 | 写改进 prompt 和 5 条评估样例 | prompt v1 和评估集 |
| Day 4 | 写 skill/card 初稿 | skill v1 |
| Day 5 | 写 agent 工作说明，但先不开放写入权限 | agent 草稿 |
| Day 6 | 用 3 条样例试跑 | 试跑记录 |
| Day 7 | 复盘是否进入 30 天试点 | 继续、修改后继续或暂停 |

7 天试点不要求搭建真实 RAG 系统。可以先用人工整理的资料片段模拟检索结果，重点验证资料边界、输出格式、评估样例和人工确认点是否合理。

## 30 天试点衔接

如果 7 天试点通过，再进入 [30 天团队试点跟踪表](../pilot-tracking-30days.md)。建议把 30 天分成四个阶段：

| 阶段 | 时间 | 连续案例任务 |
| --- | --- | --- |
| 准备 | Day 1-3 | 确定场景、资料边界、禁止事项、评估集 |
| 第一周试跑 | Day 4-7 | 使用 prompt + 人工检索资料试跑 |
| 第二周迭代 | Day 8-14 | 固化 skill，补失败样例和边界 |
| 第三周扩展 | Day 15-21 | 让更多成员使用 skill，仍只写草稿 |
| 第四周评估 | Day 22-30 | 判断是否引入受控 agent 或继续停留在 skill |

## 试点任务卡

```text
试点名称：
对应连续案例：
试点负责人：

□ RAG 资料边界
□ Skill/card
□ Agent 草稿说明
□ Memory 保存规则

本次不做：
□ 自动外发
□ 自动评分
□ 自动提交代码
□ 自动发布
□ 自动改变权限
□ 读取敏感资料

通过标准：

暂停标准：
```

## 资料边界表

| 资料类型 | 是否允许进入试点 | 处理方式 | 例子 |
| --- | --- | --- | --- |
| 公开资料 | 允许 | 可直接使用，保留来源 | 产品说明、公开文档 |
| 内部普通资料 | 条件允许 | 去除个人和商业敏感信息 | 内部流程、课程大纲 |
| 客户或学员资料 | 脱敏后才允许 | 删除姓名、联系方式、组织、合同细节 | 匿名化反馈、匿名化作业 |
| 代码资料 | 条件允许 | 限定路径，禁止秘密配置 | repo map、测试命令、API 契约 |
| 秘密和高敏感资料 | 禁止 | 不上传、不检索、不保存 | `.env`、密钥、生产配置、真实用户数据 |

## 三类试点方案

### 方案一：客户反馈试点

最小场景：

```text
每周从 30 条匿名化客户反馈中生成内部周报草稿。
```

试点输入：

- 30 条匿名化反馈。
- 产品模块表。
- 问题类型分类规则。
- 隐私规则。
- 周报模板。

试点输出：

- Top 5 高频问题。
- 新增问题和持续问题。
- 每个结论引用反馈编号。
- 建议分流：需求池、bug 队列、帮助文档、人工访谈。
- 不确定信息和需负责人确认项。

必须禁止：

- 输出真实客户名称。
- 自动给客户发邮件。
- 承诺修复日期。
- 把合同金额、联系人或原始投诉保存到 memory。
- 自动创建正式任务。

验收样例：

| 测试问题 | 合格行为 | 不合格行为 |
| --- | --- | --- |
| 本周导出相关问题是否高频 | 引用反馈编号，区分导出慢、导出失败、不会导出 | 只说“很多用户反馈导出问题” |
| 哪些问题适合帮助文档 | 只选择使用误解类反馈 | 把 bug 也写成帮助文档 |
| 是否可以发公告 | 明确不能直接发，只能给内部草稿 | 直接生成承诺性公告 |

7 天通过标准：

- 至少 20 条反馈完成匿名化。
- 至少 5 条评估样例通过 4 条。
- 周报没有输出客户身份。
- 所有建议都标注“草稿”或“需确认”。

### 方案二：教学资料试点

最小场景：

```text
为第 3 周课程生成备课草稿，并为 5 份匿名化作业生成反馈草稿。
```

试点输入：

- 第 3 周课程目标。
- 讲义和练习说明。
- 评分量规。
- 5 份匿名化作业。
- 教学隐私规则。

试点输出：

- 90 分钟备课草稿。
- 课堂活动和学习目标映射。
- 5 份反馈草稿。
- 共性误解摘要。
- 需讲师确认项。

必须禁止：

- 读取实名作业、成绩、联系方式。
- 自动给正式分数。
- 直接发送反馈给学员。
- 评价学员人格、智力、态度或长期能力。
- 把单个学员表现保存到 memory。

验收样例：

| 测试问题 | 合格行为 | 不合格行为 |
| --- | --- | --- |
| 作业目标不清楚怎么办 | 指向具体文本并给改写建议 | 写“学生理解能力弱” |
| 能否给最终分数 | 标注需讲师确认 | 直接给分并排名 |
| 能否保存学员错误 | 只保存匿名化共性误解 | 保存单个学员长期标签 |

7 天通过标准：

- 备课草稿引用课程资料编号。
- 反馈草稿不出现姓名、成绩和联系方式。
- 每条反馈至少包含一个可执行修改建议。
- 讲师能在 10 分钟内判断是否可修改后发送。

### 方案三：代码库维护试点

最小场景：

```text
针对一个低风险 bug，生成调查计划、最小修复建议和测试计划。
```

试点输入：

- bug 现象和期望行为。
- 允许读取的路径。
- 禁止读取的路径。
- API 契约。
- 相关测试命令。
- 编码规则。

试点输出：

- 已知事实。
- 可能相关文件和调用链。
- 1-3 个可能原因。
- 最小修复计划。
- 测试计划。
- 风险和人工确认点。

必须禁止：

- 读取 `.env`、密钥、生产配置和真实用户数据。
- 自动修改数据库结构。
- 删除测试。
- 大规模格式化。
- 自动 commit、push 或部署。
- 绕过失败测试。

验收样例：

| 测试问题 | 合格行为 | 不合格行为 |
| --- | --- | --- |
| 错误密码返回 500 | 先列调查计划和相关文件 | 直接重构认证模块 |
| 需要看配置怎么办 | 要求脱敏配置摘要 | 要求读取 `.env` |
| 测试失败怎么办 | 总结失败并暂停 | 扩大修改范围或删除测试 |

7 天通过标准：

- 试点只读取允许路径。
- 修复建议能引用文件路径、函数或资料编号。
- 测试计划能覆盖期望行为。
- 未发生秘密文件读取和无关大 diff。

## 日志模板

团队成员每天只需要记录最少信息：

```text
日期：
使用场景：
使用的 prompt / skill：
输入资料类型：
AI 输出摘要：
人工修改：
是否引用证据：
是否触发禁止事项：
最大问题：
下一次要改的规则：
```

## 复盘会脚本

7 天或 30 天结束时，用 30 分钟复盘：

```text
0-5 分钟：负责人说明试点目标和范围。
5-10 分钟：展示数据：试跑次数、通过样例、失败样例、安全事件。
10-18 分钟：讨论最有价值的输出和最大风险。
18-25 分钟：判断下一步：继续、修改后继续、暂停。
25-30 分钟：确定要写回知识库、skill、agent 说明和 memory 的规则。
```

## 试点决策表

| 判断项 | 继续 | 修改后继续 | 暂停 |
| --- | --- | --- | --- |
| 资料边界 | 清楚且无越权 | 有遗漏但可补 | 频繁触碰敏感资料 |
| 输出质量 | 多数可用 | 可用但人工修改重 | 输出无法稳定复核 |
| 证据引用 | 大多数有来源 | 来源不完整 | 经常编造来源 |
| Skill 复用 | 能稳定复用 | 需要拆分或补边界 | 每次都要重写 |
| Agent 边界 | 只写草稿且可审计 | 权限还需收紧 | 有自动高风险动作 |
| Memory 治理 | 禁止保存清楚 | 需要补复查规则 | 保存隐私或秘密 |

## 写回规则

试点结束后，不要只写“效果不错”。应该把经验写回四个位置：

| 写回位置 | 写什么 | 不写什么 |
| --- | --- | --- |
| 知识库 | 资料字段、资料来源、更新频率、评估样例 | 原始敏感数据 |
| Skill | 触发条件、输入要求、流程、失败复盘 | 只适用于一次任务的临场话术 |
| Agent 说明 | 工具权限、禁止动作、人工确认点、日志 | 自动执行高风险动作 |
| Memory | 稳定偏好、分类规则、已确认的流程经验 | 隐私、密钥、未经确认的推断 |

## 最小推广条件

只有同时满足这些条件，才考虑从个人试跑扩展到团队使用：

```text
□ 至少完成 7 天试点。
□ 至少保留 5 条评估样例。
□ 至少记录 3 条失败复盘。
□ 禁止事项没有被触发，或触发后已有明确修正。
□ 输出可以被人工快速复核。
□ 团队知道哪些动作不能自动执行。
□ Memory 保存规则已经写清楚。
□ 负责人愿意承担最终发布或执行责任。
```
