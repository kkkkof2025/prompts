# 运营案例

## 案例 1：把会议记录整理成可执行纪要

场景：

运营同事每周有多场会议，需要从录音转写和聊天记录中整理决定、待办和争议。

失败 prompt：

```text
帮我总结会议。
```

为什么失败：

这通常只会得到一段摘要，不能直接进入任务管理工具，也容易把争议误写成结论。

改进 prompt：

```text
请整理下面的会议记录。

要求：
1. 只依据我提供的记录，不要补充没有出现的信息。
2. 区分会议摘要、关键决定、待办事项、争议、待确认问题。
3. 待办事项必须包含事项、负责人、截止时间、依赖；缺失则写“待确认”。
4. 最后列出你无法确认但会影响执行的内容。

会议记录：
【粘贴会议转写或聊天记录】
```

验收标准：

- 待办能直接复制到任务管理工具。
- 没有编造负责人和日期。
- 争议和未决问题没有被误写成结论。

复盘：

如果纪要需要对外发送，再追加一次“请改写为对外邮件，但保留待确认标记”的任务，不要让 AI 在同一步里既分析又润色。

## 案例 2：把零散素材变成一周内容排期

场景：

运营需要根据产品更新、用户反馈和热点素材，安排一周公众号、社群和短视频内容。

失败 prompt：

```text
帮我做一个内容日历。
```

为什么失败：

AI 可能生成主题很好看但和产品节奏、渠道差异、素材质量不匹配的排期。

改进 prompt：

```text
请基于我提供的素材，生成一周内容排期。

业务目标：
- 提高新功能试用率。
- 降低用户对功能入口的困惑。

渠道：
- 公众号：每周 2 篇，适合解释和案例。
- 社群：每天 1 条，适合提醒和互动。
- 短视频：每周 3 条，适合演示。

要求：
1. 每条内容都标注对应素材来源。
2. 区分教育型、转化型、互动型内容。
3. 不要编造产品能力。
4. 列出缺少素材时需要向产品或客服确认的问题。

素材：
【粘贴产品更新、用户问题、客服反馈、历史内容数据】
```

验收标准：

- 每条内容都能追溯到已有素材。
- 渠道形式和内容目标匹配。
- 缺失信息被列为确认问题，而不是被自动补齐。

复盘：

发布后把点击率、评论、转化和用户反馈喂回 AI，让它只分析“哪些假设错了”，再决定下周怎么改。

## 案例 3：跨渠道活动执行检查，而不是只让 AI 写推广文案

场景：

运营团队要在两周内上线一次新功能推广活动，涉及公众号、社群、短视频、站内弹窗、客服话术和数据看板。最常见的问题不是文案不会写，而是不同渠道节奏不一致、素材版本混乱、负责人不清、上线后没人看数据。

失败 prompt：

```text
帮我写一个新功能推广方案，越完整越好。
```

为什么失败：

AI 可能输出一份看起来很完整的活动方案，但没有把执行链路拆成可检查任务。运营真正需要的是“哪些渠道做什么、谁负责、依赖什么素材、什么时候发布、发布后看什么指标、失败时怎么调整”。

改进 prompt：

```text
请把这次新功能推广活动整理成跨渠道执行检查表，不要只写创意方案。

活动背景：
- 新功能：【填写】
- 活动周期：【填写】
- 目标用户：【填写】
- 主要目标：提高试用率 / 降低入口困惑 / 收集反馈

可用渠道：
- 公众号
- 社群
- 短视频
- 站内弹窗
- 客服话术
- 帮助文档

已有素材：
【粘贴产品说明、截图、历史内容、客服问题、限制说明】

请输出：

1. 渠道执行表
   - 渠道
   - 内容目标
   - 素材来源
   - 负责人
   - 发布时间
   - 发布前检查项
   - 发布后指标

2. 素材缺口
   - 缺什么素材。
   - 应该找谁确认。
   - 缺口不补会影响哪个渠道。

3. 风险清单
   - 容易夸大产品能力的地方。
   - 容易引发用户误解的地方。
   - 需要产品、客服或法务确认的内容。

4. 每日复盘节奏
   - 每天看哪些数据。
   - 发现异常时先调整哪个渠道。
   - 哪些问题需要升级给产品或研发。

要求：
- 不编造产品能力。
- 不把未确认事项写成确定结论。
- 对每个渠道给不同写法，不要复制同一段文案。
```

验收标准：

- 每个渠道都有目标、负责人、素材来源和指标。
- 素材缺口能转成待办，不会被 AI 自动补齐。
- 风险清单能阻止夸大宣传和错误承诺。
- 发布后复盘能判断“哪里需要调整”，而不是只看总曝光。

复盘：

活动结束后，把实际数据按渠道回填到同一张表里：公众号是否带来试用，社群是否减少困惑，短视频是否让用户看懂入口，客服话术是否降低重复问题。下一次再让 AI 分析时，输入应是“假设、执行、数据、反馈”，而不是只输入最终结果。

这个案例适合和 [团队 AI 落地案例集](../team-adoption-cases.md) 一起读：运营活动不是单点文案生成，而是一个有任务源、素材源、渠道差异和复盘节奏的轻量工作流。
