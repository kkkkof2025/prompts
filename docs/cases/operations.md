# 运营案例

## 案例 1：把会议记录整理成可执行纪要

场景：

运营同事每周有多场会议，需要从录音转写和聊天记录中整理决定、待办和争议。

失败 prompt：

```text
帮我总结会议。
```

为什么失败：

这通常只会得到一段摘要，不能直接进入任务管理工具，也容易把争议误写成结论。

改进 prompt：

```text
请整理下面的会议记录。

要求：
1. 只依据我提供的记录，不要补充没有出现的信息。
2. 区分会议摘要、关键决定、待办事项、争议、待确认问题。
3. 待办事项必须包含事项、负责人、截止时间、依赖；缺失则写“待确认”。
4. 最后列出你无法确认但会影响执行的内容。

会议记录：
【粘贴会议转写或聊天记录】
```

验收标准：

- 待办能直接复制到任务管理工具。
- 没有编造负责人和日期。
- 争议和未决问题没有被误写成结论。

复盘：

如果纪要需要对外发送，再追加一次“请改写为对外邮件，但保留待确认标记”的任务，不要让 AI 在同一步里既分析又润色。

## 案例 2：把零散素材变成一周内容排期

场景：

运营需要根据产品更新、用户反馈和热点素材，安排一周公众号、社群和短视频内容。

失败 prompt：

```text
帮我做一个内容日历。
```

为什么失败：

AI 可能生成主题很好看但和产品节奏、渠道差异、素材质量不匹配的排期。

改进 prompt：

```text
请基于我提供的素材，生成一周内容排期。

业务目标：
- 提高新功能试用率。
- 降低用户对功能入口的困惑。

渠道：
- 公众号：每周 2 篇，适合解释和案例。
- 社群：每天 1 条，适合提醒和互动。
- 短视频：每周 3 条，适合演示。

要求：
1. 每条内容都标注对应素材来源。
2. 区分教育型、转化型、互动型内容。
3. 不要编造产品能力。
4. 列出缺少素材时需要向产品或客服确认的问题。

素材：
【粘贴产品更新、用户问题、客服反馈、历史内容数据】
```

验收标准：

- 每条内容都能追溯到已有素材。
- 渠道形式和内容目标匹配。
- 缺失信息被列为确认问题，而不是被自动补齐。

复盘：

发布后把点击率、评论、转化和用户反馈喂回 AI，让它只分析“哪些假设错了”，再决定下周怎么改。
