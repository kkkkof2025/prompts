# 连续案例课堂投影短版

本页是 [连续案例课堂试跑版](continuous-case-classroom-run.md) 的投影短版，适合讲师在 60-120 分钟课堂、读书会或团队内训中直接打开使用。它不是完整讲义，而是课堂节奏提示：每一页只保留一个判断、一个互动问题和一个讲师提醒。

建议使用方式：

- 60 分钟：只讲第 1-8 页，现场完成一张案例复盘卡。
- 90 分钟：讲完第 1-12 页，增加小组互评。
- 120 分钟：讲完后接 [连续案例样例库](continuous-case-samples.md)，让学员给样例打分。

## 投影页 1：今天不是学概念

投屏内容：

```text
今天的目标：
把一个长案例拆成可执行的 AI 工作系统。

主线：
普通 prompt -> RAG -> skill -> agent -> memory

最终产出：
一份可复盘、可评分、可进入试点的案例设计稿。
```

讲师提示：

不要从模型、工具或产品名字开场。直接强调“能不能进入真实流程”，让学员知道今天要交付的是设计稿，不是听概念。

互动问题：

```text
你现在最常让 AI 做的任务，失败时通常错在哪里？
```

## 投影页 2：三条连续案例

投屏内容：

| 案例 | 任务 | 最大风险 |
| --- | --- | --- |
| 客户反馈 | 从匿名化反馈生成内部周报草稿 | 泄露客户身份、对外承诺 |
| 教学资料 | 生成备课和反馈草稿 | 学员隐私、越权评分 |
| 代码库 | 定位 bug 和生成修复草稿 | 读取秘密、盲改代码 |

讲师提示：

让学员按角色选案例。产品、运营、客服优先选客户反馈；教师、培训者选教学资料；工程团队选代码库；管理者可以横向比较三条。

互动问题：

```text
哪条案例最像你的真实工作？为什么？
```

## 投影页 3：普通 Prompt 为什么不够

投屏内容：

```text
弱 prompt 的共同问题：
1. 没有资料边界。
2. 没有证据引用。
3. 没有禁止事项。
4. 没有人工确认点。
5. 没有失败后写回流程。
```

讲师提示：

这页要让学员承认“不是 prompt 写得不够漂亮，而是任务系统没设计”。prompt 只是入口，不是整个 AI 工作系统。

互动问题：

```text
如果只问“帮我总结 / 帮我点评 / 帮我修一下”，最坏会发生什么？
```

## 投影页 4：升级判断

投屏内容：

| 如果问题是 | 升级到 | 解决什么 |
| --- | --- | --- |
| 每次任务都要重写说明 | Prompt 模板 | 稳定输入输出 |
| 资料多、需要引用 | RAG | 回到来源 |
| 流程反复出现 | Skill | 固化经验 |
| 需要调用工具和写草稿 | Agent | 受控行动 |
| 需要跨次保留偏好 | Memory | 保存稳定经验 |

讲师提示：

强调“能不用 agent 就不用 agent”。升级不是为了显得高级，而是为了处理明确的新问题。

互动问题：

```text
你的任务现在卡在资料、流程、行动，还是长期偏好？
```

## 投影页 5：RAG 不是文件堆

投屏内容：

```text
RAG 资料表至少写清：
- 资料编号
- 来源
- 适用范围
- 是否可给 AI
- 隐私等级
- 更新频率
- 引用方式
- 禁止行为
```

讲师提示：

让学员把“知识库”从文件夹想象改成“可引用、可更新、可控制权限的资料系统”。

互动问题：

```text
你的资料里，哪三类永远不能进入 RAG？
```

## 投影页 6：Skill 不是更长的 Prompt

投屏内容：

```text
Skill 必须回答：
1. 什么时候触发？
2. 输入必须有什么？
3. 步骤怎么走？
4. 输出长什么样？
5. 边界是什么？
6. 失败经验怎么写回？
```

讲师提示：

如果学员只写了一段“请你扮演某角色”，就还不是 skill。skill 的价值是复用和维护。

互动问题：

```text
这个任务下周还会重复吗？如果会，哪些部分值得固化？
```

## 投影页 7：Agent 先写草稿

投屏内容：

```text
Agent 权限分层：
1. 只读资料
2. 写草稿
3. 执行内部低风险动作
4. 对外发布 / 提交 / 发送

课堂默认只允许到第 2 层。
```

讲师提示：

把“写草稿”和“正式执行”分开讲。大多数课堂设计不应该直接给 agent 正式执行权限。

互动问题：

```text
这个动作如果自动执行，谁承担责任？
```

## 投影页 8：Memory 只存稳定经验

投屏内容：

| 可以保存 | 禁止保存 |
| --- | --- |
| 报告格式偏好 | 客户名称 |
| 分类规则 | 学员成绩 |
| 测试命令 | API key |
| 已确认失败模式 | 生产配置 |
| 讲师反馈风格 | 原始投诉 |

讲师提示：

让学员区分知识库和 memory：业务资料进知识库，长期偏好和流程经验才进 memory。

互动问题：

```text
你最想保存的一条偏好是什么？最不该保存的信息是什么？
```

## 投影页 9：三类常见失败

投屏内容：

| 失败 | 表现 | 修正 |
| --- | --- | --- |
| 把推断写成事实 | “用户普遍认为” | 必须引用编号 |
| 把反馈写成人身评价 | “你逻辑能力弱” | 只评价作业文本 |
| 把现象当原因 | “登录页有问题” | 先查调用链 |

讲师提示：

这页用于快速纠偏。不要只让学员写完整，更要让他们知道哪些写法会导致真实损失。

互动问题：

```text
你的小组设计里，最可能出现哪一种失败？
```

## 投影页 10：小组交付物

投屏内容：

```text
每组提交：
1. 失败 prompt 和失败原因
2. 改进 prompt
3. RAG 资料结构
4. 5 条评估样例
5. Skill/card
6. Agent 工作说明
7. Memory 保存和禁止保存清单
8. 下一步试点判断
```

讲师提示：

如果时间不够，基础组只交 1-4，进阶组交 1-8。不要让学员为了完整而写空话。

互动问题：

```text
哪一项现在最缺？是资料、评估、权限，还是 memory 边界？
```

## 投影页 11：互评只问四件事

投屏内容：

```text
互评问题：
1. 证据在哪里？
2. 禁止事项写清了吗？
3. 哪些动作必须人工确认？
4. 失败经验写回哪里？
```

讲师提示：

不要让互评变成“写得很好”“还可以更完整”。每个反馈都必须指向证据、边界、确认点或写回规则。

互动问题：

```text
你给对方小组的 1 条最高优先级修改建议是什么？
```

## 投影页 12：收尾判断

投屏内容：

| 判断 | 条件 |
| --- | --- |
| 继续 | 资料边界清楚，输出能人工复核 |
| 修改后继续 | 有价值，但权限或评估样例不足 |
| 暂停 | 触碰敏感资料，或自动执行高风险动作 |

讲师提示：

让每组只选一个判断，不允许含糊。课堂结束时，学员应该知道自己的设计是“可试点”“需修改”还是“暂缓”。

互动问题：

```text
你的方案下周能不能进入 7 天试点？如果不能，先补哪一项？
```

## 讲师速查

### 时间压缩版

| 时长 | 使用页 | 课堂目标 |
| --- | --- | --- |
| 30 分钟 | 1、2、3、7、12 | 只讲边界意识 |
| 60 分钟 | 1-8、12 | 完成最小案例复盘卡 |
| 90 分钟 | 1-12 | 完成小组设计和互评 |
| 120 分钟 | 1-12 + 样例库 | 完成设计、互评和样例评分 |

### 讲师开场词

```text
今天我们不比较模型，也不讨论哪个工具最强。
我们只做一件事：
把一个真实 AI 使用场景拆成能复查、能评分、能试点的工作系统。

如果你的方案最后不能说明资料从哪里来、AI 不能做什么、谁来确认、失败后写回哪里，
那它还不能进入真实流程。
```

### 讲师收尾词

```text
今天做完的不是最终系统，而是试点前的设计稿。
下一步不要马上扩大使用范围。
先用 3-5 条样例试跑，记录失败，把规则写回 RAG、skill、agent 说明和 memory。
```

## 质量层级对照

| 层级 | 表现 | 处理 |
| --- | --- | --- |
| 刚开始 | 只有一个改进 prompt | 先补资料边界和验收样例 |
| 基本合格 | 有 RAG、skill、agent、memory，但边界粗 | 进入互评，补禁止事项 |
| 可试点 | 有评估样例、人工确认点和写回规则 | 可做 7 天试点 |
| 可示范 | 有试跑数据、失败复盘和版本记录 | 可进入样例库 |
