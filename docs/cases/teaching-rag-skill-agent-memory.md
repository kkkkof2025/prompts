# 案例：从教学资料库到受控助教助手

这个案例面向教师、培训者、读书会主持人和企业内训负责人。它和 [客户反馈连续案例](rag-skill-agent-memory.md) 使用同一条技术主线，但场景换成教学：怎样把分散的课程资料，从普通 prompt 逐步升级为 RAG、教学 skill、受控助教 agent 和 memory 边界。

教学场景的风险不只在“答案错了”。更常见的问题是：学员隐私泄露、作业反馈越权、课程目标漂移、评分标准不一致、AI 编造教材依据，以及助教 agent 在没有人工确认时给出过度承诺。

## 场景

一个培训团队正在开设 4 周 AI 入门课。每周都有：

- 课程大纲。
- 讲义和课堂示例。
- 学员匿名作业。
- 课堂练习工作纸。
- 复盘题和小测。
- 讲师课后记录。
- 学员反馈。

团队希望 AI 帮忙做四件事：

- 备课前，根据教学目标整理本周重点。
- 课中，根据学员问题快速找到讲义和示例。
- 课后，对匿名作业给出结构化反馈草稿。
- 复盘时，总结哪些概念需要下次提前解释。

这个需求看起来像“帮我备课”，但真正要解决的是资料来源、反馈边界、评分一致性和学员隐私。

## 第 0 轮：普通 prompt 的失败

讲师一开始这样问：

```text
请帮我准备一节关于 RAG 和 agent 的课，适合零基础学员。
```

AI 可能给出一份看似完整的课程计划：

```text
课程目标：
1. 理解 RAG 的基本原理。
2. 掌握 agent 的工作方式。
3. 能设计一个智能问答系统。

课堂安排：
1. 介绍概念。
2. 展示案例。
3. 学员练习。
4. 总结回顾。
```

问题是：

- 不知道这节课属于第几周。
- 不知道学员已经学过哪些内容。
- 没有引用本书或课程材料。
- 把 RAG、agent 和智能问答系统混在一起讲，跨度过大。
- 没有适配课堂练习工作纸。
- 没有说明哪些学员数据不能上传。

普通 prompt 可以给灵感，但不能保证课程连续性、材料一致性和隐私边界。

## 第 1 轮：先把教学 prompt 写稳

在接入知识库之前，先把本次任务说明写清楚。

```text
任务：
请为第 3 周课程“知识库、RAG 和 skill”生成一份 90 分钟备课草稿。

已知背景：
- 学员已经完成第 1 周 prompt 练习和第 2 周工作流练习。
- 本周目标是让学员理解资料、知识库、RAG 和 skill 的关系。
- 课堂产出是一张 skill/card 初稿。

可用材料：
- 第 6 章：工具调用、RAG 与知识库。
- 第 7 章：Skills，把经验固化成能力。
- 课堂练习工作纸。
- 教学版本材料包。

输出结构：
1. 本节课学习目标。
2. 90 分钟流程。
3. 讲师讲解重点。
4. 失败案例和改进案例。
5. 课堂练习说明。
6. 同伴互评问题。
7. 课后作业。

边界：
- 不引入课程外没有解释的新术语。
- 不使用真实学员姓名、作业或成绩。
- 不生成正式评分，只生成反馈草稿。
- 不承诺某种工具或模型一定可用。

验收标准：
- 每个活动都能对应一个学习目标。
- 练习任务必须可在课堂上完成。
- 输出必须标注哪些材料来自课程已有内容。
```

这个 prompt 已经可用，但讲师每周都要手动粘贴课程资料。课程越来越长后，问题会出现：

- 讲义、工作纸、作业样例分散在多个文件里。
- AI 可能忘记上一周已经讲过什么。
- 作业反馈需要引用统一评分量规。
- 新讲师接手时难以复用原有经验。

这时可以进入 RAG。

## 第 2 轮：建立教学资料 RAG

教学 RAG 的目标不是让 AI 替老师上课，而是让备课和反馈能回到课程资料。

### 资料结构

```text
teaching-knowledge/
├── syllabus/
│   ├── week-1-dialogue-prompt.md
│   ├── week-2-workflow-evaluation.md
│   ├── week-3-rag-skill.md
│   └── week-4-agent-memory-governance.md
├── worksheets/
│   ├── prompt-worksheet.md
│   ├── workflow-worksheet.md
│   └── skill-card-worksheet.md
├── rubrics/
│   ├── prompt-rubric.md
│   ├── workflow-rubric.md
│   └── skill-agent-rubric.md
├── examples/
│   ├── anonymized-good-work.md
│   └── anonymized-common-mistakes.md
└── privacy-rules.md
```

每份资料需要保留：

```text
资料编号：
适用周次：
适用对象：
资料类型：
是否可给学员：
是否可给 AI：
是否含学员信息：
维护日期：
来源页面：
```

### 检索策略

| 检索维度 | 用途 | 示例 |
| --- | --- | --- |
| 周次 | 避免讲超前内容 | 第 3 周只用第 1-3 周概念 |
| 资料类型 | 区分讲义、练习、评分量规 | worksheet、rubric、example |
| 学员水平 | 区分零基础、进阶、技术背景 | basic、advanced、technical |
| 隐私等级 | 避免使用未匿名化作业 | public、class-only、private |
| 学习目标 | 保持课程活动不跑题 | prompt、workflow、RAG、skill |

### RAG 版备课 prompt

```text
你是课程助教，只能依据检索到的 teaching-knowledge 内容协助备课。

任务：
为第 3 周课程生成 90 分钟备课草稿。

必须遵守：
1. 每个讲解重点必须引用资料编号。
2. 不使用未匿名化学员作业。
3. 不引入第 4 周才讲的 agent 和 memory 细节。
4. 对不确定资料写“需讲师确认”。
5. 输出只作为讲师草稿，不直接发给学员。

输出：
- 学习目标
- 课堂流程
- 讲解重点
- 示例材料
- 练习说明
- 同伴互评问题
- 需讲师确认
- 使用的资料编号
```

### RAG 评估集

| 测试问题 | 期望行为 | 不合格表现 |
| --- | --- | --- |
| 第 3 周能不能讲 agent 自动执行 | 标注为第 4 周内容，只做预告 | 提前展开 agent 权限和工具调用 |
| 能否用真实作业做示例 | 只使用匿名化作业 | 输出学员姓名或原始内容 |
| 课堂练习是否要评分 | 生成反馈草稿，不给正式成绩 | 直接给出最终分数 |
| 讲义依据来自哪里 | 引用资料编号或课程页面 | 编造“教材第几页” |

RAG 让备课和反馈有了材料来源，但还不能保证每次反馈都按同一套结构写。这时需要 skill。

## 第 3 轮：沉淀教学反馈 skill

教学反馈是高频任务，适合沉淀成 skill。它的目标不是替老师下最终判断，而是生成可复核的反馈草稿。

```text
名称：
teaching-feedback-draft

用途：
根据匿名化学员作业、课程目标和评分量规，生成教学反馈草稿。

触发场景：
- 讲师需要点评 prompt、工作流、skill/card 或 agent 工作说明。
- 读书会主持人需要给学员提供修改建议。
- 培训团队需要整理常见错误。

输入要求：
- 匿名化作业。
- 对应课程周次。
- 对应评分量规。
- 学员水平，如果已知。
- 输出语气要求。

流程：
1. 检查作业是否匿名化。
2. 检索对应周次学习目标和评分量规。
3. 按维度判断亮点、主要问题和修改建议。
4. 把反馈分成“可直接修改”和“需要讲师判断”。
5. 不给正式成绩，除非讲师明确要求且提供评分规则。
6. 输出反馈草稿和不确定点。

输出格式：
- 作业摘要
- 对应学习目标
- 亮点
- 主要问题
- 修改建议
- 可替换改写示例
- 需讲师确认
- 不应保存的信息

边界：
- 不输出学员真实姓名。
- 不基于性格、能力或态度做判断。
- 不给医疗、法律、心理咨询等越界建议。
- 不把一次作业失败写成长期能力标签。
- 不保存未授权学员信息。

验收标准：
- 反馈必须对应课程目标或评分量规。
- 修改建议必须具体到可执行动作。
- 不确定信息单独列出。
- 不出现隐私信息和羞辱性评价。
```

### 失败复盘

一次试跑中，AI 对一个 prompt 作业写了这样的反馈：

```text
你对 AI 的理解还比较浅，需要加强逻辑能力。
```

这条反馈不合格，因为它评价了学员能力，却没有指向具体作业问题。

改写后：

```text
这份 prompt 的目标已经写出，但验收标准还不够可检查。
建议把“输出要详细”改为“输出包含 3 个可执行步骤、每步不超过 80 字，并列出需要人工核验的事实点”。
```

修正 skill：

- 禁止评价人格、智力、态度和长期能力。
- 反馈必须指向具体文本。
- 每条建议必须能被学员直接修改。

## 第 4 轮：升级为受控助教 agent

助教 agent 不是替老师授课，而是在边界内处理低风险重复任务。

### 目标

```text
每周课前读取课程资料，生成备课草稿；
课后读取匿名化作业，调用 teaching-feedback-draft skill 生成反馈草稿；
整理本周常见错误，供讲师下周开场复盘使用。
```

### 允许工具

| 工具 | 权限 | 说明 |
| --- | --- | --- |
| 读取课程资料 | 只读 | 只能读 teaching-knowledge 中允许给 AI 的资料 |
| 检索评分量规 | 只读 | 返回对应周次和作业类型 |
| 读取匿名化作业 | 只读 | 不能读取原始实名作业 |
| 写反馈草稿 | 写草稿 | 保存到讲师审阅区 |
| 写复盘摘要 | 写草稿 | 不直接发给学员 |

### 禁止动作

- 禁止读取实名学员名单。
- 禁止读取联系方式、成绩单和未授权作业。
- 禁止直接给最终分数。
- 禁止直接向学员发送反馈。
- 禁止发布课程公告。
- 禁止把学员一次失误保存为长期标签。
- 禁止对学员做心理、能力或态度判断。

### Agent 工作说明

```text
目标：
为第 3 周课程生成备课草稿，并为匿名化作业生成反馈草稿。

可使用工具：
- search_teaching_materials：检索课程资料。
- read_rubric：读取评分量规。
- read_anonymized_assignments：读取匿名化作业。
- write_feedback_draft：写反馈草稿。
- write_review_summary：写讲师复盘摘要。

流程：
1. 先说明计划和要读取的资料类型。
2. 检索第 3 周课程目标、讲义和练习。
3. 生成备课草稿，标注资料编号。
4. 检查匿名化作业是否符合输入要求。
5. 调用 teaching-feedback-draft skill 生成反馈草稿。
6. 汇总本周常见错误。
7. 输出执行日志、未处理项和需讲师确认的问题。

人工确认点：
- 任何反馈发给学员前必须讲师确认。
- 任何评分必须讲师确认。
- 任何课程公告必须讲师确认。
- 涉及学员隐私、心理状态、投诉和纪律问题时必须人工处理。
```

### 助教 agent 的验收

| 检查项 | 合格标准 |
| --- | --- |
| 来源 | 备课草稿引用课程资料编号 |
| 隐私 | 不读取、不输出实名学员信息 |
| 反馈 | 指向具体作业文本，不评价人格 |
| 权限 | 只写草稿，不直接发送 |
| 日志 | 记录读取资料、生成草稿和需确认项 |

## 第 5 轮：加入 memory，但避免给学员贴标签

教学 memory 的重点是保存课程流程和讲师偏好，不是保存学员隐私。

适合保存：

- 讲师偏好的反馈语气。
- 课程每周固定结构。
- 常见概念误解。
- 匿名化后的教学改进经验。
- 已确认的评分量规调整。

不适合保存：

- 学员姓名。
- 联系方式。
- 成绩。
- 原始作业。
- 情绪状态。
- 对学员能力的长期判断。
- 未经同意的课堂发言记录。

### 记忆文件示例

```text
# teaching-assistant-memory.md

## 讲师偏好
- 反馈要具体、克制，避免空泛鼓励。
- 每条反馈至少给一个可直接替换的改写例子。
- 课堂复盘优先讲共性问题，不点名单个学员。

## 课程结构
- 第 1 周：prompt 五要素。
- 第 2 周：工作流和评估。
- 第 3 周：RAG 和 skill。
- 第 4 周：agent、memory 和治理。

## 常见误解
- 学员容易把“输出详细”当作验收标准。
- 学员容易提前要求 agent 自动执行高风险动作。
- 学员容易把知识库当成文件堆，而不是有来源、权限和更新流程的资料系统。

## 禁止保存
- 学员姓名、联系方式、成绩。
- 原始作业和课堂发言。
- 对学员能力、性格或态度的长期判断。
```

### 记忆更新 prompt

```text
请从本周课程复盘中提取可以长期保存的教学经验。

只允许保存：
- 课程结构改进。
- 讲师反馈偏好。
- 匿名化共性误解。
- 已确认的评分量规调整。

禁止保存：
- 学员姓名、联系方式、成绩。
- 原始作业内容。
- 单个学员的课堂表现。
- 对学员能力、性格、态度的判断。

输出：
- 建议新增记忆
- 建议更新记忆
- 不应保存的信息
- 需要讲师确认的信息
```

## 最终工作流

```text
课程资料 -> 权限和匿名化检查 -> RAG 检索 -> 教学反馈 skill -> 助教 agent 草稿动作 -> 讲师确认 -> 课堂复盘 -> 更新资料库和 memory
```

每一层的价值和风险：

| 层级 | 解决的问题 | 新增风险 | 控制方法 |
| --- | --- | --- | --- |
| Prompt | 把备课需求说清楚 | 课程目标漂移 | 限定周次、目标和输出结构 |
| RAG | 回到课程资料 | 引用错误、越级讲解 | 资料编号、周次范围、评估集 |
| Skill | 统一反馈流程 | 反馈模板化或评价越界 | 禁止人格判断，保留讲师确认 |
| Agent | 批量生成草稿 | 误读作业、直接发送 | 只读匿名作业，只写草稿 |
| Memory | 保存教学经验 | 给学员贴标签 | 只保存课程经验，不保存个人信息 |

## 可复用模板

把这个案例迁移到自己的课程时，先回答：

```text
1. 哪些课程资料允许 AI 读取？
2. 哪些学员资料必须匿名化或禁止上传？
3. 备课输出要引用哪些课程来源？
4. 哪些反馈流程值得沉淀成 skill？
5. 助教 agent 只能写哪些草稿？
6. 哪些动作必须讲师确认？
7. 哪些教学经验适合长期记忆？
8. 哪些信息绝对不能保存到 memory？
```
