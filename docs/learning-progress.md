## 30 天推进节奏

| 时间 | 重点 | 建议完成 |
| --- | --- | --- |
| Day 1-3 | 建立路线 | 读第 0-1 章，选个人或团队目标，写第一版学习记录 |
| Day 4-7 | 练会基础 prompt | 读第 2-4 章，完成 2 个失败 prompt 的改写复盘 |
| Day 8-12 | 建立评估意识 | 读第 5 章，做一个小评测表，不再只凭感觉判断输出 |
| Day 13-17 | 连接资料和工具 | 读第 6-7 章，把一个常用任务固化成工作流或 skill |
| Day 18-22 | 理解 agent 与记忆 | 读第 8-10 章，写出工具权限、停止条件和记忆边界 |
| Day 23-26 | 看前沿但不盲追 | 读第 11-12 章，记录一条需要季度复核的动态事实 |
| Day 27-30 | 做安全、发布和职业复盘 | 读第 13-15 章，完成一次完整实践复盘，并写出下一阶段作品集计划 |

## 卡住时怎么跳转

```text
看不懂术语 -> 术语回链索引 -> AI 术语表 -> 对应章节
不知道读哪章 -> 主题索引 -> 分角色学习路径 -> 学习进度清单
缺少案例 -> 案例索引表 -> 真实应用案例 -> 前沿与过时技术案例库
输出总是不稳定 -> Prompt 调试指南 -> 章节练习与验收映射表
想带团队用 -> 团队 AI 落地完整路线图 -> 30 天团队试点跟踪表
想找工作或接单 -> 第 15 章 -> 职业发展案例 -> 端到端实战项目指南
```

## 进入下一轮学习的条件

- 不是只读完，而是至少留下一个可复查的输出物。
- 不是只收藏案例，而是能说清案例里哪个环节有效、哪个环节有风险。
- 不是只追新技术，而是能说明它和旧方法相比解决了什么问题，又新增了什么边界。
