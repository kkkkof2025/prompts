# Prompt 优化与成本节约指南

> 好的 prompt 不只是让 AI 输出质量高，还要让每次调用便宜、快速、可复用。这一节教你写出"经济适用型" prompt。

## 一、为什么 prompt 长度很重要

每次 API 调用都在为 token 付费。**输入比输出更贵**——因为每个 prompt 都包含 system prompt + 对话历史 + 用户输入。

### 1.1 一笔账算给你看

```text
假设你每天用 AI 50 次，每次 prompt 1500 tokens，输出 500 tokens：
用 GPT-4o（输入 ¥35/百万、输出 ¥105/百万）：

每次：1500 × 35 ÷ 1000000 + 500 × 105 ÷ 1000000 = ¥0.0525 + ¥0.0525 = ¥0.105
每天 50 次：¥5.25
每月：¥157.5

如果你能压缩 prompt 到 800 tokens：
每次：800 × 35 ÷ 1000000 + 500 × 105 ÷ 1000000 = ¥0.028 + ¥0.0525 = ¥0.0805
节省：24% / 次
```

结论：**输入 token 是和钱直接挂钩的。写得越精简，越省钱。**

## 二、Prompt 瘦身技巧

### 2.1 删除"礼貌废话"

```text
❌ 长版（52 tokens）：
请帮我写一份关于我们团队上个月工作内容的周报。如果可以的话，请写得
详细一些，但也不要太长，适中就好。非常感谢你的帮助，辛苦了！

✅ 短版（18 tokens）：
写一份团队月度周报。300 字以内。包含：重点项目进展、问题与风险、下周计划。
```

**规则**：AI 不需要"请""辛苦了""非常感谢"——这些 token 是白花的。

### 2.2 用结构化替代描述性

```text
❌ 描述性（85 tokens）：
我希望你扮演一个资深的代码审查者的角色。你在审查代码时应该非常仔细，
要检查代码是不是符合规范，有没有潜在的安全问题，命名是不是合理，
有没有可以优化的地方，还要看看代码是不是好读好维护。请用友好的语气提出建议。

✅ 结构化（30 tokens）：
# 代码审查
检查项：规范|安全|命名|性能|可读性
输出：每条问题 + 严重度(高/中/低) + 建议修复方式
语气：专业但不苛刻
```

### 2.3 把长列表变成关键词

```text
❌ 罗列式：
请确保你的回答是准确的、完整的、结构清晰的、易于理解的、没有偏见的、
不包含虚假信息的、引用来源的、考虑了安全风险的。

✅ 关键词式：
要求：准确|完整|结构化|有来源|安全。
```

### 2.4 让 AI 帮你瘦身

如果你有一个经常用但很长的 prompt，直接让 AI 帮你压缩：

```text
请把这个 prompt 压缩到 40 个 token 以内，保留所有关键信息。
不要加任何解释，只输出压缩后的 prompt。

[你的长 prompt]
```

## 三、System Prompt 管理

### 3.1 区分"永久规则"和"本次规则"

```text
永久规则（system prompt）：
- AI 的角色和行为规范
- 输出格式要求
- 安全边界和禁止事项
- 这些每次调用都会带上 → 越短越省钱

本次规则（user prompt）：
- 本次任务的具体要求
- 输入数据和背景
- 这些每次不同 → 按需给
```

### 3.2 System Prompt 瘦身检查

每季度检查一次你的 system prompt：

- [ ] 有没有已经不再使用的规则？
- [ ] 有没有可以用关键词替代的段落？
- [ ] 有没有可以移到知识库的内容？
- [ ] 有没有重复的描述？

**一个重要原则**：如果你发现 system prompt 超过 500 tokens，很可能有些内容应该放在知识库或 skill 里，而不是每次都发给模型。

## 四、对话历史管理

### 4.1 对话越长越贵

每次 AI 回复时，都会把**之前的对话历史**重新发给模型。所以：

```text
第 1 轮：系统 prompt (200) + 用户输入 (100) = 300 tokens
第 2 轮：系统 prompt (200) + 第1轮 (300) + AI回复 (150) + 用户输入 (100) = 750 tokens
第 5 轮：可能已经 2000+ tokens
第 10 轮：可能已经 5000+ tokens！
```

### 4.2 什么时候该"重开对话"

**重开对话的信号**：
- 话题已经换了（之前的上下文不相关了）
- 对话已经超过 10 轮
- 你发现 AI 开始"忘事"了

**不需要重开**：AI 需要记忆来持续完成任务的情况（比如多轮迭代写文档）。

### 4.3 对话摘要替代完整历史

长对话中，你可以定期让 AI 总结，用总结替代历史：

```text
请总结我们之前的对话，保留关键决策、当前状态和待决定的问题。
我会在新的对话中使用这个总结。
```

## 五、输出控制技巧

### 5.1 限定输出长度

```text
❌ 没限制：
请介绍 RAG 的原理。

→ AI 可能输出 500+ tokens

✅ 有上限：
用 3 个要点解释 RAG 原理，每个要点不超过 20 字。

→ AI 输出约 80 tokens，节省 84%
```

### 5.2 指定输出格式减少废话

```text
❌ 自由格式：
分析一下用户反馈数据。

→ AI 可能先来一堆"根据数据分析..."的铺垫

✅ 表格格式：
| 分类 | 数量 | 占比 | 优先级 |
|------|------|------|--------|
```

### 5.3 用"检查模式"代替"生成模式"

```text
❌ 生成模式（更贵）：
请基于以下内容写一份总结。

✅ 检查模式（更便宜）：
我已经写了一份总结，请检查是否遗漏了关键信息。

[你已有的总结]
```

## 六、缓存策略

### 6.1 识别可缓存的场景

以下场景适合缓存 AI 回复：

| 场景 | 缓存策略 |
|------|---------|
| FAQ 常见问题 | 缓存标准答案，定期检查是否过时 |
| 代码模板生成 | 缓存生成结果，按模板参数复用 |
| 格式转换 | 缓存转换规则，同格式复用 |
| 合规检查 | 缓存检查清单，只对违规项调 AI |

### 6.2 简单缓存实现

```python
import hashlib
import json

cache = {}

def get_cached_or_call(prompt, model_func):
    key = hashlib.md5(prompt.encode()).hexdigest()
    if key in cache:
        return cache[key], "cache_hit"  # 零成本
    result = model_func(prompt)
    cache[key] = result
    return result, "model_call"  # 正常成本
```

## 七、模型选择省钱策略

### 7.1 任务分级路由

```text
90% 的任务 → 便宜模型（DeepSeek-V3、Qwen-Turbo）
  ├── 简单翻译
  ├── 文本分类
  ├── 格式改写
  ├── FAQ 回答
  └── 数据提取

8% 的任务 → 性价比模型（GPT-4o-mini、Claude Haiku）
  ├── 长文写作
  ├── 内容创作
  └── 中等分析

2% 的任务 → 最强模型（GPT-4o、Claude Opus）
  ├── 复杂推理
  ├── 代码调试
  └── 合同分析
```

### 7.2 路由判断 prompt

```text
判断以下任务的复杂度，只回答"简单""中等"或"复杂"：

任务：把这段英文翻译成中文。
→ 简单

任务：分析这份 50 页合同的风险点。
→ 复杂

任务：写一封客户服务邮件回复。
→ 中等
```

## 八、Prompt 模板复用

### 8.1 提取变量

```text
❌ 每次都重写：
请为项目A写一份周报。项目A本周完成了需求评审，遇到了XX问题...

✅ 模板化：
# 周报生成模板
项目：{project_name}
本周完成：{completed}
进行中：{in_progress}
阻塞项：{blockers}
下周计划：{next_week}
格式：标准周报模板

# 每次只填变量，prompt 骨架不变
```

### 8.2 建立 Prompt 库

```text
prompts/
├── weekly-report.md      # 周报模板（已验证，直接用）
├── code-review.md        # 代码审查模板
├── meeting-notes.md      # 会议纪要模板
├── data-analysis.md      # 数据分析模板
└── README.md             # 说明每个模板的用途和效果
```

## 九、常见浪费与纠正

| 浪费行为 | 浪费程度 | 纠正方式 |
|---------|---------|---------|
| 每次都写"请帮我..." | 每请求 +5 tokens | 直接用祈使句 |
| System prompt 太长 | 每请求 +N tokens | 搬到知识库 |
| 对话不重开 | 每次 +2000+ tokens | 话题换了就重开 |
| 用最强模型做简单任务 | 成本 ×10 | 分层路由 |
| 不限定输出长度 | 输出可能翻倍 | 指定字数/要点数 |
| 不缓存重复请求 | 重复付费 | 建缓存 |
| 每次从零写 prompt | 浪费时间 | 建模板库 |

## 十、检查清单

每月检查一次：

- [ ] System prompt 是否 < 500 tokens？
- [ ] 是否有"礼貌废话"可以删？
- [ ] 高频 prompt 是否已模板化？
- [ ] 简单任务是否在用便宜模型？
- [ ] 重复请求是否缓存？
- [ ] 长期对话是否及时重开？
- [ ] 输出长度是否做了限制？
