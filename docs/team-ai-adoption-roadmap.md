# 团队 AI 落地完整路线图

最后核验：2026-05-07

本文档把本书中已经完成的学习材料、专题工作坊、行业案例、30 天试点和团队复盘串成一条可执行路线。它适合团队负责人、培训者、AI 推广负责人和希望系统化落地 AI 的小组使用，也适合和 [连续案例团队试点版](cases/continuous-case-team-pilot.md) 及 [连续案例样例库](cases/continuous-case-samples.md) 配合使用。

一句话版本：

```text
先让个人学会可靠使用 AI，再让小组通过工作坊形成共同边界，
然后用 30 天试点收集真实数据，最后进入季度复盘和持续迭代。
```

---

## 总路线

```text
阶段 1：学习课
目标：让个人掌握 AI 基础协作能力
材料：第 0-5 章、速查讲义、常见误区、Prompt 调试
产出：个人任务拆解能力、基础 prompt、输出验证习惯

阶段 2：专题工作坊
目标：让团队对风险、模型路线和使用边界达成共识
材料：AI 安全与模型选型工作坊、行业化工作坊案例集
产出：风险地图、模型路线清单、评测集、团队红线

阶段 3：30 天试点
目标：用小范围真实任务验证 AI 是否适合团队流程
材料：30 天团队 AI 试点跟踪表、团队落地手册、团队案例集
产出：日志数据、prompt 迭代、评估问卷、试点总结报告

阶段 4：复盘迭代
目标：决定是否推广、暂停或重构试点方案
材料：安全事故复盘案例集、安全案例更新指南、维护指南
产出：推广决策、更新后的规则、季度复核计划
```

---

## 适用对象

### 适合

- 准备在团队内推广 AI 使用，但还没有统一规范的负责人。
- 已经有人零散使用 AI，希望从个人经验变成团队流程的小组。
- 需要对 AI 安全、模型选型、数据边界和评估机制建立共识的组织。
- 教师、培训者、读书会组织者和企业内训负责人。

### 不适合

- 只想听一次工具演示，不打算落地试点的讲座。
- 需要正式法律、医疗、金融合规结论的审查会。
- 已经进入大规模生产自动化，但没有权限回滚和审计能力的系统。

## 阶段 1：学习课（个人能力建立）

### 目标

让参与者先具备三个基础能力：

```text
1. 能把任务说清楚：目标、背景、输入、输出、限制、验收标准。
2. 能判断 AI 输出是否可靠：事实核验、格式检查、边界识别。
3. 能把一次好用的 prompt 沉淀成模板。
```

| 理解 AI 能力边界 | [第 2 章：AI 的基本概念](chapters/02-ai-basics.md) |

### 建议节奏

如果是团队培训，建议用 2-4 次短课完成：

```text
第 1 次：AI 使用基础 + 对话能力（60-90 分钟）
第 2 次：Prompt 和结构化任务拆解（60-90 分钟）
第 3 次：输出验证、误区纠偏和调试（60-90 分钟）
第 4 次：个人小作业复盘（可选，60 分钟）
```

### 阶段产出

每位参与者至少交付：

```text
□ 1 个自己工作中的 AI 使用场景
□ 1 条可复用 prompt
□ 1 条 AI 输出验收标准
□ 1 个失败案例和改进版本
```

### 是否可以进入下一阶段？

满足以下条件后再进入团队工作坊：

```text
□ 70% 以上参与者能写出带目标、背景、输入、输出和验收标准的 prompt
□ 至少收集到 5 个真实工作场景
□ 已经出现 2-3 个值得讨论的失败案例
□ 团队负责人愿意花时间讨论边界，而不是只追求提效
```

## 阶段 2：专题工作坊（团队共识建立）

### 目标

让团队不再只讨论“用哪个模型”，而是先讨论：

```text
这个任务能不能交给 AI？
哪些数据不能进 AI？
AI 输出进入正式流程前谁负责确认？
成功和失败怎么评估？
```

### 推荐材料

| 目标 | 推荐材料 |
| ------ | ---------- |
| 通用工作坊流程 | [AI 安全与模型选型工作坊](workshop-safety-model-selection.md) |
| 行业化案例 | [行业化工作坊案例集](workshop-industry-cases.md) |
| 安全复盘参考 | [AI 安全事故复盘案例集](safety-incident-retrospectives.md) |
| 模型选择参考 | [AI 模型选型实战案例集](model-selection-cases.md) |
| 模型背景参考 | [中外 AI 模型特色概览](model-landscape-china-global.md) |
| 团队制度参考 | [团队 AI 落地手册](team-adoption-playbook.md) |

### 建议流程

标准 120 分钟版本：

```text
0-10 分钟   开场：为什么要先做边界和评测
10-25 分钟  事故复盘演练：看一个失败案例
25-45 分钟  风险地图：每组画出一个真实场景的风险
45-65 分钟  模型路线选择：闭源 API / 开放权重 / 本地部署 / RAG / agent
65-85 分钟  小型评测集：每组写 5 条样例
85-105 分钟 团队边界：允许、禁止、必须人工复核
105-120 分钟 汇报和下一步试点选择
```

如果时间只有 90 分钟，压缩为：

```text
事故案例 10 分钟 → 风险地图 20 分钟 → 模型路线 20 分钟 → 评测集 20 分钟 → 边界 20 分钟
```

### 阶段产出

每个小组至少交付：

```text
□ 1 张风险地图
□ 1 份模型路线候选清单
□ 1 个 5 条样例的小型评测集
□ 1 页团队使用边界
□ 1 个准备进入 30 天试点的场景
```

### 是否可以进入下一阶段？

满足以下条件后再进入 30 天试点：

```text
□ 试点场景足够具体，不是“全面使用 AI”
□ 有明确负责人
□ 有清楚的停止条件
□ 有至少 5 条评测样例
□ 已经写清哪些数据不能进入 AI
□ 管理者认可“先试点，不直接全面推广”
```

## 阶段 3：30 天试点（真实流程验证）

### 目标

不要用感受判断 AI 是否有效，而是用 30 天数据回答：

```text
AI 是否真的节省时间？
输出质量是否稳定？
人工复核成本是否可接受？
是否出现安全或合规风险？
团队成员是否愿意继续使用？
```

### 推荐材料

| 目标 | 推荐材料 |
| ------ | ---------- |
| 试点全流程 | [30 天团队 AI 试点跟踪表](pilot-tracking-30days.md) |
| 团队制度建设 | [团队 AI 落地手册](team-adoption-playbook.md) |
| 真实案例参考 | [团队 AI 落地案例集](team-adoption-cases.md) |
| 任务选择判断 | [AI 任务选择决策指南](task-decision-guide.md) |
| 能力评估 | [AI 能力评估量表](assessment-rubric.md) |

### 30 天节奏

```text
Day 1-3   准备启动：选场景、拉人、建档、配置工具
Day 4-7   第一周试跑：每人每天记录日志
Day 8-14  第二周迭代：修 prompt、补评测集、更新红线
Day 15-21 第三周扩展：加入第二批试用者
Day 22-30 第四周评估：问卷、总结报告、复盘会
```

### 关键数据指标

| 指标 | 说明 | 建议目标 |
| ------ | ------ | ---------- |
| 使用日志数 | 每次真实 AI 使用记录 | 30 天累计不少于 50 条 |
| 输出质量平均分 | 1-5 分评分 | ≥ 3.5 |
| 人工修改比例 | 需要较大修改的输出比例 | < 30% |
| 红线触发次数 | 违反团队边界的次数 | 0 次重大触发 |
| 安全事件次数 | 数据泄露、误发、越权等 | 0 次重大事件 |
| 继续使用意愿 | 最终问卷评分 | ≥ 3.5/5 |

### 阶段产出

```text
□ 试点日志汇总
□ Prompt 迭代记录
□ 更新后的评测集
□ 更新后的团队红线
□ 最终评估问卷
□ 30 天试点总结报告
□ 推广 / 继续试点 / 暂停 的决策建议
```

### 是否可以进入下一阶段？

进入复盘迭代不需要“成功”，只需要有真实数据。

如果出现以下情况，应进入“暂停或重构”复盘：

```text
□ 出现重大安全事件
□ 输出质量平均分低于 3.0
□ 人工修改比例超过 50%
□ 团队成员普遍不愿继续使用
□ 管理层要求扩大，但试点数据不支持扩大
```

## 阶段 4：复盘迭代（推广决策与长期维护）

### 目标

用复盘把试点结果转成下一轮行动，而不是让 30 天记录沉没。

复盘要回答四个问题：

```text
1. 哪些场景值得推广？
2. 哪些场景应该暂停？
3. 哪些规则需要写进团队规范？
4. 下一季度需要复核哪些模型、工具或安全标准？
```

### 推荐材料

| 目标 | 推荐材料 |
| ------ | ---------- |
| 事故复盘 | [AI 安全事故复盘案例集](safety-incident-retrospectives.md) |
| 安全更新 | [AI 安全案例更新指南](safety-case-updates.md) |
| 维护机制 | [项目维护指南](maintenance-guide.md) |
| 资源复核 | [资源与引用](appendix-resources.md) |
| 团队制度化 | [团队 AI 落地手册](team-adoption-playbook.md) |

### 决策分支

#### A. 推荐扩大推广

条件：

```text
□ 质量评分 ≥ 3.5
□ 重大安全事件 = 0
□ 人工修改比例 < 30%
□ 70% 以上成员愿意继续使用
□ 负责人能说清推广边界
```

下一步：

```text
1. 把试点 prompt 固化为团队模板。
2. 把团队红线写入正式规范。
3. 扩大到相邻场景，而不是一次性扩大到全部场景。
4. 每季度复核一次模型和安全标准。
```

#### B. 继续小范围试点

条件：

```text
□ 有明显价值，但质量或安全边界仍不稳定
□ 部分成员愿意继续用，但分歧较大
□ 评测样例不足，难以判断真实效果
```

下一步：

```text
1. 延长 2-4 周。
2. 缩小任务范围。
3. 补充评测集。
4. 重新定义成功标准。
```

#### C. 暂停推广

条件：

```text
□ 出现重大安全事件
□ 质量长期不达标
□ 人工复核成本超过收益
□ 管理层和执行者对边界无法达成一致
```

下一步：

```text
1. 保留试点数据，不把失败当成浪费。
2. 写清暂停原因。
3. 明确重新评估条件。
4. 必要时换场景，而不是继续强推原场景。
```

## 主持人检查清单

在推动团队 AI 落地时，主持人每阶段都应确认：

### 学习课前

```text
□ 参与者知道这不是工具广告课
□ 准备了真实任务，不只做抽象练习
□ 已说明 AI 输出需要验证
```

### 工作坊前

```text
□ 已收集 2-3 个匿名化真实场景
□ 已选择行业案例包
□ 已准备事故复盘样例
□ 已提醒参与者带上实际工作任务
```

### 试点前

```text
□ 负责人明确
□ 试点范围明确
□ 数据边界明确
□ 评测集明确
□ 停止条件明确
```

### 复盘前

```text
□ 已收集日志和问卷
□ 已统计质量分和修改比例
□ 已整理安全事件
□ 已准备推广 / 继续 / 暂停三个决策选项
```

## 最常见的落地失败模式

| 失败模式 | 表现 | 修正方式 |
| ---------- | ------ | ---------- |
| 直接上工具 | 还没定义任务就买账号 | 先做学习课和工作坊 |
| 没有边界 | 什么都让 AI 做 | 先写禁止项和人工复核点 |
| 不做评测 | 靠感觉说“好用/不好用” | 至少准备 5 条样例 |
| 一次性推广 | 直接要求全员使用 | 先 3-5 人试点 30 天 |
| 没有负责人 | 大家都觉得是别人负责 | 设定单一试点负责人 |
| 只看提效 | 不看错误和安全风险 | 同时记录质量、修改率、安全事件 |
| 复盘缺席 | 试点结束后没有决策 | Day 30 必须开复盘会 |
