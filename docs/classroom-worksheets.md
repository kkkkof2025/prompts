# 课堂练习工作纸

这份材料给学员使用，也适合讲师打印、发到课程群或放进团队知识库。它把 [教学版本材料包](teaching-kit.md) 中的课堂练习拆成可填写的工作纸，帮助学习者把概念落到自己的真实任务上。进阶训练可以配合 [AI 安全与模型选型工作坊](workshop-safety-model-selection.md) 使用。

建议配合 [教学示范作业集](teaching-examples.md) 使用：先看示范，再填写自己的版本。

如果学员不知道某个任务该填哪张工作纸，可以先用 [AI 任务选择决策指南](task-decision-guide.md) 判断任务形态。

如果学员已经写了 prompt 但输出不好，可以用 [Prompt 调试指南](prompt-debugging-guide.md) 先定位失败类型。

## 使用建议

每张工作纸都遵循同一节奏：

```text
先写原始版本 -> 找出问题 -> 改写结构 -> 设定验收标准 -> 记录下一步
```

填写时只使用可以公开或已经匿名化的资料。涉及个人隐私、客户信息、密钥、合同和未公开业务资料时，先改写成结构相同的安全样例。

## 工作纸 1：五要素 Prompt

适用场景：

第 1 周课堂练习、零基础入门、任何需要把模糊请求变清楚的任务。

填写区：

```text
我的真实任务：

原始 prompt：

这个 prompt 可能失败的原因：
1.
2.
3.

目标：

背景：

约束：

验收标准：
1.
2.
3.

输出格式：

如果信息不足，希望 AI 先问我的问题：
1.
2.
3.

改写后的 prompt：
```

自查清单：

- 目标是否能判断完成或未完成。
- 背景是否只保留影响输出的信息。
- 约束是否包含不能做的事。
- 验收标准是否能用于拒收不合格输出。
- 输出格式是否能直接进入下一步。

同伴反馈：

```text
我看懂了你的任务吗：

我认为最缺的一条背景是：

我认为最重要的一条验收标准是：

我建议删除或压缩的信息是：

我建议补充的风险或边界是：
```

课后行动：

```text
我将在什么任务中使用这个 prompt：

使用日期：

实际输出是否合格：

我做了哪些人工修改：

下一版要改哪里：
```

## 工作纸 2：复杂任务拆解

适用场景：

第 2 周课堂练习、长文写作、调研、产品分析、代码任务、课程设计和任何多步骤任务。

填写区：

```text
任务名称：

为什么这个任务不适合一次性交给 AI：
1.
2.
3.

最终交付物：

第 1 步：
输入：
动作：
输出：
检查点：

第 2 步：
输入：
动作：
输出：
检查点：

第 3 步：
输入：
动作：
输出：
检查点：

第 4 步：
输入：
动作：
输出：
检查点：

第 5 步：
输入：
动作：
输出：
检查点：

必须人工复核的步骤：

最容易失败的一步：

失败后如何回退：
```

拆解原则：

- 每一步只做一类动作。
- 上一步输出要能成为下一步输入。
- 检查点要比“看起来不错”更具体。
- 涉及事实、代码、数据、发布和权限时设置人工复核。
- 如果一步很难写清，继续拆小。

同伴反馈：

```text
我认为步骤过大的地方是：

我认为缺少检查点的地方是：

我认为必须人工复核的地方是：

我认为可以模板化的一步是：
```

## 工作纸 3：小型评测集

适用场景：

第 2 周课后作业、prompt 迭代、工作流验证、skill 测试。

填写区：

```text
要测试的 prompt、工作流或 skill 名称：

它应该稳定完成什么任务：

测试样例 1：
输入材料：
预期输出特征：
必须避免的问题：
合格标准：

测试样例 2：
输入材料：
预期输出特征：
必须避免的问题：
合格标准：

测试样例 3：
输入材料：
预期输出特征：
必须避免的问题：
合格标准：

测试样例 4：
输入材料：
预期输出特征：
必须避免的问题：
合格标准：

测试样例 5：
输入材料：
预期输出特征：
必须避免的问题：
合格标准：
```

覆盖检查：

- 是否包含正常输入。
- 是否包含信息不足的输入。
- 是否包含容易误解的输入。
- 是否包含边界情况。
- 是否包含高风险或必须人工复核的情况。

测试记录：

```text
测试日期：

通过的样例：

失败的样例：

失败原因：

我修改了什么：

是否需要继续测试：
```

## 工作纸 4：知识库资料分拣

适用场景：

第 3 周课堂练习、团队知识库建设、个人资料整理、RAG 准备。

填写区：

```text
资料名称：

资料来源：

资料用途：

是否适合进入知识库：

原因：

是否包含隐私或敏感信息：

需要匿名化或删除的内容：

访问权限：

更新频率：

过期或撤回规则：

AI 回答时是否必须引用来源：

备注：
```

分拣判断：

- 资料是否稳定、可信、可授权使用。
- 资料是否包含个人隐私或未公开商业信息。
- 资料是否有来源、日期和版本。
- 资料是否需要定期更新。
- 资料是否可以被不同角色访问。

不建议进入知识库的材料：

- 密码、密钥、验证码和访问令牌。
- 未经授权的客户资料。
- 原始身份证件、银行卡和医疗信息。
- 未公开合同、报价和财务数据。
- 一次性临时讨论和未经确认的猜测。

## 工作纸 5：Skill/Card

适用场景：

第 3 周课堂练习、重复任务沉淀、团队模板库建设。

填写区：

```text
名称：

用途：

触发场景：

适合的使用者：

输入要求：
1.
2.
3.

执行步骤：
1.
2.
3.
4.
5.

输出格式：

边界：
1.
2.
3.

验收标准：
1.
2.
3.

示例输入：

示例输出摘要：

最小测试样例：

维护者：

下次复查日期：
```

判断它是否值得变成 skill：

- 是否每周或每月会重复出现。
- 是否有稳定输入和稳定输出。
- 是否有明确边界。
- 是否能通过样例测试。
- 是否比临时 prompt 更省时间。

常见问题：

- 只有 prompt，没有边界。
- 只有流程，没有验收标准。
- 输入要求不清，导致每次都要补问。
- 输出格式太随意，无法接到下一步。
- 没有测试样例，无法判断是否稳定。

## 工作纸 6：Agent 工作说明

适用场景：

第 4 周课堂练习、低风险自动化、代码任务、资料整理、个人助手设计。

填写区：

```text
任务名称：

为什么需要 agent，而不是普通对话：

目标：

可使用工具：
1.
2.
3.

允许读取：

允许写入：

禁止事项：
1.
2.
3.
4.
5.

验收标准：
1.
2.
3.

必须人工确认的动作：
1.
2.
3.

执行日志需要记录：
1.
2.
3.

失败或不确定时的处理方式：

完成后的交付物：
```

高风险动作清单：

- 删除文件。
- 发送邮件或消息。
- 发布内容。
- 支付、下单或审批。
- 修改权限。
- 修改生产环境。
- 处理敏感数据。
- 保存长期记忆。

设计原则：

- 先从低风险任务开始。
- 先限制读取和写入范围。
- 先要求日志，再考虑自动化。
- 写不清禁止事项时，不要启动 agent。
- 涉及外部影响时，必须人工确认。

## 工作纸 7：记忆规则

适用场景：

第 4 周课堂练习、个人 AI 助手设置、团队 AI 规范。

填写区：

```text
我希望 AI 长期记住的偏好或背景：
1.
2.
3.
4.
5.

我不希望 AI 保存的信息：
1.
2.
3.
4.
5.

保存新记忆前是否需要确认：

多久回顾一次长期记忆：

记忆过时时如何删除：

当前任务和历史偏好冲突时，以哪个为准：

涉及他人信息时如何处理：
```

适合保存：

- 长期目标。
- 稳定偏好。
- 常用输出格式。
- 项目公开背景。
- 反复出现的流程。

不适合保存：

- 密码、密钥和验证码。
- 身份证、银行卡和住址。
- 客户隐私。
- 未公开商业资料。
- 一次性情绪和临时要求。

- 哪些动作一旦执行很难撤回。
- 团队是否有足够能力复核 AI 输出。

## 工作纸 10：课后复盘

适用场景：

每周课后、个人自学、读书会结束后。

填写区：

```text
本周主题：

我完成的练习：

我最有用的收获：

我仍然不理解的问题：

我遇到的 AI 输出失败：

失败原因可能是：
1.
2.
3.

我做了哪些人工修改：

我想沉淀成模板或 skill 的任务：

下周我要练习的真实任务：

需要讲师或同伴帮助的问题：
```

复盘判断：

- 是否真的把 AI 用到一个真实任务。
- 是否保存了原始 prompt 和改进版本。
- 是否记录了失败原因。
- 是否把好用结构沉淀下来。
- 是否识别了安全和复核边界。

## 讲师收取作业清单

收作业前，请提醒学员：

- 只提交可公开或已经匿名化的内容。
- 不提交密码、密钥、客户资料和未公开业务信息。
- 保留原始版本和改进版本。
- 写清楚 AI 输出哪里失败。
- 写清楚人工修改了什么。

讲师点评时，优先看：

- 任务是否真实。
- 结构是否清楚。
- 验收标准是否可用。
- 边界是否具体。
- 是否有测试和复盘。

不建议只按语言漂亮程度评分。AI 输出真正能不能进入下一步，取决于目标、上下文、验证、边界和人的判断。
