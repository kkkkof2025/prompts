# 试读与试跑反馈包

这份反馈包用于把书稿、教学材料和团队落地材料从“写完初稿”推进到“经过真实使用验证”。它适合三类场景：

- 个人读者试读：检查章节是否容易理解、练习是否能做。
- 读书会或课堂试跑：检查讲授节奏、练习难度和作业要求。
- 团队 AI 试点：检查模板、工作流、安全边界和评估表是否能进入真实流程。

建议配合 [读书会与教学方案](facilitation-guide.md)、[教学版本材料包](teaching-kit.md)、[课堂练习工作纸](classroom-worksheets.md)、[连续案例课堂试跑版](cases/continuous-case-classroom-run.md)、[连续案例课堂投影短版](cases/continuous-case-slide-brief.md)、[连续案例团队试点版](cases/continuous-case-team-pilot.md)、[连续案例样例库](cases/continuous-case-samples.md)、[团队 AI 落地完整路线图](team-ai-adoption-roadmap.md)、[30 天团队试点跟踪表](pilot-tracking-30days.md)、[AI 能力评估量表](assessment-rubric.md) 和 [1.0 发布前总检查清单](release-checklist-1.0.md) 使用。

## 使用原则

只收集能指导修改的反馈。

“不错”“有点难”这类评价不能直接改稿。更有用的是：读者在哪一页停住、哪个概念需要重新解释、哪道练习无法完成、哪张表格不能直接使用。

先验证关键路径。

不要一次让试读者检查全部材料。先选一个路径，例如“初学者从第 0-4 章完成一次 prompt 改写”或“团队负责人用试点跟踪表跑一次周复盘”。

保护真实数据。

反馈表不要要求填写客户姓名、个人身份信息、合同、财务、人事、密钥或内部敏感材料。需要展示样例时，先匿名化和改写。

保留反对意见。

如果试读者认为某个练习多余、某个章节太长、某个安全建议太保守，不要急着删改。先记录使用场景、读者背景和失败证据，再决定是否调整。

## 最小验证路径

### 路径一：个人读者 60 分钟试读

适合验证第 0-4 章、速查讲义、常见误区和 Prompt 调试指南。

```text
参与者：1-3 名没有系统学过 AI 的读者
材料范围：第 0-4 章 + 速查讲义 + 1 张课堂工作纸
任务：用自己的真实任务写一个初版 prompt，再根据书中方法改写
观察重点：读者是否知道从哪里开始、是否能写出验收标准、是否能判断输出好坏
产出：读者反馈表 + prompt 前后对照 + 修改建议清单
```

### 路径二：读书会或课堂 2 小时试跑

适合验证教学材料包、课堂工作纸和教学示范作业。

```text
参与者：4-12 名学习者
材料范围：教学版本材料包中的一节课 + 2 张课堂工作纸 + 1 份示范作业
任务：完成一次现场练习和一次小组互评
观察重点：讲解是否超时、练习说明是否清楚、评分表是否能区分好坏
产出：讲师观察记录 + 学员反馈表 + 练习样例匿名摘录
```

### 路径三：团队 1 周小试点

适合验证团队 AI 落地手册、任务选择指南、工作流配方和安全边界。

```text
参与者：1 个小团队，建议先选低风险高频任务
材料范围：任务选择指南 + 团队落地手册 + 30 天试点跟踪表中的第 1 周
任务：选择 1 个真实任务，完成 3-5 次 AI 辅助执行
观察重点：任务是否适合 AI、数据边界是否清楚、人工复核是否可执行
产出：试点日志 + 输出质量评分 + 风险记录 + 是否继续试点的决策
```

## 试读任务单

### 初学者任务单

```text
你的目标：
用本书的方法改写一个你真实会使用的 AI 问题。

请完成：
1. 阅读第 0 章和第 3 章中与你最相关的部分。
2. 写下你的原始 prompt。
3. 根据书中方法补充目标、背景、约束、输出格式和验收标准。
4. 记录 AI 第一次回答哪里不满足要求。
5. 再改写一次 prompt。

提交材料：
1. 原始 prompt。
2. 改写后的 prompt。
3. AI 输出中你认为最有用的一段。
4. 你仍然不知道怎么判断的地方。
```

### 讲师任务单

```text
你的目标：
判断一节教学内容能否直接用于 60-90 分钟课堂。

请完成：
1. 选择教学版本材料包中的一节课。
2. 按讲师提示词准备讲解。
3. 选择 1-2 张课堂工作纸给学员填写。
4. 用教学示范作业讲解评分标准。
5. 记录超时、卡住、误解和讨论最集中的地方。

提交材料：
1. 实际用时。
2. 学员最常问的 3 个问题。
3. 最需要改写的一段说明。
4. 一条可以直接加入讲师备注的经验。
```

### 团队负责人任务单

```text
你的目标：
判断一个团队 AI 试点是否适合继续推进。

请完成：
1. 用任务选择指南筛选 1 个低风险高频任务。
2. 用团队落地手册填写数据分级和人工复核点。
3. 用工作流配方库写出一个可重复流程。
4. 连续执行 3 次，并记录每次输出质量。
5. 用 30 天试点跟踪表完成一次周复盘。

提交材料：
1. 任务名称和风险等级。
2. 3 次执行的评分。
3. 人工修改最多的地方。
4. 是否继续试点：继续 / 修改后继续 / 暂停。
```

## 评分量表

建议使用 1-4 分，避免所有项都落在中间。

| 维度 | 1 分 | 2 分 | 3 分 | 4 分 |
| --- | --- | --- | --- | --- |
| 易懂性 | 多数概念看不懂 | 能理解大意但经常停顿 | 基本能读懂 | 能向别人复述 |
| 可操作性 | 不知道下一步做什么 | 需要他人带着做 | 能独立完成主要步骤 | 能迁移到自己的任务 |
| 案例贴近度 | 和真实任务距离远 | 有启发但不能直接用 | 能改成自己的场景 | 能直接推动工作或学习 |
| 安全边界 | 不知道哪些不能做 | 知道风险但不会判断 | 能识别常见风险 | 能主动设置边界和复核 |
| 导航体验 | 找不到相关材料 | 需要多次回首页查找 | 基本能找到材料 | 能按目标选择阅读路径 |

记录方式：

```text
材料范围：
评分人：

易懂性：__ / 4
可操作性：__ / 4
案例贴近度：__ / 4
安全边界：__ / 4
导航体验：__ / 4

最低分维度：
最需要修改的证据：
是否建议进入 1.0：
□ 建议
□ 修改后建议
□ 不建议
```

## 修改优先级

| 优先级 | 含义 | 处理建议 |
| --- | --- | --- |
| P0 | 事实错误、安全误导、断链、无法使用 | 发布前必须修复 |
| P1 | 初学者大面积看不懂、关键练习无法完成 | 进入下一版前优先修复 |
| P2 | 例子不够贴近、表格不够顺手、说明略长 | 合并同类反馈后修改 |
| P3 | 风格偏好、个别措辞建议、扩展主题 | 记录到路线图或后续版本 |

## 从反馈到改稿

反馈进入改稿时，目标不是“把所有意见都满足”，而是判断哪些意见暴露了学习路径、例子、表格、安全边界或事实核验上的真实缺口。建议每轮只选一组优先级最高的问题处理，避免把书稿改成零散补丁。

### 改稿闭环

```text
1. 汇总反馈，不急着逐条改。
2. 把反馈按页面、读者类型和优先级分组。
3. 找出重复出现的问题，而不是只看单条评价。
4. 先处理 P0 和 P1。
5. 把每个修改写成一张修订任务卡。
6. 修改后重新跑本地链接、术语一致性和 Markdown lint。
7. 更新 CHANGELOG.md 和 MEMORY.md。
8. 若反馈来自真实课堂或团队试点，只写匿名化结论，不写可识别信息。
```

### 反馈到修改动作对照

| 反馈信号 | 可能原因 | 推荐修改 |
| --- | --- | --- |
| 多名初学者卡在同一个术语 | 定义过早或例子不足 | 在首次出现处补一句白话解释，并链接术语表 |
| 练习做不完 | 步骤太多或输入材料不明确 | 拆成准备、执行、复盘三段，补一个可复制输入样例 |
| 学员只评价“好不好看” | 验收标准不清 | 增加输出能否进入下一步流程的判断标准 |
| 团队担心数据能不能上传 | 安全边界不够具体 | 补数据分级、匿名化规则和人工复核点 |
| 表格没人填写完整 | 字段太多或用途不清 | 删掉低价值字段，保留能指导决策的字段 |
| 案例被认为太远 | 角色或行业不匹配 | 增加同结构的短案例，而不是重写整章 |
| 同一页面反复被找不到 | 入口和目录弱 | 更新 README、docs/index.md 或 SUMMARY |
| 内容涉及新模型或接口 | 事实可能过时 | 查官方来源，更新资源附录和复核记录 |
| 反馈只是风格偏好 | 不影响理解和行动 | 记录为 P3，暂不打断主线 |

### 进入改稿的判断

```text
□ 有明确证据，而不是笼统感受
□ 能定位到页面、章节、表格或任务
□ 修改后能改善理解、操作、安全或发布判断
□ 不会引入更大的结构混乱
□ 修改范围可以在本轮检查中验证
```

如果一个反馈暂时无法定位，不要直接改正文。可以先放入修订任务卡，等同类反馈出现后再处理。

### 改稿后复核

每次处理完 P0 或 P1，建议做一次轻量复核：

```text
修改页面：
解决的问题：
验证方式：
是否需要同步目录：
是否需要同步资源附录：
是否需要同步章节验收映射表：
检查命令结果：
下一轮仍需观察的问题：
```
