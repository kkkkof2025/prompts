# 中外 AI 模型特色概览

最后核验：2026-05-07

这份概览介绍中国和其他国家主要 AI 模型路线的常见特色。它不是排行榜，也不是采购建议。模型能力、价格、上下文长度、开放策略、工具能力、可用地区和许可证都会变化，实际选择前应重新查看官方文档和自己的测试结果。

如果你想学习怎么评估模型，请先读 [第 5 章：模型选择、验证与评估](chapters/05-evaluation.md)。如果你想看具体选型场景，请读 [AI 模型选型实战案例集](model-selection-cases.md)。如果你关注开源和本地部署，请读 [第 11 章：Hermes、HiMeS 与开源模型路线](chapters/11-hermes-himes-open-models.md)。如果你不知道任务该用普通对话、RAG、工具还是 agent，请读 [AI 任务选择决策指南](task-decision-guide.md)。

## 先看路线，不要先看国别

按国家或公司理解模型很直观，但实际选型更应该先看路线：

| 路线 | 主要关注点 | 常见适用场景 |
| --- | --- | --- |
| 通用对话模型 | 语言理解、写作、摘要、问答 | 日常协作、内容生成、资料整理 |
| 推理模型 | 多步骤推理、数学、代码、复杂规划 | 复杂分析、代码修复、研究辅助 |
| 代码模型 | 代码生成、补全、测试、重构 | 软件开发、脚本、代码审查 |
| 长上下文模型 | 大文档、长对话、多文件输入 | 合同、论文、报告、代码库阅读 |
| 多模态模型 | 图片、截图、文档、音频、视频 | 截图分析、视觉问答、内容审查 |
| 工具和 agent 生态 | 函数调用、插件、连接器、MCP、日志 | 自动化工作流、企业助手 |
| 开放权重模型 | 本地部署、微调、量化、私有化 | 隐私、成本控制、研究和定制 |
| 企业云模型 | 权限、审计、合规、已有云服务集成 | 团队落地、知识库、业务系统接入 |

同一个模型家族可能覆盖多条路线。不要问“哪个模型最好”，要问：

```text
我的任务最依赖哪一种能力？
```

## 中国模型的常见特色

中国模型生态有几个突出特点：

- 中文语境、中文写作和本地业务场景覆盖较好。
- 与国内云服务、办公软件、搜索、内容平台和企业系统结合紧密。
- 开放模型和商业 API 并行发展，便于从试用走向私有化或企业落地。
- 价格、延迟、可用地区和合规要求对中国团队更容易成为关键因素。
- 部分模型强调长上下文、代码、推理或 agent 能力，但具体能力应以当前版本测试为准。

### DeepSeek 路线

截至 2026-05-07 的观察：DeepSeek 常被用于讨论推理、代码、成本效率、开放模型和 API 生态。它适合被放入“高性价比推理和代码任务”的评估集合，但不应只凭社区评价直接用于高风险流程。

适合优先测试：

- 中文和英文混合技术问答。
- 代码解释、脚本生成、单元测试建议。
- 多步骤分析和推理任务。
- 成本敏感的批量处理任务。

选型注意：

- 区分不同模型版本和上下文长度。
- 真实测试自己的代码库、业务文本和格式要求。
- 高风险结论仍要外部核验。
- 如果使用开源权重或第三方部署，要单独核验许可证和运行环境。

### Qwen / 通义千问路线

截至 2026-05-07 的观察：Qwen 生态的一个重要特点是模型家族丰富，覆盖通用、代码、多模态、开放权重和企业云服务等方向。它适合关注中文能力、开源生态和阿里云企业服务的团队纳入评估。

适合优先测试：

- 中文写作、摘要、分类和知识整理。
- 代码生成和结构化输出。
- 多模态和文档理解任务。
- 需要在云服务与开放模型之间平衡的项目。

选型注意：

- 同一模型家族可能有不同尺寸、上下文长度和用途。
- 开源模型、本地部署和云 API 的行为可能不完全一致。
- 企业使用时要核验数据、地域、权限和审计能力。

### Kimi / Moonshot 路线

截至 2026-05-07 的观察：Kimi 和 Moonshot 常被用户关联到长上下文、文档阅读和产品化助手体验。适合放入“长资料阅读、中文资料问答和用户友好型助手”的候选集合。

适合优先测试：

- 长文档摘要。
- 多文件资料对比。
- 会议纪要、研究材料、报告草稿。
- 中文用户直接使用的在线助手场景。

选型注意：

- 长上下文不等于稳定理解全部细节。
- 要测试跨章节引用、数字提取、版本差异和引用准确性。
- 对合同、政策、报价等内容必须保留人工复核。

### 百度文心 / 千帆路线

截至 2026-05-07 的观察：百度文心和千帆更适合从“企业云、搜索、知识增强和业务系统接入”角度理解。对已经使用百度智能云、搜索或企业知识库能力的团队，评估成本较低。

适合优先测试：

- 企业知识库问答。
- 搜索增强的资料整理。
- 客服、营销、办公和内容生产流程。
- 需要云端权限、审计和业务集成的场景。

选型注意：

- 区分模型能力和平台能力。
- RAG 项目要先治理资料质量和权限。
- 对外输出要测试引用、拒答和低置信度升级。

### 智谱 GLM 路线

截至 2026-05-07 的观察：GLM 生态适合从中文通用模型、API 服务、开放模型和 agent 工具能力角度评估。它常见于国内开发者和企业 API 选型讨论。

适合优先测试：

- 中文问答、写作和结构化输出。
- 工具调用和 agent 原型。
- 教育、办公、企业知识助理。
- 需要本地或私有化可能性的项目。

选型注意：

- 不同 GLM 版本面向的任务不同。
- 工具调用能力要用真实工具链测试，而不是只看演示。
- 需要关注数据处理、访问控制和日志审计。

### 腾讯混元路线

截至 2026-05-07 的观察：腾讯混元更适合从腾讯云、企业服务、内容、办公、社交和多媒体生态角度理解。对已经在腾讯云或腾讯生态内建设业务的团队，集成成本可能是重要考虑。

适合优先测试：

- 企业办公和客服场景。
- 内容生成、多媒体和审核辅助。
- 与腾讯云服务结合的应用。
- 中文业务流程中的智能助手。

选型注意：

- 先明确是要模型能力、云平台能力，还是生态集成。
- 多媒体任务要单独测试输入限制、输出质量和审核要求。
- 企业场景要核验权限、审计、数据留存和可用地区。

## 国际模型的常见特色

国际模型生态的差异通常体现在前沿能力、开发者平台、企业服务、开放权重、区域合规和垂直任务上。

### OpenAI 路线

截至 2026-05-07 的观察：OpenAI 适合从前沿通用模型、开发者 API、工具调用、多模态、agent 和生态完整度角度理解。它常被用于复杂对话、代码、工具链和产品原型。

适合优先测试：

- 高质量通用问答和写作。
- 复杂代码和多步骤推理。
- 多模态输入和工具调用。
- 需要快速构建 AI 应用的开发者场景。

选型注意：

- 模型名称和能力更新很快，必须查当前官方模型页。
- 工具、agent、文件、检索和多模态能力要按产品文档验证。
- 企业使用要核验数据处理、地区可用性、成本和权限。

### Anthropic Claude 路线

截至 2026-05-07 的观察：Claude 常被放在长上下文、写作质量、企业协作、安全边界和 agent/skills 生态中评估。它适合长文档理解、研究辅助、代码协作和审慎语气的业务场景。

适合优先测试：

- 长文档阅读和改写。
- 研究材料综合。
- 代码解释、重构建议和测试计划。
- 需要较强拒答边界和企业治理的流程。

选型注意：

- 长上下文任务仍要测试遗漏、错引和跨段推理。
- 安全边界不能替代应用层权限控制。
- 对工具能力和 skills 生态要查看最新文档。

### Google Gemini 路线

截至 2026-05-07 的观察：Gemini 适合从多模态、长上下文、Google 生态、AI Studio 和 Vertex AI 企业平台角度理解。它适合已经深度使用 Google Cloud 或 Google Workspace 的团队纳入评估。

适合优先测试：

- 图片、文档、音视频相关任务。
- 长上下文资料分析。
- Google Cloud 和企业数据流程。
- 搜索、办公和开发平台结合的工作流。

选型注意：

- 同一 Gemini 家族中不同模型面向的速度、成本和能力不同。
- 企业部署应区分 AI Studio、Vertex AI 和具体产品集成。
- 多模态任务要测试隐私、引用和输出稳定性。

### Meta Llama 路线

截至 2026-05-07 的观察：Llama 系列适合从开放权重、本地部署、社区生态、微调和研究角度理解。它的价值不只在单次能力分数，也在可控性和生态规模。

适合优先测试：

- 本地或私有化部署。
- 低成本高频任务。
- 微调、蒸馏、量化和研究实验。
- 对数据出域敏感的场景。

选型注意：

- 开放权重不等于没有许可证限制。
- 部署质量受推理框架、量化方式和硬件影响很大。
- 需要自己承担安全、监控、权限和更新责任。

### Mistral 路线

截至 2026-05-07 的观察：Mistral 适合从欧洲模型生态、开放模型、效率、企业 API 和部署灵活性角度理解。它适合关注数据主权、欧洲合规环境或轻量高效模型的团队评估。

适合优先测试：

- 高效率文本处理。
- 企业 API 与自托管混合路线。
- 多语言任务。
- 对欧洲生态和部署选择敏感的项目。

选型注意：

- 不同模型的开放程度、许可证和部署方式不同。
- 多语言能力要用自己的语言和行业文本测试。
- 企业使用时核验数据处理和合规要求。

### Cohere 路线

截至 2026-05-07 的观察：Cohere 常被放在企业 RAG、检索、重排、分类和受控业务流程中评估。它适合把 AI 当作企业搜索和知识系统一部分的团队。

适合优先测试：

- 企业知识库问答。
- 检索增强生成。
- 文档分类和信息抽取。
- 需要与现有数据系统结合的流程。

选型注意：

- RAG 质量不只取决于模型，也取决于资料治理、检索和权限。
- 需要测试引用准确性、拒答和越权资料过滤。
- 如果使用重排或嵌入能力，要评估端到端效果。

### xAI Grok 路线

截至 2026-05-07 的观察：Grok 更适合从实时信息、社交内容生态和对话产品角度理解。适合关注公开信息流、社交平台内容和实时语境的使用者纳入观察。

适合优先测试：

- 公开信息流摘要。
- 社交内容理解和话题追踪。
- 轻量研究和观点对比。
- 与特定产品生态结合的问答。

选型注意：

- 实时信息更要区分来源、时间和可信度。
- 社交内容噪声高，不能把热度当事实。
- 高风险事实仍需权威来源核验。

## 对中国用户和团队的选型建议

如果你在中国环境中学习或落地 AI，建议按下面顺序判断：

```text
1. 任务主要是中文还是多语言？
2. 资料是否允许出域或进入海外服务？
3. 是否需要发票、合同、企业账号、权限和审计？
4. 是否要连接现有云服务、办公系统或知识库？
5. 是否要本地部署、私有化或开源权重？
6. 成本、延迟和可用地区是否可接受？
7. 是否需要多模态、长上下文、代码或 agent 工具能力？
8. 是否有足够测试样例验证真实任务？
```

一个实用结论：

```text
个人学习可以多试模型。
团队落地必须先定数据边界和验收标准。
高风险业务不要只看模型能力，要看权限、日志、复核和事故处理。
```

## 5 个任务的小型评测集

比较模型时，用同一组任务测试，比看榜单更可靠。

```text
任务 1：中文长文摘要
输入：一篇 3000-8000 字资料
要求：输出 5 条要点、3 个风险、需要核验的信息

任务 2：结构化输出
输入：10 条客户反馈
要求：按 JSON 或表格分类，不能漏项，不能新增字段

任务 3：代码理解
输入：一个真实函数或脚本
要求：解释逻辑、指出风险、给出测试样例

任务 4：RAG 问答
输入：3 份版本不同的内部文档
要求：只根据资料回答，标注来源，资料冲突时说明冲突

任务 5：安全边界
输入：包含越权请求、敏感字段和间接指令的样例
要求：拒绝越权动作，脱敏输出，解释需要人工确认的点
```

评分维度：

| 维度 | 问题 |
| --- | --- |
| 准确性 | 是否基于输入，不编造 |
| 完整性 | 是否覆盖关键点 |
| 格式 | 是否稳定遵守要求 |
| 中文表达 | 是否自然、准确、适合读者 |
| 引用 | 是否能指出依据 |
| 安全 | 是否识别敏感信息和越权请求 |
| 成本 | 单次和批量使用是否可接受 |
| 延迟 | 是否适合真实工作流 |
| 可维护 | 是否容易接入、监控和替换 |

## 常见误区

误区 1：把国别当作能力结论。

更好的做法：把国别视为生态、合规、语言和服务可用性的线索，不把它当成质量评分。

误区 2：用排行榜替代自己的评测集。

更好的做法：用自己的资料、格式、语言、风险和成本测试。

误区 3：只看模型，不看平台。

更好的做法：同时评估 API、工具、权限、日志、计费、限流、文档和支持。

误区 4：把长上下文当作万能记忆。

更好的做法：长上下文适合一次性读长资料，长期知识仍需要资料治理、RAG、版本和权限。

误区 5：把开源当作自动安全。

更好的做法：开源或开放权重带来可控性，但部署、权限、日志、更新和滥用防护都要自己负责。

## 最后提醒

模型选择不是一次性决定，而是持续维护：

```text
任务变化 -> 测试样例变化 -> 模型版本变化 -> 成本变化 -> 安全边界变化
```

对个人学习者，最重要的是建立比较方法。对团队，最重要的是把模型选择放进数据治理、权限、评估和复盘流程里。
