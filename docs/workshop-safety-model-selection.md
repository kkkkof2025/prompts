# AI 安全与模型选型工作坊

最后核验：2026-05-07

这是一套 90-120 分钟专题工作坊材料，适合团队培训、读书会进阶课、内部 AI 推广试点复盘使用。它把 [AI 安全事故复盘案例集](safety-incident-retrospectives.md)、[AI 模型选型实战案例集](model-selection-cases.md)、[中外 AI 模型特色概览](model-landscape-china-global.md) 和 [团队 AI 落地手册](team-adoption-playbook.md) 串成一次可执行训练。

工作坊的目标不是让每个人记住所有模型名称，也不是让团队变得保守，而是让团队学会 3 个动作：

```text
看懂风险 -> 选对模型路线 -> 写出可落地的边界和评测
```

## 适合对象

适合：

- 团队负责人、产品经理、运营、工程师、教师和内部培训者。
- 已经开始用 AI，但还没有统一规则的团队。
- 准备建设知识库、模型选型或 agent 试点的小组。
- 需要把 AI 使用从个人经验变成团队流程的组织。

不适合：

- 完全没有接触过 AI 的零基础第一课。
- 只想听工具功能介绍、不打算做练习的讲座。
- 需要专业法律、医疗、金融合规判断的正式审查会。

## 工作坊产出

结束时，每个小组至少要产出 4 份材料：

```text
1. 一个 AI 使用场景的风险地图。
2. 一份模型路线候选清单。
3. 一个 5 条样例的小型评测集。
4. 一页团队使用边界和人工复核规则。
```

如果时间是 120 分钟，可以额外产出：

```text
5. 一个事故复盘演练记录。
6. 一个上线前检查清单。
```

## 课前准备

主持人准备：

- 选择 2-3 个本团队真实但已经匿名化的 AI 使用场景。
- 准备一份不涉密的示例资料，例如公开产品说明、虚构客服反馈、脱敏会议纪要或教学材料。
- 让参与者课前阅读 [AI 安全案例更新指南](safety-case-updates.md) 和 [AI 模型选型实战案例集](model-selection-cases.md)。
- 明确工作坊中禁止上传的资料类型。
- 准备白板、共享文档或协作表格。

参与者准备：

- 带一个最近想用 AI 完成的真实任务。
- 只带公开或已经匿名化的资料。
- 写下当前最常用的 AI 工具或模型。
- 写下一个担心的风险，例如泄露、幻觉、成本、格式不稳、权限或误发。

## 90 分钟流程

| 时间 | 环节 | 产出 |
| --- | --- | --- |
| 0-10 分钟 | 开场和边界说明 | 禁止上传清单 |
| 10-25 分钟 | 案例拆解 | 事故路径图 |
| 25-45 分钟 | 小组风险地图 | 风险分级表 |
| 45-65 分钟 | 模型路线选择 | 候选路线清单 |
| 65-80 分钟 | 小型评测集 | 5 条测试样例 |
| 80-90 分钟 | 汇报和收束 | 下一步行动 |

120 分钟版本：

| 时间 | 环节 | 产出 |
| --- | --- | --- |
| 0-10 分钟 | 开场和边界说明 | 禁止上传清单 |
| 10-30 分钟 | 安全事故复盘演练 | 事故复盘表 |
| 30-50 分钟 | 小组风险地图 | 风险分级表 |
| 50-75 分钟 | 模型路线选择 | 候选路线清单 |
| 75-95 分钟 | 小型评测集 | 10 条测试样例 |
| 95-110 分钟 | 使用边界设计 | 人工复核规则 |
| 110-120 分钟 | 汇报和承诺 | 30 天行动项 |

## 开场脚本

主持人可以直接照读或改写：

```text
今天不讨论“哪个模型最强”，也不讨论“AI 会不会取代谁”。

我们只做三件事：
1. 拆一个 AI 使用风险。
2. 为一个真实任务选择模型路线。
3. 写出上线前必须测试和人工确认的规则。

请不要上传或粘贴真实客户资料、密钥、合同、身份证件、未公开财务、人事评价和内部敏感数据。
如果你想讨论真实问题，请先改写成结构相同的匿名化案例。
```

## 环节 1：安全事故复盘演练

从下面 3 个案例中选一个，也可以使用团队自己的匿名化案例。

案例 A：知识库错误引用

```text
客服助手根据知识库回答客户价格问题。
它引用了一份未发布的价格草稿，并把草稿折扣写成正式承诺。
```

案例 B：agent 误发邮件

```text
运营 agent 根据报名表生成提醒邮件。
表格中有一列“不要联系”，但 agent 忽略该列，向退订用户发送了邮件。
```

案例 C：模型升级后格式失效

```text
团队把客服反馈分类模型升级为新模型。
新模型回答质量更好，但偶尔在 JSON 外添加解释文字，导致数据看板漏算投诉。
```

小组填写：

```text
案例名称：

发生了什么：

AI 看到了哪些资料：

AI 能调用哪些工具：

影响了谁：

表面原因：

深层原因：
1. 数据：
2. 权限：
3. 工具：
4. 评估：
5. 流程：

当场止损：

长期修复：
```

主持人追问：

- 这是模型回答问题，还是系统设计问题？
- 如果只改 prompt，能不能防止复发？
- 哪一步应该有人确认？
- 这次失败应该加入哪类评测样例？

## 环节 2：小组风险地图

每组选择一个真实 AI 使用场景，按下面模板画风险地图。

```text
场景名称：

当前任务：

输入资料：
- 公开：
- 内部：
- 敏感：
- 禁止输入：

AI 输出会给谁看：
- 个人：
- 团队：
- 客户：
- 公众：
- 系统：

AI 是否能采取行动：
- 只生成文本：
- 读文件：
- 写文件：
- 发消息：
- 调用外部系统：
- 修改权限或生产环境：

主要风险：
1.
2.
3.

必须人工确认的点：
1.
2.
3.
```

风险分级：

| 等级 | 判断标准 | 处理方式 |
| --- | --- | --- |
| 低 | 只处理公开或低敏资料，输出只供个人参考 | 可用普通 prompt 或模板 |
| 中 | 处理内部资料，输出进入团队流程 | 需要验收标准和抽样复核 |
| 高 | 涉及客户、合同、财务、人事、权限或对外承诺 | AI 只做草稿，必须人工确认 |
| 禁止 | 涉及密钥、验证码、越权访问、违法违规或不可回滚动作 | 不进入 AI 流程 |

主持人判断标准：

```text
如果 AI 输出会影响客户、公众、员工权益、合同义务、财务结果或生产系统，就不能按低风险处理。
```

## 环节 3：模型路线选择

不要先写具体模型名称，先写路线。

小组填写：

```text
任务名称：

最重要的能力：
- 中文表达：
- 长上下文：
- 代码：
- 多模态：
- RAG：
- 工具调用：
- 本地部署：
- 低成本批量：
- 强推理：

数据边界：
- 可使用外部云服务：
- 必须企业账号：
- 必须本地或私有化：
- 需要脱敏后处理：

候选路线 1：
适合原因：
主要风险：

候选路线 2：
适合原因：
主要风险：

候选路线 3：
适合原因：
主要风险：

暂不考虑的路线：
原因：
```

路线提示：

| 任务特征 | 优先路线 |
| --- | --- |
| 中文写作和资料整理 | 中文表现稳定的通用模型 |
| 长合同、长报告、多文件 | 长上下文模型或 RAG |
| 内部知识库问答 | RAG、权限过滤和企业平台 |
| 代码修复和测试 | 代码模型或强推理模型 |
| 批量分类和结构化 | 低成本模型加 schema 校验 |
| 截图、PDF、表格 | 多模态模型或文档解析工具 |
| 高敏感资料 | 本地部署、私有化或脱敏流程 |
| 自动化动作 | agent 工具边界和人工确认 |

主持人提醒：

```text
选型不是一次性答案。今天只确定候选路线和测试方法，不直接宣布最终模型。
```

## 环节 4：小型评测集

每组为自己的任务写 5 条样例。不要只写正常样例，必须包含失败和边界。

```text
任务名称：

样例 1：正常输入
输入：
预期输出：
合格标准：

样例 2：信息不足
输入：
预期输出：
合格标准：

样例 3：格式要求严格
输入：
预期输出：
合格标准：

样例 4：高风险或敏感内容
输入：
预期输出：
合格标准：

样例 5：容易误导 AI 的内容
输入：
预期输出：
合格标准：
```

必须至少覆盖：

- 一个正常样例。
- 一个信息不足样例。
- 一个格式边界样例。
- 一个安全边界样例。
- 一个需要人工确认的样例。

评分表：

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 准确性 | 明显错误 | 可作草稿 | 基于资料且可核验 |
| 完整性 | 漏关键点 | 覆盖主要点 | 覆盖主点和边界 |
| 格式 | 无法解析 | 少量修改可用 | 稳定符合格式 |
| 安全 | 忽略风险 | 提醒不完整 | 能识别并拒绝越权 |
| 可用性 | 不能进入下一步 | 需要较多人工修改 | 少量修改即可进入流程 |

合格线示例：

```text
平均分不低于 4 分；
安全维度不得低于 4 分；
格式维度不得低于 4 分；
高风险样例必须触发人工确认。
```

## 环节 5：团队使用边界

每组把本次任务写成一页边界说明。

```text
场景名称：

允许 AI 做：
1.
2.
3.

禁止 AI 做：
1.
2.
3.

允许输入的数据：
1.
2.
3.

禁止输入的数据：
1.
2.
3.

必须人工复核的输出：
1.
2.
3.

必须记录的日志：
1.
2.
3.

下一次复查日期：

负责人：
```

边界写法要求：

- 不写“注意隐私”这种空话。
- 写清具体数据类型。
- 写清具体动作。
- 写清谁复核。
- 写清什么时候复查。

可接受：

```text
禁止把包含客户手机号、身份证号、合同金额和未公开报价的资料输入外部 AI。
```

不可接受：

```text
注意不要输入敏感信息。
```

## 汇报模板

每组用 3 分钟汇报：

```text
1. 我们选择的场景是什么。
2. 最大风险是什么。
3. 我们选择了哪些候选模型路线。
4. 我们的 5 条评测样例覆盖了什么。
5. 哪些动作必须人工确认。
6. 未来 30 天准备怎么试点。
```

其他小组只问 3 类问题：

- 有没有漏掉更高风险的数据或动作？
- 模型路线是否和任务约束匹配？
- 评测样例是否能真的筛出失败？

## 主持人评分表

| 维度 | 分值 | 判断标准 |
| --- | --- | --- |
| 场景定义 | 15 | 任务、输入、输出和使用者清楚 |
| 风险识别 | 20 | 覆盖数据、权限、工具、对外影响 |
| 模型路线 | 20 | 不是只看热度，能解释路线选择 |
| 评测样例 | 20 | 覆盖正常、边界、格式、安全和人工确认 |
| 使用边界 | 15 | 禁止事项具体，责任清楚 |
| 可落地性 | 10 | 有负责人、下一步和复查日期 |

## 30 天后复盘

工作坊结束不等于落地完成。建议 30 天后开一次 45 分钟复盘会。

复盘问题：

```text
1. 哪个场景真的开始试点了？
2. 哪些评测样例发现了问题？
3. 哪些模型路线被淘汰，为什么？
4. 是否出现数据、权限或对外输出风险？
5. 哪条团队边界最有用？
6. 下一轮要扩大、暂停还是修改？
```

复盘产出：

- 更新评测集。
- 更新禁止输入清单。
- 更新模型候选清单。
- 更新人工复核规则。
- 决定是否进入下一轮试点。

生成工作坊案例：

```text
请为一次 AI 安全与模型选型工作坊生成一个匿名化案例。

团队类型：
【填写团队】

常见任务：
【填写任务】

要求输出：
1. 场景背景。
2. 一次可能的 AI 使用失败。
3. 涉及的数据、权限、工具和流程问题。
4. 5 个讨论问题。
5. 适合的模型路线候选。
6. 5 条评测样例。

要求：
不使用真实公司、真实客户和真实隐私信息。
```

点评小组方案：

```text
请点评以下小组的 AI 试点方案。

方案：
【粘贴小组方案】

请按以下维度点评：
1. 场景定义是否清楚。
2. 风险识别是否完整。
3. 模型路线是否匹配任务。
4. 评测样例是否足够。
5. 人工复核点是否明确。
6. 最应该先修改的 3 件事。

不要只给鼓励，要指出具体缺口。
```

生成 30 天试点计划：

```text
请把以下工作坊产出整理成 30 天 AI 试点计划。

工作坊产出：
【粘贴内容】

输出：
1. 试点目标。
2. 每周任务。
3. 负责人。
4. 评测集。
5. 安全边界。
6. 成功标准。
7. 暂停条件。
```

## 常见主持问题

参与者争论模型名称：

把讨论拉回任务约束，让他们先写“必须能力”和“不能接受的失败”。模型名称放到最后。

参与者只写正常样例：

要求每组至少写一个信息不足、一个格式边界、一个安全边界和一个人工确认样例。

参与者说“我们没有风险”：

追问 AI 输出会不会给客户、公众、员工、数据库、工单、邮件或生产系统看。只要进入这些地方，就有风险。

参与者想马上自动化：

先要求写清允许动作、禁止动作、日志、回滚和人工确认。写不清就只能做草稿流程。

管理者想用一次培训解决问题：

明确工作坊只产出试点材料。真正落地需要 30 天试点、评测、复盘和规则更新。

## 最后提醒

一次好的 AI 工作坊，不是让大家觉得“AI 很厉害”，而是让团队离开房间时手里有这些东西：

```text
一个清楚场景；
一个风险地图；
一组候选模型路线；
一份评测集；
一页使用边界；
一个 30 天试点动作。
```

这些材料比记住某个模型名字更能长期产生价值。
