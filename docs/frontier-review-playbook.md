# 前沿资料季度复核执行手册

最后维护：2026-05-13

这份手册用于把 0.8“前沿资料季度复核”变成可执行流程。它回答三个问题：

1. 本季度要复核哪些资料。
2. 看到变化后，怎样判断是否要改正文。
3. 修改后，哪些入口、记录和检查必须同步。

相关文件分工：

| 文件 | 作用 |
| --- | --- |
| [资源与引用](appendix-resources.md) | 保存官方来源、论文、标准和维护提醒 |
| [前沿资料季度复核记录表](frontier-review-log.md) | 记录每次复核的证据、影响范围和处理动作 |
| 本手册 | 指导维护者定范围、判断影响、执行修改和收尾检查 |
| [项目维护指南](maintenance-guide.md) | 说明项目整体维护节奏和文件边界 |
| [1.0 发布前总检查清单](release-checklist-1.0.md) | 发布前确认复核是否满足 1.0 条件 |

本手册不声称已经完成最新联网核验。真正更新模型、协议、工具和安全资料时，应打开官方文档、论文、标准组织资料或官方仓库，记录复核日期和证据。

## 复核层级

季度复核不一定每次都要全量重写。可以按时间和发布风险选择层级。

| 层级 | 适用场景 | 时间 | 产出 |
| --- | --- | --- | --- |
| 快速巡检 | 距离上次核验时间短，准备小版本发布 | 60-90 分钟 | 记录“已巡检/无重大变化”或列出待处理项 |
| 标准复核 | 准备 0.8、0.9 或 1.0 发布 | 半天到 1 天 | 更新资源附录、影响页面和发布记录 |
| 深度复核 | 出现重大模型、协议、安全标准或许可证变化 | 1-2 天 | 更新正文、案例、教学材料、检查清单和发布判断 |

选择建议：

- 只改错别字、格式和本地链接：不需要前沿复核。
- 新增模型、协议、agent、RAG、安全案例：至少做快速巡检。
- 发布 1.0 或对外推荐为稳定版本：至少做标准复核。
- 涉及医疗、法律、金融、教育、招聘、公共服务：优先做深度复核，并标注本书不替代专业意见。

## 复核范围

每次开始前，先在 [前沿资料季度复核记录表](frontier-review-log.md) 复制“复核批次记录”，再选择范围。

| 范围 | 必查资料 | 可选资料 | 典型影响 |
| --- | --- | --- | --- |
| 模型选型 | OpenAI、Anthropic、Google、中国模型、开放权重模型官方文档 | 价格页、模型卡、云平台公告 | 第 5 章、模型概览、模型选型案例 |
| 工具与 RAG | OpenAI 工具、MCP、检索与 rerank 文档 | 各厂商 connector、file search、企业知识库文档 | 第 6 章、团队落地手册、工作流配方 |
| skills 与 agent | OpenAI Agents SDK、Anthropic Agent Skills、A2A、OpenClaw | agent 框架 release、示例仓库 | 第 7、8、10、12 章和 agent 安全清单 |
| 记忆系统 | HiMeS、长期记忆、个性化助手相关论文或官方资料 | 产品记忆功能说明 | 第 9、11 章和安全治理章节 |
| 开源模型 | Llama、Mistral、Hermes、Hugging Face 模型卡 | 推理框架、量化工具、社区评测 | 第 11 章和本地部署案例 |
| 安全治理 | NIST、OWASP、MITRE、NCSC/CISA、OpenAI 安全指南 | 当地法规、行业指引、安全事件复盘 | 第 13 章、安全案例更新指南、事故复盘案例集 |
| 趋势报告 | Stanford HAI AI Index | 监管报告、行业年度报告 | 第 12 章和资源附录 |

如果时间有限，优先复核会影响读者决策的内容：模型是否还可用、接口是否变化、许可证是否变化、安全建议是否变化、协议是否有兼容性变化。

## 复核前准备

开始联网核验前，先做本地准备：

```powershell
./scripts/check-markdown-links.ps1 -Root . -CheckPlaceholders
./scripts/check-terminology.ps1 -Root .
npx --yes markdownlint-cli2 "**/*.md" "#_site" "#node_modules" "#vendor" "#dist"
```

如果本地检查已经失败，先修本地结构问题。否则联网复核后很难判断失败来自旧问题还是新修改。

阅读这些文件：

1. [MEMORY.md](../MEMORY.md)：确认上次核验日期、已完成项和下一步建议。
2. [CHANGELOG.md](../CHANGELOG.md)：确认本次修改应该写入哪个版本段。
3. [资源与引用](appendix-resources.md)：确认本次要复核的官方来源。
4. [前沿资料季度复核记录表](frontier-review-log.md)：复制批次记录和单条资料记录模板。
5. [前沿资料季度复核记录表](frontier-review-log.md)：参考一条虚构示范，熟悉填写方式。

## 证据记录规则

每条资料记录至少包含：

| 字段 | 写法 |
| --- | --- |
| 资料名称 | 使用官方名称，不写简称猜测 |
| 链接 | 官方文档、论文、标准页、模型卡或官方仓库 |
| 复核日期 | 使用 `YYYY-MM-DD` |
| 资料日期或版本 | 如果页面有版本、release、更新时间，必须记录 |
| 原书相关位置 | 具体到章节或材料页 |
| 发现变化 | 用自己的话概括，不复制长篇原文 |
| 影响判断 | 不影响、更新附录、更新正文、更新案例、影响发布 |
| 处理动作 | 不修改、改附录、改正文、移到历史说明、标注待人工复核 |

不要把“看起来很火”“社区都在用”“某榜单很高”直接写成事实。可以记录为观察，但不能作为正文改动的唯一依据。

## 影响判断

看到变化后，先判断变化类型，再决定是否修改正文。

| 变化 | 默认处理 |
| --- | --- |
| 模型名称、模型下线、默认模型变化 | 更新资源附录、模型概览和相关案例 |
| 上下文长度、价格、速率限制变化 | 如果正文写了具体数字，更新或改成“以官方页面为准” |
| 工具、connector、MCP、file search、computer use 能力变化 | 更新工具、RAG、agent 和安全边界相关章节 |
| 协议字段、版本、兼容性变化 | 更新 MCP、A2A 和 agent 协作说明 |
| 许可证、商用限制、开放权重策略变化 | 更新开源模型章节、本地部署案例和模型选型建议 |
| 安全标准或风险分类变化 | 更新安全治理章节、检查清单和事故复盘材料 |
| 新模型发布 | 先判断是否改变选型框架；不改变框架时只更新附录 |
| 产品营销表述变化 | 不直接进入正文，除非官方文档改变了可验证能力 |
| 论文实验结论变化 | 保留研究边界，避免写成产品能力 |

可以用这个决策句：

```text
这条变化是否会让读者做出不同决策？
如果会，更新正文或案例。
如果不会，只更新资源附录或复核记录。
```

## 修改顺序

涉及事实更新时，按下面顺序修改，能减少遗漏。

1. 先更新 [前沿资料季度复核记录表](frontier-review-log.md)，写清证据和影响范围。
2. 再更新 [资源与引用](appendix-resources.md)，调整核验日期、来源和维护建议。
3. 修改受影响的正文、案例、教学材料或检查清单。
4. 如果新增页面，写入 [SUMMARY.md](SUMMARY.md)、[docs/index.md](index.md)、根目录 [README.md](../README.md) 和根目录 [index.md](../index.md)。
5. 如果新增页面需要离线阅读，写入 [export-ebook.ps1](../scripts/export-ebook.ps1)。
6. 更新 [CHANGELOG.md](../CHANGELOG.md) 和 [MEMORY.md](../MEMORY.md)。
7. 重新运行本地链接、术语一致性和 Markdown lint。
8. 如果新增或修改外部链接，运行外部链接检查或记录未运行原因。

如果变化只影响内部组织方式，不涉及外部事实，可以跳过第 1 步的联网证据，但仍应更新 CHANGELOG 和 MEMORY。

## 常见复核场景

### 场景一：模型文档变化

处理流程：

1. 在资源附录找到对应官方文档入口。
2. 记录当前文档页、版本或更新时间。
3. 检查正文是否写死模型名称、上下文长度、价格、地区可用性或工具能力。
4. 修改第 5 章、模型概览和模型选型案例中受影响的表述。
5. 如果变化只影响产品细节，不改变选型方法，正文改成“以官方文档为准”，不要堆模型列表。

建议写法：

```text
截至 YYYY-MM-DD，官方文档显示该模型路线适合【场景】。具体模型名称、价格、上下文和地区可用性变化较快，正式选型前应重新核验官方页面。
```

### 场景二：协议或 agent 能力变化

处理流程：

1. 先确认协议文档、规范页或官方 SDK 文档是否变化。
2. 判断变化属于概念层、接口层还是生态层。
3. 概念层变化影响第 8、12 章；接口层变化影响工具/RAG/agent 示例；生态层变化通常先进入资源附录。
4. 检查 agent 安全清单是否需要新增权限、日志、回滚或人工确认项。

不要把某个 SDK 的实现细节写成协议本身的长期特征。

### 场景三：安全标准变化

处理流程：

1. 查标准组织、政府机构或官方安全指南，不依赖二手文章。
2. 判断新建议影响数据分级、权限、日志、评估、供应链还是人工审批。
3. 优先更新第 13 章、安全案例更新指南、事故复盘案例集和团队落地手册。
4. 如果风险较高，在发布影响记录中标注是否建议暂缓发布。

安全更新不只改概念解释，还要检查模板是否会引导读者做高风险操作。

### 场景四：开源模型或许可证变化

处理流程：

1. 同时查看官方发布页、模型卡、许可证和基础模型来源。
2. 判断变化是否影响商用、再分发、本地部署或微调。
3. 更新第 11 章、本地部署模型选型案例和资源附录。
4. 对不确定许可证，不给法律结论，只提示读者在商用前核验许可证和组织政策。

## 发布判断

复核完成后，用下面标准判断发布影响。

| 结论 | 条件 | 动作 |
| --- | --- | --- |
| 可以发布 | 变化已记录，正文没有明显过时事实 | 更新 CHANGELOG 和 MEMORY |
| 修改后发布 | 有影响正文的变化，但范围可控 | 先完成修改和检查 |
| 暂缓发布 | 模型、协议、安全或许可证变化会误导读者 | 标注阻塞问题，等待人工复核 |
| 发布但标注限制 | 教学试跑或团队反馈不足，但事实资料已核验 | 在发布说明写明“尚未真实试跑” |

1.0 发布前至少应满足：

- 资源附录完成一次标准复核，或明确标注尚未联网复核。
- 前沿资料季度复核记录表中有可追溯记录。
- 本地链接、占位标记、术语一致性和 Markdown lint 通过。
- 涉及安全、许可证或高风险行业的内容没有被写成专业意见替代品。

## 收尾检查

修改完成后，把结果写入复核记录表的“本地检查记录”和“发布影响记录”。

建议执行：

```powershell
./scripts/check-markdown-links.ps1 -Root . -CheckPlaceholders
./scripts/check-terminology.ps1 -Root .
npx --yes markdownlint-cli2 "**/*.md" "#_site" "#node_modules" "#vendor" "#dist"
```

如果本次新增或修改外部链接，再执行：

```powershell
./scripts/check-external-links.ps1 -Root .
```

如果没有运行外部链接检查，应在记录表写明原因，例如“本次只新增内部流程文档，未改外部链接”。

## 可复制的季度复核 prompt

```text
请阅读 README.md、MEMORY.md、CHANGELOG.md、docs/SUMMARY.md、docs/appendix-resources.md、docs/frontier-review-log.md 和 docs/frontier-review-playbook.md。

任务：执行一次【快速巡检 / 标准复核 / 深度复核】。

范围：【模型选型 / 工具与 RAG / skills 与 agent / 记忆系统 / 开源模型 / 安全治理 / 趋势报告】。

要求：
1. 只使用官方文档、论文、标准组织、政府机构、官方仓库或模型卡作为证据。
2. 先在 docs/frontier-review-log.md 记录证据和影响范围。
3. 只修改受影响文件。
4. 修改后同步 README、docs/index.md、docs/SUMMARY.md、CHANGELOG.md 和 MEMORY.md 中需要更新的入口或记录。
5. 运行本地链接检查、术语一致性检查和 Markdown lint。
6. 如果没有运行外部链接检查，写明原因。
```
