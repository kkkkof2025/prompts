# AI 学习与使用速查讲义

这份讲义适合打印、培训发放或放在团队知识库首页。它浓缩了本书最常用的方法。

如果你已经遇到 AI 输出不稳定、编造、任务越做越乱或 agent 边界不清的问题，可以配合 [常见误区与纠偏指南](common-pitfalls.md) 和 [Prompt 调试指南](prompt-debugging-guide.md) 使用。如果你还不确定任务该用 prompt、工作流、skill、RAG 还是 agent，先看 [AI 任务选择决策指南](task-decision-guide.md)。

## 1. 好 Prompt 五要素

```text
目标：你要 AI 做什么？
背景：AI 需要知道什么上下文？
约束：哪些必须做，哪些不能做？
标准：怎样算完成？
输出：用什么格式交付？
```

可复制模板：

```text
请完成【任务】。

背景：
【必要上下文】

约束：
- 【限制 1】
- 【限制 2】

验收标准：
- 【标准 1】
- 【标准 2】

输出格式：
【表格/清单/Markdown/JSON/邮件/大纲】

如果信息不足，请先问我最多 3 个关键问题。
```

## 2. 复杂任务六步法

```text
澄清目标 -> 拆解任务 -> 执行一步 -> 检查输出 -> 迭代修正 -> 汇总交付
```

适合：

- 写长文。
- 做竞品分析。
- 读论文。
- 生成代码。
- 设计课程。
- 建立知识库。

## 3. AI 输出验证方法

| 输出类型 | 验证方法 |
| --- | --- |
| 事实 | 查来源、日期、原文 |
| 计算 | 用表格、计算器或代码复算 |
| 代码 | 运行测试、类型检查、静态分析 |
| 写作 | 按目标读者、结构和语气评分 |
| 决策 | 列假设、反例、风险和替代方案 |

## 4. RAG/知识库最小流程

```text
用户问题 -> 检索资料 -> 筛选片段 -> 注入上下文 -> 生成回答 -> 标注引用 -> 核验
```

知识库原则：

- 原始资料和总结分开。
- 重要信息保留来源和日期。
- 过时资料要删除或标记。
- 私密资料限制访问。
- 回答要标注依据。

## 5. Skill 最小结构

```text
名称：
用途：
触发场景：
输入要求：
执行步骤：
输出格式：
边界：
验收标准：
示例：
```

当你发现自己反复说“还是按上次那个格式”，就该写 skill。

## 6. Agent 工作说明

```text
目标：

可使用工具：

允许读取：

允许写入：

禁止事项：

验收标准：

需要人工确认的动作：
```

高风险动作必须人工确认：

- 删除文件。
- 发送邮件。
- 支付或下单。
- 发布内容。
- 改变权限。
- 处理敏感数据。

## 7. 记忆保存规则

值得保存：

- 长期目标。
- 稳定偏好。
- 项目背景。
- 常用格式。
- 反复出现的流程。

不该保存：

- 密码、密钥、验证码。
- 身份证、银行卡。
- 客户隐私。
- 未公开商业资料。
- 一次性临时要求。

## 8. 团队 AI 使用底线

团队至少明确：

```text
哪些数据可以输入 AI？
哪些数据禁止输入 AI？
哪些任务必须人工复核？
哪些工具被允许使用？
输出是否需要引用来源？
AI 行动是否有日志？
出错后谁负责处理？
```

## 9. 最常用的 5 个追问

```text
请先判断信息是否足够，不足就问我最多 3 个问题。
```

```text
请从准确性、完整性、可执行性三个角度自查。
```

```text
请区分事实、推测和建议。
```

```text
请列出你不确定、需要核验的信息。
```

```text
请保留结构，只改第 2 部分，让它更适合初学者。
```

## 10. 一句话原则

AI 不是魔法答案机，而是一个需要目标、上下文、工具、边界和验收标准的协作者。
