# Agent 工作流安全检查清单

这份清单用于在使用 AI agent 执行读写文件、调用工具、运行命令或修改项目时降低风险。它适合初学者，也适合多人并行协作的开源项目。

核心原则：

- 先确认目标，再执行动作。
- 先读上下文，再修改文件。
- 只改任务要求范围内的内容。
- 对不可逆操作保持谨慎。
- 所有重要动作都应该可解释、可追踪、可回滚。

## 1. 任务边界检查

开始前确认：

- [ ] 我是否理解用户的最终目标？
- [ ] 用户是否指定了允许修改的目录或文件？
- [ ] 用户是否指定了禁止修改的目录或文件？
- [ ] 是否存在多个 agent 并行工作？
- [ ] 我的写入范围是否和其他人可能的写入范围分离？
- [ ] 是否需要先询问用户，而不是直接执行？

风险信号：

- 用户只说“优化一下”“整理一下”，没有说明范围。
- 任务涉及全局重构，但没有授权。
- 目录里已有大量未提交改动。
- 同名文件已经存在，且不是本次任务明确要求覆盖。

安全做法：

- 明确写入范围，例如“只修改 examples/ 下的文件”。
- 遇到同名文件时先读取内容，再决定追加、修改还是询问。
- 不修改与任务无关的 README、配置、锁文件或文档目录。

## 2. 权限检查

执行命令或工具前确认：

- [ ] 这个动作是否真的需要执行？
- [ ] 命令是否只作用于任务范围内？
- [ ] 是否会联网、安装依赖、删除文件或改写大量内容？
- [ ] 是否会访问敏感路径、密钥、凭据或个人数据？
- [ ] 是否需要用户明确授权？

高风险操作：

- 删除、移动或批量覆盖文件。
- 修改全局配置、系统环境变量或凭据。
- 安装依赖、升级依赖或运行未知脚本。
- 推送代码、发布包、部署服务。
- 执行从网络复制来的命令。

安全做法：

- 优先运行只读命令，例如查看目录、搜索文本、查看差异。
- 对写操作使用最小范围路径。
- 执行批量修改前先列出目标文件。
- 不把密钥、令牌、Cookie 或个人信息写入日志和回复。

## 3. 记忆与上下文检查

使用历史记忆或项目上下文前确认：

- [ ] 当前任务是否真的需要历史记忆？
- [ ] 记忆是否可能过期？
- [ ] 记忆是否和当前用户指令冲突？
- [ ] 是否应该以当前仓库内容为准？
- [ ] 是否需要记录本次新增的长期偏好或规则？

风险信号：

- 依赖“我记得这个项目是这样”的印象，而没有读取文件。
- 使用旧规则覆盖用户本轮明确指令。
- 把临时任务细节写成长期记忆。
- 把敏感信息、私有路径或个人数据记入长期记忆。

安全做法：

- 当前用户指令优先于历史记忆。
- 当前文件内容优先于模型印象。
- 只记录稳定、长期、非敏感的偏好。
- 不把一次性任务、临时路径、密钥或隐私内容写入记忆。

## 4. 工具使用检查

调用工具前确认：

- [ ] 工具是否适合当前任务？
- [ ] 是否有更简单的只读方式先获取信息？
- [ ] 工具输入是否明确、范围是否有限？
- [ ] 工具输出是否需要人工复核？
- [ ] 工具是否可能产生副作用？

常见工具风险：

- 搜索工具：找到相似文件后误改无关文件。
- Shell 命令：路径拼写错误导致作用范围扩大。
- 格式化工具：改动大量无关文件。
- 代码生成工具：覆盖人工修改。
- 浏览器或网络工具：引用过期、不可靠或非官方来源。

安全做法：

- 搜索优先使用精确关键词。
- 写入前确认目标路径。
- 只格式化本次修改过的文件。
- 对事实性问题优先使用官方或一手来源。
- 对工具结果保持怀疑，尤其是自动修复和批量替换。

## 5. 文件修改检查

修改文件前确认：

- [ ] 是否已经读取相关文件？
- [ ] 是否知道文件的现有风格和结构？
- [ ] 是否只修改任务要求的文件？
- [ ] 是否会覆盖他人的改动？
- [ ] 是否需要保留原有格式、标题、链接或元数据？

修改时注意：

- 不做无关重构。
- 不顺手整理无关段落。
- 不删除看似重复但不理解用途的内容。
- 不修改用户明确禁止的文件。
- 不回滚自己没有做的改动。

修改后检查：

- [ ] 文件是否保存到正确目录？
- [ ] Markdown 标题层级是否清晰？
- [ ] 链接、代码块和清单语法是否正确？
- [ ] 是否混入了临时笔记、调试输出或占位废话？
- [ ] 是否符合用户指定语言和读者水平？

## 6. 回滚与恢复检查

执行可能影响文件状态的动作前确认：

- [ ] 是否知道如何查看本次改动？
- [ ] 是否能区分自己的改动和他人的改动？
- [ ] 是否避免使用会清空他人工作的命令？
- [ ] 是否需要先备份或生成补丁？

禁止默认使用：

- `git reset --hard`
- `git checkout -- .`
- 批量删除未知文件
- 覆盖整个目录
- 清理未跟踪文件

安全做法：

- 用差异查看本次修改。
- 只回滚自己明确造成的问题。
- 如果他人改动和本任务冲突，先说明冲突并询问。
- 对生成文件或批量输出，先确认目标目录和命名规则。

## 7. 审计与记录检查

任务结束前确认：

- [ ] 是否能列出修改了哪些文件？
- [ ] 是否能说明每个文件的用途？
- [ ] 是否运行了必要检查？
- [ ] 如果没有运行检查，是否说明原因？
- [ ] 是否留下了可供审阅的清晰差异？

建议记录：

- 修改文件列表。
- 主要内容变化。
- 执行过的检查命令。
- 未解决的问题或需要人工确认的事项。
- 没有触碰的敏感范围。

最终回复应包含：

- 创建或修改的文件。
- 简短说明每个文件的内容。
- 验证方式或未验证原因。
- 如果存在风险，明确指出。

## 8. 并行协作检查

当多个 agent 同时工作时确认：

- [ ] 是否遵守 disjoint write set？
- [ ] 是否只在自己负责的目录或文件中写入？
- [ ] 是否避免格式化整个仓库？
- [ ] 是否避免修改共享索引文件，除非任务明确要求？
- [ ] 是否没有回滚、整理或覆盖他人的改动？

安全做法：

- 只创建或修改本任务指定文件。
- 对共享文件保持只读。
- 不因为本地状态“看起来乱”就清理。
- 最终回复清楚列出自己的写入范围。

## 9. 快速执行清单

适合每次 agent 开始工作前快速过一遍：

- [ ] 目标清楚
- [ ] 写入范围清楚
- [ ] 禁止范围清楚
- [ ] 已读取必要上下文
- [ ] 不依赖过期记忆
- [ ] 工具调用范围有限
- [ ] 不执行高风险命令
- [ ] 不修改他人文件
- [ ] 不回滚他人改动
- [ ] 修改后查看差异
- [ ] 最终回复列出文件

## 10. 初学者常见错误

| 错误 | 为什么危险 | 更安全的做法 |
| --- | --- | --- |
| 直接让 agent “整理整个项目” | 范围过大，容易改坏无关文件 | 指定目录、文件和交付物 |
| 不看现有文件就生成内容 | 容易风格不一致或覆盖已有内容 | 先读取目录和相关文件 |
| 把联网结果当事实 | 可能过期或来源不可靠 | 优先官方来源，并标注日期 |
| 允许批量格式化 | 产生大量无关差异 | 只格式化本次修改文件 |
| 使用强制回滚命令 | 可能删除他人工作 | 只回滚自己明确造成的改动 |
| 不写验收标准 | 无法判断结果是否完成 | 事先列出可检查标准 |
| 忘记最终说明 | 审阅者不知道改了什么 | 回复中列出文件和验证情况 |
