# Prompt 模式实践模板

这份模板用于帮助初学者把“随口问 AI”改成“可复用、可检查、可迭代的提问方式”。每个模式都包含适用场景、可直接复制的模板、常见反例和改进版。

使用建议：

- 先从 1-3 个基础模式开始，不要一次堆太多要求。
- 每次只改一个变量，例如角色、输出格式或约束，观察结果差异。
- 对重要任务保留“反例”和“改进版”，方便下次复用。
- 不要要求 AI 编造来源、事实或经历；不确定时让它标注不确定性。

## 1. 角色 + 任务 + 受众

适用场景：

当你希望 AI 的回答风格、深度和举例方式更贴近某类读者时使用。例如：给小白解释、给老板写摘要、给工程师写方案。

模板：

```text
请扮演【角色】。
你的任务是：【具体任务】。
目标读者是：【读者背景】。
请用【语气/深度/篇幅】回答。
如果涉及专业术语，请先用通俗语言解释。
```

反例：

```text
给我讲一下机器学习。
```

问题：

- 没有说明读者是谁。
- 没有说明讲到什么深度。
- 没有明确输出目标。

改进版：

```text
请扮演一名耐心的 AI 入门课老师。
你的任务是向完全没有编程经验的大学生解释“机器学习”。
请用 800 字以内回答，先给一个生活类比，再解释核心概念，最后列出 3 个常见应用。
涉及专业术语时，请用一句通俗话解释。
```

## 2. 背景 + 目标 + 约束

适用场景：

当任务和你的实际情况有关时使用。例如：制定学习计划、写项目方案、修改简历、规划课程。

模板：

```text
背景：
- 我目前的情况是：【现状】
- 我已经具备：【已有资源/能力】
- 我受到的限制是：【时间/预算/工具/政策】

目标：
- 我希望达到：【可观察结果】
- 截止时间是：【时间】

请输出：
1. 可执行方案
2. 每一步的原因
3. 可能风险和应对方式
```

反例：

```text
帮我学会 AI。
```

问题：

- “学会 AI”太宽泛。
- 没有说明基础、时间和目标。
- AI 无法判断优先级。

改进版：

```text
背景：
- 我是中文系学生，几乎没有编程经验。
- 每周可以投入 5 小时。
- 目前只会使用 ChatGPT 做问答。

目标：
- 8 周后能够独立完成一个“用 AI 辅助资料整理和文章初稿生成”的小项目。

请输出：
1. 8 周学习计划
2. 每周要完成的实践任务
3. 每周的验收标准
4. 哪些内容可以先跳过
```

## 3. 示例驱动

适用场景：

当你需要 AI 模仿某种格式、风格、分类标准或判断规则时使用。示例越接近真实任务，输出越稳定。

模板：

```text
请根据下面的示例学习输出风格和判断标准。

示例 1：
输入：【样例输入】
输出：【理想输出】

示例 2：
输入：【样例输入】
输出：【理想输出】

现在处理新输入：
【新输入】

请保持与示例一致的结构、语气和粒度。
```

反例：

```text
帮我把这些笔记整理得好一点。
```

问题：

- “好一点”没有标准。
- AI 不知道你想要表格、提纲还是总结。
- 容易改变原意或加入无关内容。

改进版：

```text
请根据示例把课堂笔记整理成“概念-解释-例子-待确认问题”的格式。

示例：
输入：
神经网络，好像是很多层，能识别图片。训练时会调参数。

输出：
概念：神经网络
解释：一种由多层计算单元组成的模型，可以从数据中学习特征。
例子：用大量猫狗图片训练后，模型可以判断新图片中是猫还是狗。
待确认问题：参数是如何被调整的？

现在处理：
输入：
提示词工程，就是怎么问 AI。上下文很重要，输出格式也重要。
```

## 4. 分步骤拆解

适用场景：

当任务比较复杂、容易遗漏步骤时使用。例如：写论文、做调研、开发功能、准备演讲。重点是让 AI 输出可执行步骤，而不是只给泛泛建议。

模板：

```text
请把任务拆成可执行步骤。

任务：【任务描述】
我的起点：【当前进度】
最终结果：【交付物】

请按以下结构输出：
1. 总体路线
2. 关键步骤
3. 每一步的输入、动作、输出
4. 哪些步骤需要人工判断
5. 最容易出错的地方
```

反例：

```text
帮我做一个 AI 课程。
```

问题：

- 任务太大。
- 没有交付物定义。
- AI 可能直接给一个空泛目录。

改进版：

```text
请把“制作一节 60 分钟的 AI 入门课”拆成可执行步骤。

我的起点：
- 已经确定主题是“如何写好 Prompt”
- 听众是高中老师
- 还没有课件

最终结果：
- 一份课程大纲
- 一组课堂练习
- 一个 10 分钟实操环节

请输出：
1. 准备流程
2. 每一步需要输入什么材料
3. 每一步产出什么文件或内容
4. 哪些地方必须由我人工确认
```

## 5. 输出格式约束

适用场景：

当你要把 AI 输出继续复制到表格、文档、代码、工单或模板中时使用。格式越明确，后续处理成本越低。

模板：

```text
请严格按照以下格式输出，不要添加额外解释。

输出格式：
【表格/JSON/清单/邮件/大纲】

字段要求：
- 【字段 1】：【说明】
- 【字段 2】：【说明】
- 【字段 3】：【说明】

内容来源：
【待处理文本】
```

反例：

```text
总结一下这篇文章，越清楚越好。
```

问题：

- “清楚”不能直接用于后续处理。
- 输出可能时长时短。
- 不利于比较多个结果。

改进版：

```text
请严格用 Markdown 表格总结下面的文章，不要添加表格外说明。

表格字段：
- 核心观点：一句话概括
- 论据：列出最多 3 条
- 可行动建议：给初学者的具体做法
- 不确定信息：文章中没有充分说明的地方

文章：
【粘贴文章】
```

## 6. 先澄清再回答

适用场景：

当你的需求还不完整，或者错误代价较高时使用。例如：学习路线、职业建议、项目方案、法律或医疗类信息整理。让 AI 先问问题，可以减少误判。

模板：

```text
我想完成：【目标】。
目前我只知道：【已知信息】。

在给出方案前，请先提出最多 5 个关键澄清问题。
如果某个问题不会明显影响方案，请不要问。
等我回答后，你再给出建议。
```

反例：

```text
我该不该转行做 AI？
```

问题：

- 缺少背景信息。
- AI 容易给励志式泛泛建议。
- 无法判断机会成本。

改进版：

```text
我想判断自己是否适合转向 AI 产品经理方向。
目前我只知道：
- 我有 3 年内容运营经验
- 会用 AI 工具，但不会编程
- 希望 6 个月内找到更高成长性的岗位

在给出建议前，请先提出最多 5 个关键澄清问题。
问题要能影响你的判断，例如技能差距、行业选择、时间投入和风险承受能力。
```

## 7. 评审 + 修改循环

适用场景：

当你已经有初稿，希望 AI 帮你提高质量时使用。例如：文章、方案、简历、提示词、学习计划。先评审再改写，比直接“润色”更可控。

模板：

```text
请先评审，再修改。

材料：
【粘贴内容】

目标：
【说明这份材料要达到什么效果】

请按顺序输出：
1. 主要问题，最多 5 条
2. 每个问题为什么影响目标
3. 修改原则
4. 修改后的版本
5. 修改前后差异说明
```

反例：

```text
帮我润色一下。
```

问题：

- AI 可能只改字句，不解决结构问题。
- 可能改变原意。
- 没有说明“润色”的目标。

改进版：

```text
请先评审，再修改下面这段 AI 课程介绍。

目标：
- 面向没有技术背景的成人学习者
- 让读者明白课程能解决什么问题
- 语气专业但不夸张

材料：
本课程将全面深入讲解 AI 的底层原理和产业趋势，帮助每个人掌握未来核心竞争力。

请按顺序输出：
1. 主要问题，最多 5 条
2. 每个问题为什么影响目标
3. 修改原则
4. 修改后的版本
5. 修改前后差异说明
```

## 8. 对比决策矩阵

适用场景：

当你需要在多个方案之间做选择时使用。例如：选学习路径、工具、模型、课程、项目方向。它能把“感觉哪个好”变成“按标准比较”。

模板：

```text
请帮我比较以下选项：
选项：
- A：【说明】
- B：【说明】
- C：【说明】

我的决策标准：
- 【标准 1】，权重：【高/中/低】
- 【标准 2】，权重：【高/中/低】
- 【标准 3】，权重：【高/中/低】

请输出：
1. 对比表
2. 每个选项的优点和风险
3. 推荐选择
4. 推荐成立的前提
5. 如果前提变化，应该如何调整
```

反例：

```text
我应该学 Python、机器学习还是提示词工程？
```

问题：

- 三个选项层级不同。
- 没有决策标准。
- 推荐结果容易脱离个人目标。

改进版：

```text
请帮我比较以下 3 条 AI 学习路径：
- A：先学 Python 基础
- B：先学提示词工程和 AI 工具使用
- C：先学机器学习理论

我的情况：
- 文科背景
- 每周 5 小时
- 目标是在 2 个月内提升工作效率，而不是马上找算法岗位

决策标准：
- 短期可用性，权重：高
- 学习难度，权重：高
- 长期发展价值，权重：中
- 对编程基础要求，权重：中

请输出对比表、推荐选择、推荐成立的前提，以及什么时候应该切换路径。
```

## 9. 来源约束 + 不确定性标注

适用场景：

当任务涉及事实、数据、政策、论文、新闻、产品参数或任何可能过期的信息时使用。这个模式用于降低“看起来很真但实际编造”的风险。

模板：

```text
请基于我提供的资料回答，不要使用未给出的事实。

资料：
【粘贴资料或链接摘要】

问题：
【你的问题】

请输出：
1. 直接答案
2. 支持答案的资料依据
3. 资料中没有说明或无法确认的部分
4. 如果需要进一步验证，应该查什么来源
```

反例：

```text
告诉我现在最好的 AI 模型是什么。
```

问题：

- “最好”没有定义。
- 模型信息变化很快。
- 容易出现过期或编造信息。

改进版：

```text
请基于我提供的资料回答，不要使用未给出的事实。

资料：
【粘贴来自官方文档、论文或评测报告的摘要】

问题：
如果目标是“中文长文总结”，这些模型中哪个更适合初学者使用？

请输出：
1. 推荐模型
2. 推荐理由
3. 资料依据
4. 资料中没有说明的限制
5. 需要进一步验证的信息，例如价格、上下文长度、隐私要求
```

## 10. 验收标准 + 自检清单

适用场景：

当你希望 AI 的输出达到可交付质量时使用。例如：写教程、生成代码、设计练习题、整理报告。验收标准可以让 AI 自己发现明显缺口，也方便你人工检查。

模板：

```text
请完成以下任务：
【任务描述】

验收标准：
- 【标准 1】
- 【标准 2】
- 【标准 3】

输出前请自检：
- 是否满足所有验收标准
- 是否有未经确认的事实
- 是否有明显遗漏
- 是否有需要我人工决定的地方

最终输出：
1. 成品内容
2. 自检结果
3. 需要我确认的问题
```

反例：

```text
帮我写一份 AI 学习计划。
```

问题：

- 没有质量标准。
- 输出是否可执行难以判断。
- 可能缺少检查点。

改进版：

```text
请为 AI 初学者写一份 4 周学习计划。

验收标准：
- 每周学习时间不超过 6 小时
- 每周必须有一个可提交的小作品
- 不要求学习高等数学
- 每个任务都要能用免费或低成本工具完成

输出前请自检：
- 是否满足所有验收标准
- 是否存在不适合初学者的内容
- 是否有需要我人工决定的地方

最终输出：
1. 4 周计划
2. 每周小作品
3. 自检结果
4. 需要我确认的问题
```
